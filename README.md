# EC_CPP

面向研控 **YKD2205PE** EtherCAT 滑台驱动器 (CiA 402) 的 Qt 上位机与原生 C 运动接口。

**2026-09-21 清理**: 仓库原先有一批命令行验收/诊断程序 (`aliasinfo` / `slide_verify` /
`slide_motion` 含 `sm_state` / `sm_pdo` / `test2` / `motor_test`)。`scan` 一个都不依赖,
所以它们连同 `baseline_ykd2205pe.ini`、`docs/slide_motion_verify.md` 一起删掉了。
**现在只有两个程序: `scan` (产品) 与 `hmi` (它的前身界面)** —— 外加一个不需要设备就能跑的
`scan_selftest`。它们留下的**结论**(驱动器实测值、PDO 映射、安全口径) 全部保留在下面的
文档与代码注释里。

顶层 `CMakeLists.txt` 通过 `add_subdirectory(SOEM)` 引用 SOEM 库, 再 `add_subdirectory`
两个上位机 —— SOEM 只以子工程身份产出 `soem` 静态库, 不构建其自带 samples, 源码不被改动。

`hmi/` 由一个开关控制: `-DEC_BUILD_HMI=ON` 才会被 `add_subdirectory`。**默认 OFF** ——
现在 OFF 等于**只编 SOEM 静态库**, 那是给"只验 SOEM 能不能编过"用的 (`enable_language(CXX)`
在 `hmi/CMakeLists.txt` 里, 所以这一档连 C++ 编译器都不需要有)。
`scan/` 由 `EC_BUILD_SCAN` 控制, **默认值就是 `${EC_BUILD_HMI}`** —— 于是现有那条
`cmake --preset hmi-qt-ucrt64` 一次把两个都编出来, 只想编 hmi 的人 `-DEC_BUILD_SCAN=OFF`。
两个界面侧都**不 include SOEM**、不调 `ecx_*`: 所有总线操作都在工作线程里, 见
[hmi/ecatworker.h](hmi/ecatworker.h) 顶部。

## 构建

两个程序都要 Qt6 + C++ 编译器, 走的是仓库自带的 preset (见下一节)。
只编 SOEM 那一步 (不碰 Qt) 是:

```bash
cmake -S . -B build-mingw -G Ninja -DCMAKE_BUILD_TYPE=Release \
      -DCMAKE_C_COMPILER=C:/msys64/ucrt64/bin/gcc.exe
cmake --build build-mingw --target soem
```

产物 (统一输出到仓库根的 `bin/`):
- `bin/hmi.exe` (仅当 `EC_BUILD_HMI=ON`)
- `bin/scan.exe` / `bin/scan_selftest.exe` (仅当 `EC_BUILD_SCAN=ON`, 默认跟随 `EC_BUILD_HMI`)

### 上位机 `hmi` (Qt)

完整设计、部署细节与**哪些验收做了 / 哪些还没做**见
[docs/hmi_click_position.md](docs/hmi_click_position.md)。

先装依赖(**新机器做一次**)。Qt 必须取自 **MSYS2 的 UCRT64 仓库** —— 编译器和 `motor_api`
用的是**同一个** `C:/msys64/ucrt64` 工具链 (底下那堆 `-D_UCRT -lucrt` 就是为它准备的):

```bash
MSYSTEM=UCRT64 pacman -S --needed mingw-w64-ucrt-x86_64-qt6-base
```

自检(全部 `OK` 才继续):

```bash
for f in C:/msys64/ucrt64/bin/gcc.exe C:/msys64/ucrt64/lib/cmake/Qt6/Qt6Config.cmake \
         C:/msys64/ucrt64/share/qt6/bin/moc.exe C:/Qt/Tools/Ninja/ninja.exe; do
  [ -e "$f" ] && echo "OK   $f" || echo "MISS $f"
done
cmake --version >/dev/null 2>&1 && echo "OK   cmake" \
  || echo "MISS cmake (pacman -S mingw-w64-ucrt-x86_64-cmake)"
```

注意 `moc.exe` 在 `share/qt6/bin/` 而**不在** `bin/` 下 —— MSYS2 把 Qt 工具装在那儿。

再走仓库自带的 [CMakePresets.json](CMakePresets.json) 里的 `hmi-qt-ucrt64`
(**生成器是 Ninja, 与上面那条 MinGW Makefiles 的构建目录不能混用**):

```bash
cmake --preset hmi-qt-ucrt64
cmake --build out/build/hmi-qt-ucrt64 --target hmi
```

**configure 失败时第二条报的 `ninja: error: loading 'build.ninja'` 是连带的**
(`out/build/hmi-qt-ucrt64/` 里从没生成过 `build.ninja`)。

> 最常见的失败是 **UCRT64 里没装 Qt6**, 现象是第一条报
> `Could not find a package configuration file provided by "Qt6"`。自检表里第 2、3 项
> 会同时 `MISS`。完整前置清单与每一项的装法见
> [docs/hmi_click_position.md](docs/hmi_click_position.md) 的 6.0。

> **不要用 Qt 官方安装器那个 MinGW 版 Qt。** 它自带的是 **msvcrt** 版 MinGW (没有
> `_UCRT`), 而 SOEM 的 `SOEM/cmake/Windows.cmake` 给 GNU 编译器加了 `-D_UCRT -lucrt`,
> 且 `SOEM/osal/win32/osal.c` 确实要用它 (`timespec_get`/`TIME_UTC` 在该工具链的
> `time.h` 里只有 `_UCRT` 打开时才有声明, 没有 msvcrt 退路)。于是进程里会同时存在
> 两套 CRT 的 stdio 表: 一个 CRT 建出来的 `FILE*` 被另一个 CRT 去 `_lock_file` ——
> **工作线程第一次 `printf` 就 SIGSEGV 在 `msvcrt!_lock`**。SOEM 是下载库不能改,
> 所以只能换 Qt。详见 [CMakePresets.json](CMakePresets.json) 里那条 preset 的说明。

生成器要在**带 `C:/msys64/ucrt64/bin` 的 PATH** 下跑 (moc 等 Qt 工具自身要加载那儿的
DLL, 否则 configure 就报 `AUTOUIC ... Exit code 0xc0000139`; MSYS2 的 UCRT64 shell
本来就是这个 PATH)。项目没有 `.ui` 文件, 已显式关掉 AUTOUIC。

跑之前用 MSYS2 的 `windeployqt6` 把 Qt 运行时搬到 `bin/`:

```bash
C:/msys64/ucrt64/bin/windeployqt6.exe --release --compiler-runtime \
    --no-translations bin/hmi.exe
```

> MSYS2 的 `windeployqt` **只搬 Qt 自己的 DLL**, 会把 MSYS2 运行时 (`libstdc++-6.dll`/
> `libgcc_s_seh-1.dll`/`libicu*.dll`/`zlib1.dll` …) 当成"PATH 里已有"而跳过 ——
> 双击 `bin\hmi.exe` 会报 `0xc0000139` (缺入口点)。这些得从 `C:/msys64/ucrt64/bin`
> 补拷进 `bin/`。`--no-translations` 是必须的: 否则会多出几十个
> `bin/translations/*.qm`, 而 `.gitignore` 只忽略 `*.dll`/`*.exe`。

### 上位机 `scan` (扫描采集)

完整设计、安全须知与**哪些验收做了 / 哪些还没做**见
[docs/scan_sweep.md](docs/scan_sweep.md)。

**前置条件、工具链与上面那条 `hmi` 完全相同** —— 同一个 `hmi-qt-ucrt64` preset、
同一套 UCRT64 Qt、同一条 `windeployqt6`。**不需要第二条 configure 命令**, 因为
`EC_BUILD_SCAN` 默认就等于 `EC_BUILD_HMI`:

```bash
cmake --preset hmi-qt-ucrt64
cmake --build out/build/hmi-qt-ucrt64            # 两个界面 + 自检一起编
cmake --build out/build/hmi-qt-ucrt64 --target scan
```

**自检不需要设备, 也不需要网卡** (它只链 `Qt6::Core`, 用 `FakeBus` + 模拟功率计把
整轮扫描跑完):

```bash
PATH="/c/msys64/ucrt64/bin:$PATH" ./bin/scan_selftest.exe
# ... 2741 passed, 0 failed, 0 skipped
```

> **那个数会在 2735 与 2741 之间摆** —— 它取决于**此刻插没插 Ophir 表头**。表头在的时候多跑
> 一组 6 条 (`ophir: live reading through OphirMeter`, 那一组**必须真表头**才能跑: 没有设备时
> 第二趟 `open()` 直接失败, 走不到那条路上), 表头不在就少 6 条 —— 而那 6 条**不算 skipped**,
> 只是压根不跑。跑完看一眼输出里有没有那行 `a head is attached`。
> **不插表头也照样 0 failed**, 少的只是那 6 条。

它只链 `Qt6Core`, 所以上面那条 `windeployqt6` (照 `bin/hmi.exe` 跑) 搬来的 DLL 就够它用了。

> **`scan` 运行时在 exe 旁边放两个文件, 两个都不入库** (`.gitignore` 里各占一条):
> `bin/scan.ini` (记的参数与上次连的那张网卡, 见下) 和 **`bin/scan.qss` (界面样式表)**。
> 样式表是 2026-09-23 从 `scan/main.cpp` 里搬出来的 (见
> [docs/scan_sweep.md](docs/scan_sweep.md) §31.7): 程序里那份
> (`scan/scanstyle.cpp` 的 `kDefaultSheet`) 是**缺省, 不是备份** —— exe 旁边没有
> `scan.qss` 时启动会照它写出去一份, 文件**在的时候从不覆盖**。改那个文件, 界面上按
> **F5** 重新读一遍就算数, **不用重编译** (改坏了想回出厂样子就把它删掉)。
> 它能改的是"长什么样" (颜色 / 边框 / 内边距 / 按钮大小 / 灰掉时的样子);
> **"谁摆在哪儿"改不了** —— 位置、行顺序、拉伸比例都在 `scan/scanwindow.cpp` 里。
> 两个最容易改坏的地方 (标题那一行按钮的 `padding`、`QGroupBox` 的 `margin-top`)
> 连同各自的症状写在文件开头那一段注释里。

> **`bin/scan.exe` 跟 `bin/hmi.exe` 是并存的两个程序, 不是两种模式。**
> `hmi` 是手动调试台 (点哪里走哪里, 自己不会动); `scan` 管自动采集 (会自己走完一个
> 区域, 一两个小时)。两者**编的是同一份 `hmi/ecatworker.cpp`** —— 2ms 的 CSP 插补循环、
> 坐标与零点、收尾那套安全代码只有一份实现。

默认参数下扫描的区域是 **27×27 mm** (1 mm = 50000 脉冲, 也就 1 圈) ⇒
**55×55 = 3025 点**, 线性估计约 **110 分钟**。
> **2026-09-29 起这个数比原来多约 10 分钟** (之前写的是「约 100 分钟」): 一个点的采样从
> "背靠背连要 N 次"改成"等连续读数按**间隔**喂够 N 笔" (见下文 §功率计 与
> [docs/scan_sweep.md](docs/scan_sweep.md) §41.3), 于是「采样」那一项从
> `50 × 采样数` 变成 `(间隔 + 50) × 采样数`。缺省 (间隔 200 ms、每点 1 笔) 是每点
> **1975 → 2175 ms**; 每点取 4 笔时那笔账是 `200 → 1000 ms`, 差得更明显。
> 想要快就把那个「间隔」调小 —— 它能到 20 ms。

> **长度单位就是 mm。** 区域 X/Y、分辨率、画布的标尺与读数全都按 mm 写
> (代码内部与 **CSV 表头**里仍旧叫 `unit`: `area_x_unit` / `pulses_per_unit` 是**已经落在
> 文件里的格式**, 改了名以前的 CSV 就接不上了, 所以不动 —— 见 §24)。

三件用起来会碰到的事:

- **参数改了当场生效。** 参数框没有「编辑」这一层 (2026-09-23 撤掉, 见
  [docs/scan_sweep.md](docs/scan_sweep.md) §31): 想改哪个直接改, 改完就是生效值。
  每块参数框的**标题那一行右端**有「保存」「取消」两个按钮。
  改了还没定的框, 标题上会挂一个 `● 未保存`, 那一框的「取消」跟着亮起来。
  **落进 `bin/scan.ini` 的时机有三个** —— 按那一框的「保存」、点「连接」、或者关窗。
  后两个是**整份**都记 (屏幕上此刻的值就是往后的值)。改完三样都没做就断电,
  那一次改动不落盘。按「取消」则把**那一框**退回上次保存的那一份 (并重新下发给控制器)。
  一个框的「保存」只写这一框管的字段, **别块框还没保存的改动不会被顺手固化**。
  **几何那几项 (区域 X/Y、分辨率、1 mm = N 脉冲、方向、方式、CSV 路径、恢复默认)
  在扫描/回零进行中仍然锁住** —— 改到一半, 落进 CSV 的 (ix,iy) 就和滑台实际位置对不上了;
  其余参数运行中也能改。**回零速度与「高级选项」那三项都进 ini**
  (见 [docs/scan_sweep.md](docs/scan_sweep.md))。**色标上下限、扫描那份 CSV 的路径、
  取样源不记 (界面只剩真机一个)**(功率计那一框自己的**间隔**、**曲线时长**与**那份连续读数的
  CSV 路径**是记的 —— 它们不是"上趟数据的范围", 而是"这台机器怎么采", 见 §23;
  **「曲线时长」是 2026-09-29 加的**, 记的是"这块屏一次看多长的一段", 见 §41.2)
  (色标那个「自动跟随数据」是个**模式**, 它记 —— 记不住就得每次开程序重新勾一遍;
  上下限是**数值**, 把上趟的范围套到新数据上就会把人骗了, 所以不记)。**色标那一框的「单位」
  是个手选的四项 (随取样源 / W / mW / μW), 缺省 mW, 也记** —— 与「自动跟随」同型, 记的是
  "这台机器怎么看数" (见 [docs/scan_sweep.md](docs/scan_sweep.md) §40)。**色标上下限
  非负且最小 < 最大**, 改一个顶到另一个头上时**另一个会自己让开、跨度不变**
  (最小 0/最大 1 时把最小改成 5, 最大跟着抬到 6)。
  关窗时 (以及每次「连接」) 也会顺手把当前值记一遍, **包括上次连的那张网卡**
  (十条 `\Device\NPF_{GUID}` 里自动选回原来那条)。想清零就删掉那个文件。
- **滚轮的规矩: 按住 Ctrl 才改值。** 参数框上直接滚**不改值** —— 那一下会交给参数栏去滚
  页面 (参数栏本来就要滚, 而扫描区域算错一格是要撞限位的)。想用滚轮调某个值就**按住 Ctrl**
  再滚; 松开 Ctrl 就是普通滚动。
- **点数上限 200000。** 区域×分辨率算出来超过它, **网格就不建了** (画布是空的、
  「开始扫描」按不动, 参数栏会写清实际点数)。
- **参数栏那块「功率计」是外露的, 开着就能改, 不插滑台、不连总线也能用。**
  功率计走的是 Ophir 的 COM 接口, **一个 EtherCAT 帧都不发**。面板里只有: **只在还没打开 /
  打开失败时才出现**的状态行(正在打开… / 未打开 · 为什么 —— 打开着的时候整行不显示, 那些字
  屏幕上别处都有)、**「设备」下拉**(同一台面上插着两台表头时选哪一台)、打开失败或采集卡死时
  露出的**「重试」**、真机的**波长/量程/模式**、**「间隔」+「曲线时长」+「清空」**这一行
  (**「曲线时长」**是 2026-09-29 晚从图下面挪上来的, 见 §46; 下面单说)、实时读数(大字)、
  统计、手画的时间-功率曲线;
  取样源选择、「读一次」、**每次平均 N 个读数**
  与模拟源那几个旋钮 (2026-09-28 一起删掉, 见 [docs/scan_sweep.md](docs/scan_sweep.md) §36),
  以及「未写入文件」那行与它下面那段说明 (同日删掉, 见 §37)。
  **「添加波长」那一行 (330-1100 nm 里挑一个写进表头) 当晚也藏了起来** (§37.12) ——
  那是**唯一一处会写设备**的功能, 藏起来之后这个程序在界面上不再写 Ophir 表头任何一个字节
  (代码没删, 要放回来是删两行 `setVisible(false)`)。
  **2026-09-29 又藏了一族 (§41.1, 用户原话"隐藏功率计独立的写入csv功能")**:
  「开始记录 / 停止记录」那**一个**按钮 (开与关共用, 没在写文件时写「开始记录」、写着了写
  「停止记录」)、CSV 路径框、「…」、「导出当前缓冲」—— 那一整行现在整块不见, 屏幕上**不留空行**。
  这一框从此只做"看数"。**代码一个字节没删** (槽、`MeterLog` 那半边协议、CSV 格式、自检里那
  一整族断言全在), 要放回来同样是删两句 `setVisible(false)`; 藏起来的那 4 件**照旧每拍算可用性**,
  恢复显示那一刻不必再想怎么灰。
  **采集是常开的**: 功率计一打开就一直在采, 不需要按任何键 —— 曲线自己长, 大字读数自己跳。
  设备那一行下面只剩**诊断**那一行 (ROM 版本 / 探头类型 / 驱动报的两个版本号): 型号与序列号
  已经在下拉里每一项上写着, 不再重复一遍 (2026-09-28, 见 §37.10)。
  **那块曲线一次看多长的一段是可以设的 (2026-09-29, §41.2)**: 「间隔」右边那一件
  **「曲线时长」** (2026-09-29 晚从图下面挪上来的, 见 §46), 单位分钟, **1 … 120, 缺省 5**,
  记进 ini。到点就丢最旧的, 而且**内存里真丢** —— 统计那一行 (`缓冲 N 点 …`) 跟着变成
  "窗内统计", 不是只把旧的画出画面。调小**当帧**
  就生效, 调回来那些点**回不来** (内存里已经没了), 曲线从此刻重新长。它裁的比容量 (20000 点)
  先到是常态 —— 缺省 5 分钟、缺省间隔 200 ms 那一档就是"窗先到" (5 分钟只装得下 1500 笔);
  窗开到 120 分钟那头上就轮到容量先到 (缺省间隔下那要 36000 笔)。
  **扫描与这一框现在是同一条流 (2026-09-29, §41.3)**: 扫描**不再自己**向功率计要数 —— 一个
  点的值 = **该点读取期间到齐的那些连续读数的平均**。于是扫描跑着的时候这一框照旧满速采
  (曲线一直在长, 移动时也在长), 曲线画的就是扫描正在用的那条流; 反过来, 连续读数跑着时扫描
  也**起得来**, 两个之间没有"谁让位"这回事了。"一个功率计同一时刻只允许一个未决请求"那条约束
  **没变** (撞上会静默分错数), 只是现在**只剩一个发起方**: 连续读数。代价是**扫描变慢** ——
  见开头那个「约 110 分钟」的注。
  **单位自适应 (2026-09-28, 见 §37)**: 大字读数 / 统计行 / 曲线纵轴按量级在 **W / mW / μW**
  之间自动换前缀 (μW 量级不再写 `0.00035 W`), 但**只对设备确实报 `W` 的换** —— `J` 是能量、
  `dBm` 是对数、空是「单位不明」, 三种一律原样 (除 1000 会把 `0 dBm` 变成 −30)。
  **CSV 一个字节不动**: 那一列与 `# meter_unit=` 照旧是设备报的原值与原单位, 于是
  **屏幕上的单位可能与文件里的不同**, 这是定下来的口径。统计那一行剩下的两个数 (最小 / 最大)
  **共用一个**前缀 (不出现一行两个单位), 曲线纵轴取的是同一个, 免得单位字与刻度数字对不上。
  **色标那一框的数走的是另一套 (2026-09-29, 见 [docs/scan_sweep.md](docs/scan_sweep.md) §40)**:
  同一批 `W` / `mW` / `μW` 的字, 但**不是自动挑的, 是操作员在「单位」那一项里定死的** (缺省 mW)
  —— 色标讲的是"这一张图按哪个量级看", 而大字读数是"这一个数有多大", 两件事。换那个单位
  **只改屏幕上的数字, 颜色一个字节都不动**; 缺省那对上下限也跟着单位走 (缺省 = `0 … 1` 个当前
  单位, 即 `0 … 1 mW`) —— 于是**开程序时的颜色与这一版之前不一样**: 毫瓦级的台子不再是一片深蓝,
  而读数本来就在 W 量级的场合会全红 (一次「按数据定标」即可)。
  **读数那三行 (2026-09-28, 见 §37.11)**: 统计是**一行** —— `缓冲 N 点   最小 …   最大 … (单位)`
  (平均与标准差不再显示, 类里照算); 状态那一行**只在有事可说时才有字** (记录中的「已写入 N 行」、
  卡住时的「请求无响应, 采集等待中。」、改设备配置期间的「改设备配置中, 采集暂停。」),
  三件都没有时**整行不在**。
  **换设备** = 停采集 + 清空缓冲 + 按新的序列号重开 (Ophir 表头是独占的, 旧的那只必须先还
  回去); 那一下是无声的, 而**已写进 CSV 的内容一个字节不动** (文件是追加的)。上一次用的是
  哪一台记进 ini, 插着两台时不必每次重选。
  **「添加波长」(藏起来之前) 曾是唯一一处写设备** —— 写完**当场把表读回来核对**: 读回来的表里
  出现了才算成功、才可选、才进 CSV, 没出现就报「设备不接受这个波长」(成因见
  [docs/scan_messages.md](docs/scan_messages.md) §13.6; 那一行藏起来之后这句在界面上出不来了)。
  加进去的值留在表头自己的配置里 (StarLab 那边也看得见), 本程序没有「删掉它」的功能。
  真机打开失败时状态行写原因, 并露出「重试」(采集卡死时也露)。**2026-09-29 修掉一处**:
  「重试」从前只把设备打开、不把上一次会话的"该收摊了"标志清掉, 于是**插上表头再按「重试」**
  能连上却永远读不到数, 只能重启程序; 「切换设备」是同一条路。成因与那根自检钉子见
  [docs/scan_sweep.md](docs/scan_sweep.md) §37.13。
  **默认构建下没真机就一趟扫描也起不来** (`ScanController::preflight` 会拒) —— 这是确认过的
  取舍; 留了一个编译开关 `SCAN_ALLOW_SIM_METER` (默认 OFF, `-DSCAN_ALLOW_SIM_METER=ON` 时
  构造期用随机源顶替, **界面形状不变**) 给没有硬件的机器跑通整条扫描流水线。
  **读数单位由取样源自己给: 真机由探头与测量模式判(那个随机源是 W); Ophir 的 COM 不给单位, 判不
  出来就一律写「单位不明」, 一个地方都不许替它编)。两份 CSV 的 `#` 行里也记着这一份是哪个
  探头/波长/量程/模式/什么单位采的, 列名一个字节都没动。**
  详见 [docs/scan_sweep.md](docs/scan_sweep.md) §23 与 §36。

## 运行注意

- **「退出码 10」的语义现在只剩模态告警这一种形态。** 原先 CLI 用退出码 10 表示
  "收尾写完 `6040h = 0` 但回读 `6041h` 仍报 Operation enabled" —— 即**电机可能仍带电**,
  它覆盖其它所有退出码。两个上位机的收尾是同一件事, 只是报法变成了**弹一个没有「取消」
  可点的模态框**。**见到请立即断掉驱动器动力电源, 不要只依赖软件。**
- 运动接口 (`motor_api`) 与 CLI 说过的几条**实测事实**仍然成立, 因为它们约束的是驱动器、
  不是那个程序:
  - 它**不写死** `1600h`/`1A00h`, 而是先读 `1C12h`/`1C13h` 问"哪个 PDO 生效" ——
    本机 `1C12h` 指的是 **`1601h`**, `1600h` 是一张**没生效**的表。
  - 同理 `6060h`(运行模式) 就在 `1601h` 里, 所以它由过程数据驱动而不是 SDO ——
    对它做 SDO 写会被下一帧撤销。
  - **这条规矩适用于表里每一项**: `6081h`/`6083h`/`6084h` 也在 `1601h` 里, 主站每
    周期都在下发它们 —— 不驱动就是下发 0。`6083h` 被下发成 0 会让 PV 的斜坡永远
    起不来 (现象: 报速度指令已被接受、却一步不走), 所以加减速度由接口下发
    (`em_set_ramp()`)。**界面侧不调它** —— `hmi`/`scan` 自己按实测 `dt` 做梯形插补;
    但 `em_setup` 里进 OP 之前那次 `em__pin_ramp()` (把常量写进镜像) 照走, 谁也绕不开。
    详见 [docs/ykd2205pe_ci402.md](docs/ykd2205pe_ci402.md) 的「PDO 映射」。
  - 上面这几条**不是 GUI 独有的**: `em_setup` 与 `em__pin_ramp()` 是 `scan` / `hmi`
    每次「连接」都要走的路, 走错了现象与当年 CLI 上一模一样。
- `hmi` (Qt 上位机) 沿用**原 CLI 那一套护栏**, 只是把 `--allow-*` 换成了按钮:
  - **启动后一个字节都不写**。按钮形态完全由总线遥测推出来。
  - 顶栏「连接」= `em_open` + `em_setup` + 进 OP, **开始每 2ms 发帧**, 并会覆盖生效 RxPDO
    里主站拥有的那些项 —— **但这一步不发使能, 电机不带电**。点它会先弹一个说清这些的确认框。
  - **「使能」是唯一让电机带电的按钮**, 每次点击都弹模态确认 (要求"人在设备旁、手放在
    物理急停上") —— 这就是原先 CLI 的 `--allow-motion`。**没有持久勾选、不自动使能**。
  - 「停止」= 目标冻在当前位置并**保持保持力矩** (不卸力); 「失能」才是回失能态。
    `6041h` bit3 报故障 → 自动冻结目标 + 红色横幅。
  - 收尾 (断开 / 关窗) = 失能 → **还原 PDO 映射** → 降 `PRE_OP` → 关网卡。收尾时若
    **未能确认所有轴失能**, 会弹模态告警 (= CLI 退出码 **10** 的语义) —— 见到请立即
    断掉驱动器动力电源, 不要只依赖软件。
  - 界面坐标 ≠ `6064h`: 界面显示的是 `6064h − 软件零点`, 而**零点就是「连接」那一刻
    读到的位置**。所以开机 (连接后) 滑台显示在正中、且**一步不走**; 另有「设为 0」按钮
    就地重设零点 (它只挪软件零点, 不动驱动器的目标值)。
  - 行程 ±500000 脉冲 (50000 pul/圈 ⇒ ±10 圈)。点画布即走 —— **点远处就是一次长距离
    移动**, 点越界会被夹在 ±500000 上并在画布上标出来。
    (`HMI_RANGE` 现在只是个**缺省值**: `scan` 会经 `postRange()` 把量程调成跟它的
    扫描区域匹配; **hmi 从不调它**, 所以这条对它依然字面成立。)
  - 速度每轴一个滑块, 1000~100000 pul/s, 默认 20000。界面侧自己按实测 `dt` 做梯形插补
    (进近段自动减速), 不写 `6081h`, 也不走 `em_csp_move_multi`。
  - 它**不写** `2102h` (EEPROM)、**不动** `607Dh` 软限位、**不改** `2400h/2408h/2409h/2201h`。
- `scan` (Qt 上位机, 自动采集) 与 `hmi` **同一套护栏**, 但它是**一段没人看着的长动作**
  (默认参数下一趟约 100 分钟 / 3025 点), 所以额外注意:
  - **方向盘没动过之前, 先跑一行。** 默认区域 27×27 mm = **±13.5 圈 = ±675000 脉冲**,
    这个行程是**算出来的, 不是量出来的** —— hmi 那边的 ±500000 是一个**选定的软量程**,
    不是实测的机械行程, 机器上到底有没有 ±13.5 圈没人验过。
    **第一次请把区域改成 `27 × 0.5` (分辨率 0.5) = 55 点、约 2 分钟**, 看方向和两端到不到位,
    再决定要不要放开整片。硬件限位是真实存在的 (`2311h`/`2312h` 实测 = 2/3:
    X1 = 正限位 / X2 = 负限位, `2310h` = 1 即 X0 = 原点) —— 区域算错就是一头撞上去。
  - **`2201h` 的真实值从没被记下来过, 而现在没有任何程序会读它。** 它决定"1 mm =
    50000 脉冲"这个前提成不成立 (0 = 细分有效 ⇒ 当量来自 `2400h` = 50000; 1 = 电子齿轮比
    有效 ⇒ 当量来自 `2408h`/`2409h` = 1000, **差 50 倍**)。原先有个 CLI 的只读诊断会把它
    连宽度一起打印出来, 那个程序与那份参数基线 2026-09-21 一起删掉了, **`sm_spec_table[]`
    里那道"真值不对就挡住动作"的闸也跟着没了** —— `motor_api/ec_motor.h` 里
    `EM_OID_GEAR_ENABLE` 现在**只剩定义, 一个调用方都没有**。
    所以现在只有两条路: 用厂家上位机看一眼 `2201h`, 或者自己临时加一行
    `em_rd_u16(bus, slave, EM_OID_GEAR_ENABLE, 0, &v)`。**弄清它之前别按缺省区域扫**
    —— 当量差 50 倍时"27 mm"是 27 圈还是 0.54 圈, 没人知道。
  - 屏幕上的二维面板 **Shift + 左键**点哪里走哪里, 但**扫描进行中一律吞掉** (要先按「中止」)。
    **吞的只是手动定位** —— 只读的「查看」不归那道闸管, 扫描中照样能点。
    手动走点 (以及「全部回中」) 的速度是参数栏里单独的「手动速度」—— **只在没扫描时生效**;
    扫描 (含「重测选中点」) 用「扫描速度」。扫描一结束/中止, 手动速度会自己推回去。
    「手动速度」与「扫描速度」这两个框在扫描中都是**灰的**(2026-09-29, 见
    [docs/scan_sweep.md](docs/scan_sweep.md) §42.2): 扫描速度一轮只在下发那一刻设一次、
    手动速度扫描中根本不往外推, 留着能改就是让人白改。
  - **画布视野固定 30×30 mm** (每边 ±15 再留 1 mm 余量, 接受点击的边界是 ±16),
    **不跟着区域缩放**。
    区域框现在画在视野**里面** (默认 27×27, 每边还剩 2.5 mm), 左上角写着它的实际尺寸。
    **Shift + 左键**手动定位**面板上点到哪就走到哪** (软量程的下限就是画布半宽, 见 §28);
    真的被夹到时会由画出来的橙色三角显示出来。位置跑到面板外时那一行字会说 (区域 > 32 mm
    时可能发生)。
  - **两个左键分工**: **左键 = 查看那一格** (选中 + 读出数值 / 索引 / 坐标, 只读,
    扫描中也能点); **Shift + 左键 = 手动定位**。
  - **画布带坐标标尺**: 下边 X、左边 Y, 每 1 mm 一个小刻度、每 5 mm 一个带数字的
    (与网格线同一组位置, 零点用亮色)。手动定位是按坐标下发的。
  - 画布上的一切 (热力图 / 蛇形轨迹 / 滑台位置) 都**按 mm 存、画的时候才换成像素**,
    所以**拉伸窗口是整张图一起缩放**。
  - **色标条**: 值越大越红 (蓝 → 青 → 绿 → 黄 → 红), 条上两端加中间整数刻度都写数字。
    色标**默认锁定** (要「按数据定标」或改两个数才变); 勾上「自动跟随数据」则跟着已采
    数据的最小/最大走 —— 代价是新采到一个更极端的值整张图就重排一次颜色, 要对比两张图
    时把它关掉。**勾着的时候「最小」「最大」两个框是读数而不是输入: 只读、且不画上下
    箭头**(2026-09-29, 见 [docs/scan_sweep.md](docs/scan_sweep.md) §42.3), 要手改先把那个
    勾去掉。
  - 布局: 左画布 | 右参数栏, 中间一根**可以拖的分隔条**。窗口变大, 多出来的全给画布;
    参数栏自己上下滚 (六组框约 1330px, 窗口通常只给它 670)。
  - **横幅不进布局** (2026-09-20 改): 那条提示横幅**浮在画布顶上**, 不占体积 ——
    原先它排在分隔条上面, 一出现就把参数栏连同分隔条整体往下推一行高, 一消失又弹回去,
    而横幅是**来回闪**的 (连接/断开/每次提示), 于是参数栏一直上下跳, **点偏一格就点到
    别的按钮上**。它同时挂在 "鼠标点它要能穿过去" 上, 所以点那一块仍然是在点画布。
  - **画布顶上给它留了一条空带** (2026-09-21 改): 那 20px (`MapCanvas::kBannerBand`)
    什么都不画, 横幅就落在里面 —— 画图区与左上角那三行 HUD (进度 / 状态 / 区域)
    **一起下移 20px**, 于是横幅挡不着任何字。代价是画图区小 20px。
    空带按**一行**横幅定高; 换一句更长的话折成两行时会超出它, 重新压住第一行。
    带子**最小 8px** (再小横幅就压住 HUD 第一行)。
  - 「扫描参数」组底部有**「恢复默认」**: 这一组每一项都回到缺省值
    (区域 27×27 / 分辨率 0.5 / 1 mm = 50000 脉冲 / 速度 20000 pul/s …), **CSV 路径不动**。
  - **限位判据 (默认 = `6041h` bit11「硬件限位信号有效」) 几处同时显示**: 状态栏常显的
    两根轴 (**信号灯 + 文字**)、参数栏「轴信号」里那三个限位灯、画布上实测位置点外面的一圈
    红环 + 是哪根轴、以及上升沿那条不自动消失的横幅。
    措辞一律是**「有效」而不是「撞上」**: 手册对这一位的定义就是硬件限位信号**此刻的
    电平**, 不是一次已经发生的碰撞 (回零时它本来就该是 1)。
    判据**只有一处定义** (`ecatcmd::limit_hit` / `limit_rule_for`, 在 `hmi/ecatworker.h`),
    界面只读它算好的那个字段。
  - **限位守卫 (2026-09-29, 见 [docs/scan_sweep.md](docs/scan_sweep.md) §43)**: 上面那几处
    只是**显示**; 从这一轮起, 撞过某一侧之后那一侧**从此不许再点过去**。
    撞上那一刻滑台**停住** (目标冻在当前位置, 保持使能), 当时的位置**逐轴逐侧记下来**
    (落在 `bin/scan.ini` 的 `limit/*` 里, **触发即落盘**), 画布上从此画出**一条限位线与外侧
    的阴影区** —— X 轴那一侧是竖线 (左边或右边阴影), Y 轴是横线 (上边或下边), 线旁写着
    `X 轴负限位区` 这样的字; 之后**往那一侧点会被夹到线上**, 横幅里说明夹到了哪儿,
    而**点回来一律照走**。
    扫描那边管的是**起点**: 网格里有任何一点越过那条线就**拒绝启动** (参数栏出红字,
    写明"记在多少 pul、网格最远要到多少 pul"), 不让它跑到一半才缺一个角。
    - **记下来的位置只许往外** —— 贴着线反复试, 线不会一寸寸啃进来。
    - **回零 / 设为区域中心 / 设软件零点之后整份作废** (线消失、夹取解除): 记录里存的是
      **那个坐标系里的一个点**, 零点一搬那个数就没有意义了。**没有清除按钮** —— 想清回一次零。
    - **关掉「让 `60FDh` 进 TxPDO」照样会停** (停由 `6041h` bit11 管), 但**分不出是哪一侧
      就不记线** —— 那时没有线、没有阴影、也不夹。回零与找限位那两趟**整套豁免**
      (那两趟就是要去撞开关的)。
    - **线旁那个字与 HUD 那行字只在滑台离那条线 2 mm 以内才写** (2026-09-30, 见
      [docs/scan_sweep.md](docs/scan_sweep.md) §48): 线与阴影**照旧画** (那是"以后不许越过"
      的界, 与滑台在哪无关), 收掉的只是**文字**。位置不知道时 (没连接 / 没帧) 也一个字不写
      —— 说不出滑台在哪, 就说不出一句"接近"。
    - **这不是机器级的保护**: 记录只活在 `scan` 里, 一个字节都不写 `607Dh`, 所以 **`hmi`
      照旧能一路开到开关上**。硬件限位开关仍是最后一道。
    - **界面侧的停有 ≤ 33 ms 的滞后** (守卫挂在 30 Hz 的刷新上): 手动速度下大约几百个脉冲,
      不是"精确停在开关上"。与既有的红横幅、红环同一条时间尺度。
  - **信号灯的语法只有一条: 灯亮 = 这个名字代表的事正在发生; 灭 = 没发生; 灰 = 不知道。**
    灰 / 灭 / 绿亮 / 红亮 四种样子 (`ScanWindow::Lamp`)。**绿 = 使能带电, 红 = 出事了,
    这两个以外都不亮**。
    同一根信号在状态栏和参数栏**用的是同一套语法、同一份遥测**。
  - **参数栏最上面那一块「轴信号」** (2026-09-20 由「轴信号」与「限位开关」两块合成:
    **一行一根轴**, 最右边一格是**「故障复位」**):
    每根轴一行**六盏灯** —— **使能 / 故障 / 通讯** 与 **原点 / 正限位 / 负限位**,
    后面跟着各自那行字 (已使能/未使能、无故障/有故障、压住/松开)。前两盏问 `6041h`
    bit2/bit3, 后三盏问 `60FDh` bit2/1/0; 「不知道」这一态跟状态机里那个信任条件是同一个
    (`m_connected && valid && mirror_ok`)。
  - **「通讯」是 2026-09-22 加的那盏, 它问的不是驱动器而是这台上位机自己**: 过程数据帧
    **连续不足** `HMI_BAD_WKC_LIMIT` (10) 帧 ⇒ 红亮。跟「故障」那盏是**两件事** ——
    「故障」= 驱动器自报 (`6041h` bit3 或 `603Fh` 非 0), 「通讯」= 主站自己没按时把帧发出去
    (工作计数器 `WKC` 不足)。两件事处置不同, 所以措辞也刻意不共用。
    这盏灯的信任条件**刻意不含 `mirror_ok`**: 帧差到一定程度 `mirror_ok` 就降 0,
    用那个条件的话它会在事情变糟的那一刻从红变成灰 —— 恰好相反。
    配它的还有: 状态栏那句「最长 `N` ms 没发帧」(这台 PC 是不是元凶的那把尺)、
    连续不足帧数、以及异常时读一次的 AL 状态码; 以及一条**不自动消失**的红横幅。
    2026-09-24 又加了**平均帧周期**那半句(「· 帧周期平均 `N` ms (上限 `M` ms)」):
    它是**另一把尺** —— 上面那个数只记 > 50 ms 的离群点, 看不出节拍**均匀地**慢下来,
    而实测那正是本机出过的毛病(见下面那条省电项与 `docs/scan_sweep.md` §34)。
- **上位机侧要关掉的省电项 (2026-09-23; 这是「最长 N ms 没发帧」的根因处置)。**
  现场实机量到: 空闲挂着没人动, 本程序**最长 1657 ms 一帧都没发出去**(超 50 ms 共 12 次),
  两台驱动器的 SM 看门狗因此动作(AL `0x14` / 状态码 `0x001B` = 主站喂帧超时), 从站停止
  过程数据交换, 工作计数器恒为 2/6 —— 于是复位/使能全被拒, **唯一的回程是「断开 → 重连」**。
  已量到本机两条证据: 网卡是 Realtek PCIe GbE, 省电特性全开 (`*EEE` / `EnableGreenEthernet` /
  `GigaLite` / `PowerSavingMode` / `*InterruptModeration`); 电源计划是**平衡**,
  `SUB_PCIEXPRESS`/`ASPM` = `0x2`(最大电源节省量), 交直流都是。
  **一层一层改, 改完用状态栏那两句验收 ——「最长 N ms 未发帧」与「帧周期平均 N ms」
  (2026-09-24 加的)。两个数都不动就说明这一层没生效, 别接着往下改。**
  **只盯前一个是会漏的**: 本机还有一条它看不见的毛病 —— 节拍整体慢成一个系统 tick
  (`Sleep(2)` 实际睡 15.9 ms, 应为 2.5 ms), 帧是**均匀地**每 15.9 ms 才发一次。那个数
  只记 > 50 ms 的离群点, 所以全程不变。处置(`em_sleep_ms` 换高精度定时器 + 工作线程
  起手拒绝省电节流)与实测数据见 `docs/scan_sweep.md` §34。
  ```powershell
  $n = (Get-NetAdapter | Where-Object { $_.InterfaceGuid -eq '{7C64E0FA-D69A-4C92-A821-E5D341E63575}' }).Name
  Set-NetAdapterAdvancedProperty -Name $n -RegistryKeyword '*EEE'                -RegistryValue 0
  Set-NetAdapterAdvancedProperty -Name $n -RegistryKeyword 'EnableGreenEthernet' -RegistryValue 0
  Set-NetAdapterAdvancedProperty -Name $n -RegistryKeyword 'GigaLite'            -RegistryValue 0
  Set-NetAdapterAdvancedProperty -Name $n -RegistryKeyword 'PowerSavingMode'     -RegistryValue 0
  Set-NetAdapterAdvancedProperty -Name $n -RegistryKeyword '*InterruptModeration' -RegistryValue 0
  Set-NetAdapterAdvancedProperty -Name $n -RegistryKeyword '*PriorityVlanTag'    -RegistryValue 0
  Set-NetAdapterAdvancedProperty -Name $n -RegistryKeyword '*FlowControl'        -RegistryValue 0
  Set-NetAdapterAdvancedProperty -Name $n -RegistryKeyword '*SpeedDuplex'        -RegistryValue 4
  Disable-NetAdapterPowerManagement -Name $n     # 「允许计算机关闭此设备以节约电源」
  powercfg -setacvalueindex SCHEME_CURRENT SUB_PCIEXPRESS ASPM 0
  powercfg -setdcvalueindex SCHEME_CURRENT SUB_PCIEXPRESS ASPM 0
  powercfg -setactive SCHEME_CURRENT
  ```
  `*SpeedDuplex` 的 `4` = 这台驱动里「100 Mbps 全双工」的那个值 (0=自动侦测 / 4=100M FD /
  6=1G FD), 钉死它只为不让它周期性重协商 —— 现场本来就跑 100 Mbps。
  **回滚** = 把每条的值改回改之前读到的 (`Get-NetAdapterAdvancedProperty` 一读就有,
  `*SpeedDuplex` 回 `0`)。`Disable-NetAdapterPowerManagement` 在本机可能报
  `Windows System Error 31` —— 那就去「设备管理器 → 网络适配器 → 属性 → 电源管理」用 GUI
  取消勾选; **顺手看一眼那个报错还在不在, 查询本该成功却失败, 本身就像驱动状态不对**。
  没上 `PROCTHROTTLEMIN=100`(CPU 最低状态拉满): 这是笔记本, 先看上面这些够不够,
  一次动三层的话下回再出问题就分不清是哪一层。
  **未解的一个疑问**: `2217h`(本机实读 = 20)在文档里标注为「同步帧阈值」, 程序只读不写。
  若它真是驱动器侧的看门狗阈值, 放大它就能容忍上位机的长停顿 —— 但那是**削弱保护**不是修
  根因, 且要先对着手册 V2.4 p84 确认它到底是不是这个意思。本轮**不碰驱动器参数**。
- **自动重请求 OP (兜底) 与「重连总线」按钮。**
  停顿真发生了、从站没跟回来时, 程序会**自己**把过程数据救回来(「重连总线」旁边那条出口
  不再需要人自己悟)。它**只管把 AL 拉回 OP 并让各轴停在未使能**, 明确不做: **不重新给
  力矩、不自动使能、不清驱动器故障位、不碰仍在 OP 的轴、不重建 PDO 映射**。
  触发前要过一串闸, **两个条件各管一头**: 本机**按时**发帧连续够久
  (`HMI_RECOVER_ARM_FRAMES` = 1000 帧 ≈ 2 s) **且**过程数据帧连续不足够久
  (`ecatcmd::recover_bus_broken`); 再加冷却 30 s、本会话最多 2 次, 而且有任何命令在
  跑/在排队时一点都不碰。
  - 第二个条件(总线**确实**坏着)是 2026-09-23 第一次实跑补上的: 少了它, 一条**健康**的
    总线在连上约 2 秒后就会被点着 —— 白阻塞界面 1~3 秒、白烧一次尝试次数(上限只有 2),
    而它自己紧接着还会报「所有从站的 AL 都在 OP」。**动手前那句话现在只说真的查过的事**:
    「本机已连续 N 帧按时发出, 而过程数据帧仍连续 M 帧不足」。
  - 爬 `AL` 阶梯之前**先单独清一次错误位**: 写「当前那一级 `|` ACK」, 每圈照常发过程数据,
    等 bit4 自己消失再往上爬。状态字 bit4 是**闩锁**, 而"含错误位就立刻判失败"那条会在
    **第一帧**就返回 —— 把 ACK 与目标级一起写、或者清错期间断帧, 症状都是"重请求了但没上去"。
  - 三种局面**一个 AL 字节都不写**, 只喊人: 有从站**没答话**(AL 读回 0 = 掉线/掉电)、
    有从站停在 **INIT/BOOT**(配置已丢)、以及「有轴仍在 OP 且 `6041h` bit2 = 1(可能正带
    保持力矩) + 有轴掉出 OP」的**混合局面**(只把掉出去的那根救回来会让另一根单独抱着负载;
    竖直轴会被扭)。前两种和"没救全"都只有**「重连总线」**能恢复。
  - 「重连总线」= 断开(**先给各轴卸力**, 滑台失去保持力矩) → 重连(重新进 OP, 各轴停在
    **未使能**)。它没连上时等同「连接」; `hmi` 会先弹确认框(`scan` 与它自己的「断开」一致,
    不弹)。这两个程序都摆在顶栏「连接/断开」旁边, **不藏进菜单栏或独立窗口**。
  - 帧间隔统计现在**分两份**: 净的外部停顿, 与**本程序自己的命令造成的**那一份(复位/使能/
    回零期间 SOEM 的 SDO 事务一帧都不发)。**自动恢复的触发只看前者** —— 不分开的话, 我们
    自己一次使能造成的静默会被读成"这台 PC 在卡", 把人支去查电源计划与网卡节能。
    状态栏/横幅在最长的那个间隔是自家造成时会点明。**这一份归因曾经是错的**
    (2026-09-23 实跑): 自动恢复收尾处跳过一次帧间隔测量, 却没把"这一次该归给谁"一起吃掉,
    于是标志漏给了下一次测量 —— 一段纯外部的停顿被写成"本程序自己的命令造成的", 正好把人
    从根因上支开。修在 `serviceAutoRecover` 收尾: 跳过一次测量就必须同时吃掉那个标志。
  - **合成一块不改变判据**: 两组信号回答的是**两个不同的问题** —— 「会不会中止扫描」看
    `6041h` bit11 (状态栏那对灯 / 画布红环 / 横幅); 「**开关本身压着没有**」看 `60FDh`
    三个位。两者**可能不一致, 不一致时以 bit11 为准**。表头上前两个名字与后三个名字分得开,
    每格的 tooltip 里写着自己问的是哪一位; 判据在 `refreshAxisSignals()` 里照旧分两次算。
  - **宽度**: 六列灯 + 复位那格 (2026-09-22 由五列变六列: 多出「通讯」那一列, 于是这块
    再宽一格 —— 五列时实测约 **413px**, 六列**没重量过**, 参数栏的最小宽度跟着它走)。
    多一列的代价是画布窄一点, 这是**认下来的**: 那一列是操作员唯一能看见"是不是这台
    PC 的锅"的地方, 藏进菜单或独立窗口就等于没有 (原先四列那块约 280px)。
  - **原点那盏灯是绿的, 而且是唯一一盏"绿 = 正在发生"的非使能灯**: 压到原点是回零时的
    正常动作, 是**位置信息不是故障**; 而**扫描经过原点开关不会中止**(中止只由 bit11 决定)。
    正/负限位才是红灯。三个格子用同一组词 (压住/松开), 所以**颜色是唯一说"这个会撞"
    的东西** —— 悬停原点的 tooltip 会把这句话说出来。
  - **`60FDh` 读不到是常态** (本机生效的 `1A00h` 里没有它), 那时三个灯是**灰 + `--`**,
    而那**不是**"三个都没压住" —— 这两件事在数据里分开存, 不许互相冒充。
    要让它们亮起来: 优先**用厂家上位机改一次驱动器的 `1A00h`**(零代码、断电也在),
    或者勾上那个「让 `60FDh` 进 TxPDO」让主站在连接时补一次 (只写 RAM, 收尾还原)。
  - **「故障复位」**清驱动器的故障位 (`6040h` bit7 上升沿)。**只对报了故障的轴写字节**
    (判据是 `6041h` bit3, 不是操作员点了哪个按钮 —— 所以按钮不带轴参数);
    **一根轴都没报故障时一个字节都不写**, 按下去也安全。
    复位的动作是**先写 `6040h = 0x0000`(卸力) 再抬 bit7**(bit7 是上升沿触发), 而它
    **到函数末尾**才报告"本来就没有故障" —— 对一根**健康的保持轴**做这件事会真的松开
    保持力矩。复位成功后该轴停在**未使能**, 要接着走请重新点「使能」;
    扫描进行中不能复位 (先「中止」); **不弹确认框** —— 按下去就发, 但"它看起来要复位
    哪根轴"会用横幅说出来; 每轴最多 1 秒且**不可中断** (按钮在这期间显示「正在复位…」)。
  - **「回零与找限位」框**: 一行一根轴 (行首一个「轴X / 轴Y」标签), 每行**四个按钮** ——
    正向回零 / 反向回零 (找**原点开关** `X0`) 与 找正限位 / 找负限位 (把**限位开关本身**
    当机械基准)。两类走的是**同一条** `em_home()`, 共用框里那一个速度值:
    发起之前先过一道闸 (**没连上 / 位置未知 / 丢帧 / `6041h` bit3 故障 / 还有轴在走**
    → 拒绝, 且**一个字节都不写**), 判据**只看被点的那一根**, 不看另一根,
    **也不看它使能没使能** (未使能也能回零, `em_home()` 自己会先失能再使能)。
    **不弹确认框** —— 事前的说明在按钮自己的 tooltip 上 (轴 / 方向 / 方式号 /
    「**驱动器会自己带电并移动, 软件拦不住它撞开关**」/ **该轴会先失能**、
    竖直轴此时失去保持力矩)。框里**不写说明文字**: 面板上就是速度值、超时值、两个回零偏移值
    加八个按钮
    (本速度派生的**返回速度 / 加减速 / 最多走多远**与两根轴的 `6061h`
    只在**控制台**的回零收尾那句话里)。速度与超时**改完即生效, 关窗或「连接」时落进 ini**,
    而且**不在「恢复默认」的范围内**: 为试回零特意压小的速度、特意调长的超时, 不会被那个按钮
    顺手抬回去。
    回零期间**该轴按钮变「回零中…」** (找限位则是「找限位中…」)、顶部出横幅, 而「使能 / 失能 / 停止点 /
    设为区域中心 / 开始扫描」全部锁住。结束后**自动切回 CSP 并保持使能**
    (停在落点带保持力矩), 并**从 `6064h` 重新锚定显示零点**。
    **「回零偏移X / Y」(2026-09-28)**: 找原点(方式 24/29)停稳之后, 显示坐标 0 放在**落点
    正方向**该数处 —— 现场要的零点离原点开关的落点 75000 pul (1.5 mm), 所以**落点读出
    −75000**。缺省 75000, 填 **0 = 落点即零点**(与改造前一样)。**只对找原点生效** ——
    找限位(17/18)的落点仍是显示坐标 0。「全部回中」因此真的把滑台带到机械中间。
    超过当前量程(比如脉冲当量调小了)时**回零照常跑完, 这一趟不搬零点**, 并在结论句里写明。
    **不写驱动器的 `607Ch`**: 这是上位机的软件零点。改完即生效, 关窗或「连接」时落进 ini
    (`ui/home_off_x` / `ui/home_off_y`), **不在「恢复默认」的范围内**。详见
    `docs/scan_sweep.md` §38。
    **框里那个「速度」输入框**喂 `6099h:01`; 返回速度与加减速都由它派生 (返回 = 1/4,
    加减速按**斜坡时间 0.1 秒**算)。**上限与「扫描速度」同一个数
    (100000 pul/s ≈ 2 圈/秒), 缺省 50000 是驱动器自己 `6099h:01` 的实测值**;
    下限 100。**进 `scan.ini`** (`ui/home_vel`, 走「保存」才固化; 手改坏的值会被夹回量程内)。
    **普通超时框**喂 `em_home()` 那个等待上限 (等 `6041h` bit12), 单位**秒**,
    缺省 **120**、可改、夹在 5…600。**进 `scan.ini`** (`ui/home_tmo_s`), 现存 ini 缺这一项
    就是 120, 不需要迁移。**它同时是一条距离上限** (速度 × 超时): 缺省两者相乘 = 6000000
    脉冲 ≈ 120 mm, 是缺省扫描区域 (27 mm) 的 4.4 倍 —— 所以**够不着开关时该做的是先把
    滑台挪近, 不是把超时或速度调大**: 真正让滑台停下的是硬件限位开关。
    (2026-09-22 前它是写死的 30 秒, 只对缺省速度成立 —— 速度压到下限 100 pul/s 时
    30 秒只走 0.06 圈。)
    **回零用的是驱动器自己读到的开关电平, 所以「高级选项」里的「上位机侧取反」对它无效**;
    极性配反时 **必须先去改驱动器的 `2300h`** (也就是那个默认开着的「写驱动器 2300h」)。
    - **每行左边那两个是找原点开关**, 方式 **24** (正向) / **29** (反向); **右边那两个是找限位**,
      方式 **18** (以**正限位**为原点) / **17** (以**负限位**为原点), 手册叫「找限位」。
      找限位**落点在开关的释放点上** (刚退开一点的那个位置), 所以**那一侧几乎没有行程** ——
      跑完请按实测行程重算区域, 继续用旧区域扫会一路撞限位。
    - 找限位比回零**多一道闸**: **`60FDh` 读不到** (分不出手册的 a)/b) 两条分支,
      而两条分支的**首段方向是相反的**) 或 **正/负限位同时报有效** → 拒绝, 同样
      **一个字节都没写**。判据用的是**驱动器自己**那两位读数, 不是界面反相之后的 ——
      所以「上位机侧取反」不影响它; 出路是把「高级选项」里那个默认开着的
      「让 `60FDh` 进 TxPDO」重新勾上再「连接」。
    - 只有 17/18 这两个方式手册才分 a)/b) 两条分支 (启动那一刻那个开关**没压着**走 a,
      **已经压着**走 b, 而 b 与 a 的**首段方向相反**) —— 所以**发起之前会在控制台/
      状态栏预告这一趟走哪条**, 免得看到它先朝反方向走以为点错了按钮。
    - 找限位**故意**去撞限位, 所以这期间**不弹红色「撞限位」横幅、也不自动中止**;
      但**限位灯与状态栏那格照常变红**、stdout 那行证据照打。豁免只覆盖**正在找的那一根**,
      找完之后压住限位再启扫, 那条红横幅与自动中止**照常**发生。
    - **「测量原点宽度」(2026-09-28)**: 一个按钮管两根, 量出**原点开关的信号从进入到退出
      跨了多少脉冲** —— 那个数决定"拿原点开关当参考点时重复定位能有多准"。它先用方式
      **24** 把两根回到原点开关上 (与「回零校准」同一趟), 再顺着正向慢速走过去、盯
      `60FDh` bit2 翻两次, 读数落在按钮下面那一行 (**脉冲数 / 测量中 / 未测得(原因) /
      未测量** 四态)。段 2 的速度是**速度框那个值的 1/4**, 超时也复用那个框但**只对段 2
      计时**。**量完停在信号远端边沿, 显示坐标不回到落点** (段 2 不重锚零点) —— 要回 0
      再按一次「回零校准」。`60FDh` 读不到时**按不动**(也拒绝发起): 采不到那条信号,
      这一趟什么也量不出来。详见 `docs/scan_sweep.md` §35。
  - **「停止」在回零进行中 = 立即中止** (≤2ms 被 `em_home()` 的轮询看见),
    **并且保持使能** —— 中途位置不明, 卸力会让竖直轴自由下滑。
    它走的是 GUI 直呼 `em_request_stop()` (**不是**命令队列: 队列要等回零退出来才轮到,
    那样最长要等**整个回零超时**, 缺省 120 秒) —— 这是全程序**唯一**一处 GUI 直呼 `motor_api`,
    安全理由是**结构性**的 (那行只往一个原子量里存 1, 不碰总线、不做 I/O)。关闭窗口 /
    断开时也会先中止回零。
  - **自动中止** (红色横幅 + 模态框): 掉出 OP / `6041h` bit3 故障 /
    **`6041h` bit11「硬件限位信号有效」** (勾了上位机侧取反则改看反相后的正/负限位开关,
    见 `ecatcmd::limit_rule_for`) / WKC 连续掉帧 / 丢帧或掉使能 / 有人从旁路改了目标 /
    走到位超时 / CSV 写失败。注意 bit11 报的是那路限位信号**此刻的电平** (手册原话),
    不是"撞过了"也不是闩锁 —— 回零时它本来就该是 1, 而**极性配反**会让它恒为 1。
  - 「暂停」「中止」都把目标冻在当前位置并**保持保持力矩** (故意不写 `6040h=0x0000`,
    那是卸力, 滑台会因自重下滑)。「继续」会**重新走完当前点并重新采样**, 不会写进半点数据。
  - 断点续扫 = 打开一个已存在的 CSV 继续追加。**打开时会先把参数栏的区域 X / 区域 Y /
    分辨率 / 每 mm 脉冲数对齐到那份文件**, 再照旧接上 —— 对齐是"把控件改了", 所以参数栏自己
    那套「● 未保存」+ `[保存]/[取消]` 就是它的兜底 (按「取消」= 退回对齐之前那份值),
    横幅提一句; 本来就一致的话一个数都不动、一个字都不说。**只有对不齐才拒绝** —— 表头缺

    **不弹确认框**, 直接按"允许世代不同"接上去, 并把那句差异留在**红色横幅**上
    (接错了「中止」随时可按, 已经采到的点都在 CSV 里)。
  - **续扫是两步 (2026-09-29)**: 打开 CSV **只把数据读进来** —— 上半场画在画布上、要补哪些点

    开始补点。装载期间几何那几项与功率计那几项配置**改不动**(要改先「中止」), 「中止」在
    装载态 = **放弃这次装载** (画布上那半场一起清掉, 回到未装载, 之后可以按「开始扫描」新建
    一轮)。按「继续」时"几何还是装载那一份吗 / 零点世代还是装载那一个吗"会**重查一遍** ——
    这段时间里工作线程可能自己搬过零点, 拦下时留在装载态, 接好线再按一次就行。
    **这一族按钮 2026-09-30 起没连接就不亮** (见 [docs/scan_sweep.md](docs/scan_sweep.md) §47):
    「打开 CSV 续扫」「继续」「重测选中点」与「开始扫描」一样, 都要先连上总线; **「中止」不在
    此列** —— 它是退出去的那一个, 断了线正靠它退出装载态。同一轮里 **CSV 那个路径框搬进了
    「扫描控制」**(与「打开 CSV 续扫」同一框); 它右边那个按钮原先被钉死在 28 px、字被剪得只剩
    三分之一 (看着**只有一个点**), 现在不设固定宽了 —— 是完整的「…」(**三个点**); 而「扫描参数」
    最上面那三句说明 (网格 / 时间估计 / 参数不合法的红字) 从这一框的**最底下**提到了最上面。
  - **零点跨断开重连保留 (2026-09-22 起跨重连, 2026-09-29 起跨程序重启; 只对 `scan`)**:
    断开再「连接」**不再重设零点** —— 界面正中仍是上次那个物理位置, 滑台接着显示断开前
    那个数, 而且**连接那一刻一步不走**。**关掉程序再开也一样**: 那份零点连世代一起记在
    `bin/scan.ini` 里, 重开之后接着显示 (连接那一刻的横幅写「零点从 scan.ini 恢复…」)。
    要还原就用「回零」或「设为区域中心」; 想彻底清掉就删 `bin/scan.ini`。
    **限位记录 (见上面「限位守卫」) 跟着同一个世代一起作废**: 回零 / 设为区域中心 / 设软件
    零点之后, 记下来的那几条限位线整份当没记过 —— 它们记的也是**那个坐标系里的一个点**。
