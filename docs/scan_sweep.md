# `scan`:滑台蛇形扫描 + 逐点功率采集

控制滑台在一个矩形区域里**蛇形(逐行往返)扫描**,每到一个网格点停下来,读一次功率计,
把 `(X, Y, 功率, 时间戳)` 追加进 CSV,最后得到一张功率分布图。

它与 [hmi](hmi_click_position.md) 是**并存的两个程序**,不是一个程序的两种模式:

| | `bin/hmi.exe` | `bin/scan.exe` |
|---|---|---|
| 干什么 | 手动调试台:点哪里走哪里 | 自动采集:自己走完一个区域 |
| 面板 | 两根一维轨道 | 一块二维面板 + 热力图 |
| 会自己动吗 | 不会 | 会,而且一次一两小时 |
| 共用 | **同一个 `hmi/ecatworker.cpp` 编进来的** —— 线程模型 / 坐标零点 / CSP 插补 / 全套护栏只有一份实现 | |

**功率计是 PD300R + Juno+**(走 Ophir 的 COM,见 §7.1),另有三个模拟源。
接真机时**状态机、CSV、热力图一个字都没改** —— 改到的只有界面 (多三行设备选项 +
一个「读一次」按钮) 与一个专属工作线程。

## 2. 线程模型:总线线程一个字不改

现有边界是 **`EcatThread` 独占总线,GUI 侧只经 `post*` / `set*` / `telemetry()` 与它交互**。
扫描完全落在这条边界的 GUI 一侧:

```
GUI 线程                                  工作线程 (2ms 循环, 不动)
─────────                                 ──────────────────────────
ScanController (30Hz, 时钟由外面喂)
  ├─ BusView::setTarget(axis, want)  ───▶  m_want[]  ─┐
  ├─ BusView::telemetry()            ◀──  BusTelem   │ interpolate(dt)
  └─ 状态机: Moving→Dwelling→Reading→Log             └─▶ em_csp_set_target
```

中间隔着一层 `BusView`(只有四个方法):
[hmi_click_position.md](hmi_click_position.md) 的「尚未验证」一节写明
**hmi 的「连接」那条路一次都没在真机上跑过**。也就是说这个仓库目前**没有可用的真机回路**
来验扫描状态机。而状态机里真正会出错的是暂停/继续/中止、到位窗口、外部改目标、
续扫从哪接上这些**时序**问题,它们跟总线没关系,只跟状态机有关。
换成 `FakeBus`(自己按速度推 `pos`,能注入掉帧/故障/失能/限位),整个状态机就能
**在没有硬件的情况下跑通** —— 这就是 `scan_selftest` 干的事。

**节拍是外部喂的**(`tick(now_ms)`),不是状态机自己起定时器。
时间一律用**单调钟**(`QElapsedTimer`)—— 墙上时间会被 NTP 和对时往回拨,
那样"停留了 200ms"可能永远不成立,扫描会卡在那一点上。

30Hz 对到位判据够用:换行一次移动要几百 ms,停留最少也有 100ms 量级。

### 唯一的例外:GUI 线程直呼了一次 `em_request_stop()`

上面那条边界在此之前是**无例外**的(除了 `main()` 里那句只设控制台代码页的
`em_console_init()`),现在有两个例外,都写在
[hmi/ecatworker.h](../hmi/ecatworker.h) 顶部。

非开不可的原因是**结构性的**:回零是 `em_home()` 在**工作线程里阻塞着**跑完的
(它自己泵帧、自己每 2ms 轮询 `6041h`),而命令队列是在 `EcatThread::run()` 顶部
**由同一个线程**排空的 —— 回零期间投进去的 `CMD_STOP` 要等 `em_home()` 退出来才被看见,
也就是最长 30 秒之后。

它安全的理由**同样是结构性的**:`em_request_stop()` 只往一个
`static volatile sig_atomic_t` 里存 1 —— 不碰 `em_bus_t`、不碰网卡、不做任何 I/O。
motor_api 自己就是按「信号处理器里也能调」来设计它的(见
[ec_motor.c](../motor_api/ec_motor.c) 里 `em_request_stop` 那一段)。所以它跟
「GUI 线程不许碰总线状态」这条规矩不冲突 —— 它碰的不是总线,是一个原子量。

**用它的地方只有两处**,都在 `scan/scanwindow.cpp`:
- 「停止」按钮在回零进行中走的那一支(`onStopClicked`);
- 断开 / 关窗收尾的第一步(`disconnectAndStop`)—— 那条路径是同步等 12 秒的,
  而回零单个动作就能阻塞 30 秒,不先掐掉就会在 `QThread` 被拆时还在泵帧。

`hmi` 那两个按钮**一个字都没改**(它连回零功能都没有),所以这条例外对它不存在。

## 3. 单位、坐标与量程

```
1 单位 = 1 圈 = 50000 脉冲     (2400h 实测值, 是可调参数 pulses_per_unit)
显示坐标 = 6064h 原始值 − 软件零点
零点     = 「连接」那一刻读到的位置, 或「设为区域中心」按下的位置
区域     = 27×27 单位, **以原点为中心** → ±13.5 单位 = ±675000 脉冲
```

### 量程必须跟着区域走

`HMI_RANGE` 原来是编译期常量 `500000`,扫描区域要 ±675000。它在 `ecatworker.cpp` 里
夹了 **4 次**(`setTarget()` 两次、`interpolate()` 两次)。直接复用会把区域边缘
**悄悄削掉**。

改法(**纯增量,`hmi.exe` 行为逐字节不变**):

- `m_range` 从常量变成 `std::atomic<int32_t>`,**默认仍是 `HMI_RANGE`**
- 新增 `postRange(int32_t)`,走 `m_cmds` 队列(与 `postCenter` 同一个模式)
- `hmi` 自己从不调 `postRange`,于是它拿到的永远是 500000

```
量程脉冲 = ceil((max(area_x, area_y) / 2 + 1.0) * pulses_per_unit)
         = ceil((13.5 + 1.0) * 50000) = 725000     (默认参数)
```

`+1.0` 的余量是给**手动对位**用的:扫描区域之外还能手动走一点。
`range_pul` **不暴露给操作员**,永远按区域自动算。

> **`postRange` 有个必须绕开的陷阱。** `interpolate()` 是**先夹 `m_tgt`、再用 `m_tgt`
> 算 CSP 目标**的。所以如果把量程**改小**、而滑台此刻正停在旧量程的边缘外,那一夹就会
> 把 `m_tgt` 拽回来 —— **等于凭空产生一次运动,而且是没人按过任何按钮的运动**。
> 所以 `doRange()` 的规矩是:**放大无条件允许;缩小只在新范围装得下所有轴的当前
> `m_tgt` 时才允许,装不下就拒绝**并提示"先把滑台走回区域内"。绝不为了迁就新量程
> 去改 `want`/`tgt`。

## 4. 网格与蛇形

```
n     = floor(area / res) + 1        // 27 / 0.5 + 1 = 55
span  = (n - 1) * res                // 27.0
坐标[i] = -span/2 + i * res          // -13.5 .. +13.5, 共 55 个
```

`area / res` 除不尽时取 `floor` 并**把网格居中**(此时 `span < area`),
于是永远**不会越出区域**。

轴 0 = **X**(行方向,快轴),轴 1 = **Y**(列方向,慢轴)。默认蛇形(逐行往返),
也可以改成每行同向。第一行的方向由「起始方向」定。

> **蛇形里每一步只动一根轴。** 行内走 X、Y 不动;到行尾时下一个点
> 就在下一行的同一列上,于是 X 不动、只有 Y 进一格。稳态下**不会出现两轴同时走的斜线** ——
> 唯一一次斜着走是「从当前位置到第一个网格点」那一步(以及续扫/重测时)。
> 每步要么是 `res` 的距离、要么是行尾一格 `res`。

### 时间估算

`estimatePerPointMs()` 是**线性**的:

```
移动   = res * pulses_per_unit / speed * 1000 = 25000 / 20000 * 1000 = 1250 ms
每点   = 移动 * 1.30 + settle + dwell + 50 * samples
       = 1625 + 100 + 200 + 50 = 1975 ms
全程   = 3025 * 1975 ms ≈ 100 分钟
```

`* 1.30` 是给**进近段减速**留的粗估,`50 * samples` 是采样本身占位
(模拟源是 0,真机未知)。界面上会明说这是线性估计、**实际更长**。

## 5. 到位判据

`AxisTelem::at_target` 只是 `want == tgt`(`ecatworker.cpp`),那是**插补器自己走完了**,
**不等于实际位置到了**。所以判据是**两个都要**:

```
到位(i) = telem.ax[i].at_target                     // 插补目标已到终点
       && |telem.ax[i].pos - want_i| <= pos_tol     // 6064h 实测也在容差内
```

并且要**连续 `settle_ms`(默认 100ms)成立**才算稳定 —— 单帧瞬时满足可能在高速
掠过时误判。窗口一旦被打破就**重新计时**。

`pos_tol` **由步长推出来,不暴露给操作员**:固定 50 pul 在 25000 pul 的步长下是 0.2%
(合适),但有人把步长调到 500 pul 时就变成"允许偏 10% 个格子"(不合适)。
所以按步长取 1/20,并夹在 `[50, 步长/4]` —— 默认参数下是 **1250 pul**。

**没有单独的 `Settling` 状态**:稳定窗口就长在 `Moving` 里,界面想问"现在是在走
还是在等稳定",用 `settlingNow()` 读。

## 6. 状态机

```
Idle ──开始──▶ Moving ──到位且稳──▶ Dwelling ──停够──▶ Reading ──采到──┐
                 ▲                                                      │
                 └──────────────── 下一个点 ◀──────────────────────────┘
                 全部走完 ▶ Done

Paused / Aborted 可以从上面任意一个状态进来, 且**立刻生效**。
```

- **Preflight**(缺一不可,全过才动):在 OP · 已使能 · 两轴 `mirror_ok` · 功率计已开 ·
  CSV 可写 · 参数合法 · 区域半宽 + 余量 ≤ 量程 · 点数 ≥ 1 且 ≤ 200000
- **Moving**:`setTarget(0, x_pul)` + `setTarget(1, y_pul)`(显示坐标),等两个轴都到位
- **Dwelling**:停 `dwell_ms`
- **Reading**:发一次 `requestReading()`,等信号回来(异步)。超时(默认 2s)
  或 `readingFailed` → 该点标为失败,CSV 里功率列写空、带一列错误原因,
  **扫描继续**(一个点读不到不该毁掉整轮)
- **Log**:追加一行 CSV + `flush` + 刷新热力图 → 下一个点

**`samples_per_point > 1`** = 到点后连采 n 次取平均。代价是每点多 n 倍**读数时间**
(真机串口一次几百 ms 时这项很贵),不是塞在停留期里白拿 —— 停留期是"等机械稳定",
两件事不该混。

### 暂停 / 继续 / 中止

- **暂停**:立即 `postStop()` 冻在当前位置(**保持保持力矩,不卸力**),
  当前点标记为未完成。**响应是立即的**。
- **继续**:**重新走向该点并重新采样**,所以不会写进半点数据的半成品。
- **中止**:同样冻住,状态转 `Aborted`,**已完成进度留在 CSV 里**。

> 暂停/中止走的是 hmi 的「停止」语义:**故意不写 `6040h=0x0000`**,那是卸力,
> 滑台会因自重下滑。

### 自动中止(每个 tick 都查)

扫描是**一次一两小时、没人看着**的长动作,所以下面这些在**每个 tick** 都查,
命中就立刻自动中止:

| 条件 | 备注 |
|---|---|
| 掉出 OP / 连接断了 | |
| 任一轴 `6041h` bit3 故障 | `EcatThread` 已经会冻结目标,但扫描必须停下来 |
| 任一轴 `6041h` bit11 撞硬件限位 | 判据读 `AxisTelem::limit_active`(只有 `ecatcmd::limit_hit()` 一处算出)。中止文案会把 `60FDh` 那一行一并写出来(哪个开关压着 / 状态未知) |
| WKC 连续 10 帧不足 | 拔网线就是这个表现 |
| 任一轴丢帧(`mirror_ok` 掉)或掉使能 | |
| 有人从**旁路**改了目标 | 见下 |
| 走到位的最后期限 | `max(5000, 距离/速度*3 + 3000)` 封顶 120s —— 卡住/被夹住时的兜底 |
| CSV 写失败 | 宁可停,也不要默默少采几千点 |

中止时弹**红色横幅 + 模态框**。

> **`externalWantChanged()` 的两个坑。**
>
> 1. `setTarget()` → `publish()` 之间差一个 2ms 周期,所以下发之后不能立刻比 ——
>    那样会把自己当成外部干预。于是有一道"等它出现"的确认门(`m_want_ok`)。
>    但这道门**可能永远开不了**:如果在我们自己的值出现**之前**就有别人改了目标,
>    扫描会跟着别人的目标一路走下去,直到 120s 的移动期限才停。
>    所以加了 `WANT_CONFIRM_MS = 200`:下发 200ms 内没看到自己的值,就判定为外部干预。
> 2. **暂停时目标本来就"不是我们下发的那个了"** —— `postStop()` 把它冻在当前位置
>    (`want := tgt`),而那正是我们要的。不在暂停时放行的话,**一按暂停就会被自己
>    判定成"有人从别处改了目标"然后自动中止。**

## 7. 功率计接口(异步)

真机很可能是串口/SCPI,一次往返几百毫秒。所以是**请求 + 信号**:

```cpp
class PowerMeter : public QObject {
   Q_OBJECT
public:
   virtual QString kind() const = 0;
   virtual bool    open(QString *err) = 0;
   virtual void    close()            = 0;
   virtual void    requestReading()   = 0;   // 非阻塞; 恰好回一次 ready 或 failed
   bool isOpen() const;                      // Preflight 要问这一句
signals:
   void readingReady (double watts);
   void readingFailed(const QString &err);
};
```

四个实现(三个模拟 + 一个真机):

| 实现 | 用途 |
|---|---|
| `ManualMeter` | 界面上现填一个数,每次采回来都是它。用来手对流程 |
| `RandomMeter` | 基值 + 噪声,可调延迟。用来压热力图的配色与刷新 |
| `ScriptMeter` | 读一个每行一个数的文本文件,**每次请求取下一行**。可以配延迟 |
| `OphirMeter` | **真机**: PD300R 探头 → Juno+ 表头 → PC,走 `OphirLMMeasurement` COM |

`ScriptMeter` 是没有功率计时最有用的一个:**它能让整条流水线(状态机 → CSV → 热力图 →
断点续扫)完整跑一遍,而且数据是可预测、可断言的**。

三个模拟实现都用 `QTimer::singleShot(...)` 把 `emit` **挪出调用栈**
(`ManualMeter` 是 `0`,另两个是那个可调的 `delay_ms`,默认 20ms)。
如果 `requestReading()` 直接 emit,状态机的 `readingReady` 槽会在
`requestReading()` 内部**嵌套执行** —— 状态机正在 Reading 里发请求,槽又把它推到下一步,
于是所有"进入某状态后紧接着做的事"都会踩到自己。延时投递之后,模拟源与真机
(串口回来了才 emit)的行为**完全一致**,状态机只需要考虑一种时序。

**一个例外**:没打开 (`!m_open`) 时三个模拟实现都是**同步** emit
`readingFailed` 然后 return。也就是说"`emit` 一定在调用栈之外"这句话**只在打开之后成立**。
扫描里走不到这一支 (Preflight 已经要求 `isOpen()`),「读一次」那个按钮也挡了没打开的情形,
但任何新的调用方都不能假设"发完请求就已经把状态摆好了才轮到回话" —— 见 §17.3。

**不做工厂 / 注册表 / 配置文件**:一个基类 + 四个子类 + 界面上一个下拉框的 `switch`。
也不支持并发请求 —— 一个时刻只允许一个未决请求,状态机才能有确定的 Reading。

### 7.1 真机那一路(`OphirMeter`,PD300R + Juno+)

硬件链路是 **PD300R (光电二极管探头) → Juno+ (USB 表头) → PC**,软件走 Ophir 官方的
`OphirLMMeasurement` COM 对象。四件事把它和其它三个实现区分开:

1. **它有自己的线程。** 那个 COM 服务是 Apartment 线程模型 (手册 "Threading issues"):
   一个对象只能在**创建它的线程**里用。而界面线程不能去做 USB 往返。两条加起来只剩一条路
   —— 所有 COM 调用集中在专属线程里,界面靠原子标志 (请求读数) 和信号 (结果) 跟它说话,
   **一次直接调用都没有**。
2. **`open()` 会阻塞**(有上限,超时就把线程收掉并报错)。接口就是这么定的
   (`bool open(QString *err)`),真机却做不到"设一下就好":枚举 USB、开设备、读探头、配置、
   开流要几百毫秒到一两秒。
3. **读数的语义**:设备一直在推数,而状态机是"到位了给我一个数"。所以每次返回**缓冲区里
   最新的那个**,并且按设备时间戳记水位线 —— **同一个采样不返回两次**(否则
   `samples_per_point > 1` 求的平均就是个假数)。`status != 0` 的项**不能当测量值**
   (手册:"The status code must always be checked"),过量程就明确报错。
4. **信息由设备给,不按型号推断。** 表头型号/序列号、探头型号/序列号,以及波长/量程/模式
   **三个下拉框的选项表**,全部原样来自设备 —— 手册明确说了不要按型号推断规格。换探头就是
   换一张选项表。

打开时界面会把这四样摆出来 ("功率计已接上: ...")。

**踩过的一个坑**:这台机器注册表里那个 typelib 的版本号是字面量 `a.a`,于是
`IDispatch::GetIDsOfNames` / `GetTypeInfo` / `Invoke` 全返回 `0x8002801D`。所以
`ophircom` **绕开注册表**,直接从 dll 资源里 `LoadTypeLibEx` 再走 `ITypeInfo::Invoke`。
自检里那条 "GetVersion 拿得到数" 证明的不是"设备在",而是**这套绕法成立、名字解析和派发都通**。

## 8. CSV:它本身就是进度文件

**不另存 sidecar 状态文件** —— 边采边写的 CSV 里已经有全部信息。

```csv
# scan v1
# area_x_unit=27.000000 area_y_unit=27.000000 res_unit=0.500000 pulses_per_unit=50000.000000
# speed_pul_s=20000 dwell_ms=200 settle_ms=100 samples=1 serp=1 start_pos=1
# range_pul=725000 pos_tol_pul=1250 zero_epoch=1
# started=2026-09-17T10:00:00
index,ix,iy,x_unit,y_unit,x_pul,y_pul,watts,ok,flags,pos_x_pul,pos_y_pul,spread_x_pul,spread_y_pul,unix_ms,elapsed_ms
0,0,0,-13.5,-13.5,-675000,-675000,0.001234,1,,−675000,−675000,60,45,1758096000123,412
```

- **每采一点追加一行 + `flush`** → 中途崩了/断电了,已采的数据一行不丢
- 列名一律 ASCII、数值用 C locale 格式化(`%f`/`%lld` 本来就是)—— 中文列名在中文
  Windows 上会被 Excel 按 GBK 打开成乱码,而某些区域设置会把小数点变成逗号、
  把整列解析搞崩
- `watts` 用 `%.9g`,**采不到时留空而不是写 0** —— 0 是一个合法的读数,
  拿它当"没采到"的哨兵,以后就没法区分"这儿真的没有功率"和"这儿没读上"了
- **`ok` 与 `flags` 是一对**:`ok=0` 时 `flags` 写原因(如 `timeout`),`ok=1` 时留空。
  单点重测写 `flags=retest` —— 重测**不是一个单独的列**,而是与失败原因共用这一列
  (两者可以同时成立,那时用 `|` 连起来,如 `timeout|retest`)。热力图与统计一律取
  **该格最后一行**
- `pos_*_pul` 是**采样那一刻的实测位置**,和网格点的理论值放一起就能看出这一点的
  定位误差;`spread_*_pul` 是稳定窗口内 `pos` 的极差

### 断点续扫

打开一个已有 CSV → 读表头**校验几何参数一致**(区域 X/Y、分辨率、每单位脉冲数;
不一致就拒绝并**指出哪个变了**)→ 读所有 `(ix,iy)` → 剩下没采的补扫 →
**继续往同一个文件追加**。

速度/停留/采样次数这些**不影响几何**的随便改,不该拦。

### 零点世代(`zero_epoch`)

每次「连接」或每次「设为区域中心」,**零点世代 +1**,写进 CSV 表头。

连接时 `tryInitOrigin()` 会把零点重设为"当时所在的位置"。
所以断线重连之后,**同一个显示坐标指的可能已经是另一个物理位置**。

续扫时世代对不上**不是错误**:界面**不弹确认框**,直接按"允许世代
不同"接上去,并把那句差异留在**红色横幅**上(接错了「中止」随时可按,已经采到的点都在
CSV 里)。

### 单点重测

在画布上 **左键**选中一格 → 点「重测选中点」→ 走回那一点再采一次,
**追加一行**(带 `flags=retest`),不改动别的格子。热力图与统计取**该格最后一行**。

> **`ScanLog::beginAppend()` 会先把没写完的那半行切掉。** 追加写是掉电留下的残行是
> **正常情况**;而 `QIODevice::Append` 会把下一行**粘在那半行后面**,
> 于是产生一行字段错位的垃圾,并且**它之后的所有行都跟着错位**。
> 切回最后一个 `'\n'` 是唯一不丢东西的做法 —— 那半行按定义就是没写完的。

> **跑完之后日志不关。** 中止也一样不关。

## 9. 二维面板与配色

`MapCanvas` 是 hmi 那两条一维轨道的二维版本,语义照搬:
**实心点 = `6064h` 实测位置,橙色 = `want`(Shift+点击给的),绿色虚线 = `tgt`(本周期下发的)**。
多出来的一层是热力图 —— 以及**棋盘上那两种左键**:见下面的「两个左键」。

- **可视量程固定 30×30 单位**(每边 ±15 再各留 1 单位余量,`MapCanvas::kViewHalfUnits = 16`),
  **不跟着区域缩放**;网格 + 每 5 单位一条淡线 + 零点十字
- **坐标标尺**:下边 X、左边 Y,每 1 单位一个小刻度、每 5 单位一个带数字的,
  位置与网格线**同一组**(都走 `pxOf(u)`,u 为 5 的倍数);零点用亮色,别的用灰。
  单位写在两根标尺交会的那只角上
- **区域框**:超出量程时**标红并写明"边缘会被静默夹掉"**
- **扫描路径预览**:开始前画出将要走的蛇形折线
- **当前点高亮** + 剩余点数 / 预计剩余 / 悬停读数(单位 + 脉冲)
- **左键 = 查看那一格**(选中 + 读出数值 / 索引 / 坐标);**Shift + 左键 = 手动定位**;
  手动定位在扫描进行中一律吞掉,查看随便点
- **撞硬件限位时**,实测位置那个点外面套一圈红环 + 写下是哪根轴(见下)

### 视野固定为 30×30

视野固定成 ±16 单位之后:

- 1 单位恒等于固定的一格,热力图可以直接叠着比;
- 区域框成了**图里的一个量** —— 默认 27×27 时每边还剩 2.5 单位余量;
- 每 5 单位一条的网格线落在 ±5/±10/±15 上,正好与 30×30 的边界对齐。

窗口变大变小,变的是这块方形的**像素边长**,不是它的量程。正方形画布**居中**,
区域尺寸写在左上角第三行。

> **画布上的东西一律"按单位存,画的时候才换成像素"。** 热力图、蛇形轨迹、滑台位置
> 都是这么画的,所以窗口一拉伸是**整张图一起缩放**。
>
> 蛇形轨迹把 `pxOf()` 的结果(像素)缓存进 `m_path` 时,缓存只在"网格数/点数变了"时失效 ——
> 窗口缩放这两样都没变,于是热力图跟着长了,折线却停在旧的像素位置上。
> 现在 `m_path` 存的是**单位**,像素由 `drawPath()` 用 `QTransform` 现算。
>
> 那个变换里 `QPen::setCosmetic(true)` **不能省**:世界变换会把线宽一起放大 k 倍
> (k ≈ 20),不写的话那条 1px 的预览线会变成一条 20px 的灰带,把整张热力图盖掉。

> **手动定位被夹在"当前生效量程"之内。** 视野固定之后,画布上会有一圈既在扫描区
> 外面、也超出量程的地方;不夹的话在那儿点一下就是一次走到量程尽头的长动作,而界面上
> 完全看不出"我要的是 16 单位、实际只走到 14.5"。夹掉之后橙色三角停在量程边上。

### 两个左键:查看给左键,动滑台给 Shift + 左键

| 动作 | 干什么 | 扫描中 |
|---|---|---|
| **左键** | 查看那一格:选中 + 显示数值 / `[ix, iy]` / 单位坐标 | **能用**(只读) |
| **Shift + 左键** | 手动定位到那一点(与 hmi 的点击同义,走显示坐标) | 吞掉,只留一行提示 |

查看是只读的,所以不受扫描那道闸限制;点在没有网格的地方(区域框外那圈余量)
**取消选中**,而不是什么都不做。

数值那一行**没采到也写出来,写"未采集"**:空着的话跟"这里根本没选中"分不清,
而这两种情况的下一步动作完全不同(一个去重测,一个去检查是不是点歪了)。

### 布局:画布随窗口长,参数栏自己滚

左画布 | 右参数栏,中间一根**可以拖的分隔条**(`QSplitter`)。窗口变宽,多出来的地方
全给画布;参数栏塞在 `QScrollArea` 里,自己上下滚 ——
六组框加起来约 1330px,而窗口通常只给它 670。

> 参数栏**不能用"固定宽度"**。里面那些输入框有自己的最小宽度,固定宽度一旦压到它
> 下面,`QScrollArea` 就把右边**裁掉** —— 横向滚动条关着的话连拖都拖不回来。
> 交给 `QSplitter` 之后宽度分配由它算。

#### 横幅**不进布局**(2026-09-20 改)

那条横幅(`m_banner`)原先跟其他控件一样 `addWidget` 进竖向布局,排在分隔条上面 ——
于是它**出现时把下面的分隔条连同右栏整体往下推一行高,消失时又弹回去**。
而这条横幅是来回闪的(连接/断开/每次提示/每条回零状态),结果是参数栏一直上下跳,
**点偏一格就点到别的按钮上**。它本来就只是"说一句话",不该占体积。

现在它是**浮在画布顶上的一层**:不进布局,`placeBanner()` 自己算位置与折行高度
(`heightForWidth(canvas 宽 - 2×6px)`,左右各留 6px 边距),`raise()` 到最上层;
窗口 `resizeEvent` 与 `QSplitter::splitterMoved` 各接一次,画布一变宽就重算。
另外挂 `Qt::WA_TransparentForMouseEvents` —— 它纯是信息,点在它身上要能穿过去
落到画布上,否则"点了画布没反应"看起来像卡了。

#### 画布顶上留一条空带给它(2026-09-21 改)

上面那版是**纯浮层**:横幅是浮起来了,但它**压住画布左上角那三行 HUD 的前两行**
(`0 / 2695 点 剩 0`、`空闲 —— 参数可改`)—— 那正是扫描中要盯的数。
现在的做法是给画布加一条**专用空带**:`MapCanvas::kBannerBand = 20`,
并进 `kPadT`(见 mapcanvas.cpp 顶上那组留白),画图区与 HUD 一起**整体下移 20px**,
顶上那一段什么都不画 —— 横幅就落在它里面(`kBannerInset` 那 6px 是横幅在带子里的边距)。

- **算式**(都是量出来的):横幅占画布内 `6..34`;画图区顶 = 那原有的 20(超量程红字那条)
  + `kBannerBand` 20 = **40**;HUD 第一行从画图区顶 +6 = **46** 起 —— 中间剩 **12px**。
  **带子的下限是 8**:再小横幅就压住第一行了。横幅那 6 与 28 在别处
  (scanwindow.cpp 的 `kBannerInset` 与那三条样式表),改那边要连这个一起改。
- **代价**:画图区小 20px(高度受限时正方形跟着缩;宽度受限的窗口只是顶上多留白)。
  这是"用一点画布换 HUD 不被压住"。**空带里那条分界线是看不见的** ——
  画布底色与空带是同一块,看上去就是"图往下挪了一点"。
- **横幅换成一句更长的话会折成两行**(高 56,占到画布内 `62`),那就超出这条带子、
  重新压住第一行。带子按**一行**定:多数提示是一行,按两行定要白扔 40px。
- 另外**它是画布自己的留白,不是窗口再摆一个控件** —— 摆在画布外面也一样要占体积,
  而且横幅得改成按窗口坐标定位,反而把"横幅属于画布顶上"这件事拆散了。

**验证**(1360×860 的窗口,离屏跑真正的 `ScanWindow`,横幅由构造时那句
「未连接…」带出来、8 秒后由 `m_bannerTimer` 自己收掉):

| | 画布 | 参数栏(那个 `QScrollArea`) | 横幅 |
|---|---|---|---|
| 横幅在 | `9,40` **938×785** | `951,40` **400×785** | `15,46` 926×28,visible=1 |
| 横幅没了 | `9,40` **938×785** | `951,40` **400×785** | visible=0 |

两组**逐字段相等** —— 横幅的出现与消失对画布和参数栏**一点几何都没动**。
横幅自己:顶边离画布顶 6px、宽 926 = 画布宽 938 − 12、高 28(一行)。
抓图核过:三行 HUD 全在(`0 / 2695 点 剩 0` 在画布内 y≈53),顶上就是一条空带。

### 限位相关的显示:**四个地方、两个问题**

| 问题 | 谁回答 | 在哪儿看 |
|---|---|---|
| **扫描会不会中止** | `6041h` bit11 | 状态栏那对灯 + 画布红环 + 横幅 |
| **开关本身压着没有** | `60FDh` bit2/1/0 | 参数栏「轴信号」那三个灯 (每根轴一行, 见下) |

两者**可能不一致**(开关压着而驱动器没置 bit11,或者反过来),**不一致时以 bit11 为准**。

| 位置 | 内容 |
|---|---|
| 状态栏(常显,两根轴各一个) | **信号灯 + 文字**:`○ 限位X 正常` / `● 限位X 有效!`(红底) / 不知道时灰灯 + `限位X --` |
| 参数栏「轴信号」(见下) | 每根轴一行**五个灯**:使能 / 故障 / 原点 / 正限位 / 负限位 |
| 画布 | 实测位置点外面一圈红环 + `X 轴撞限位` |
| 横幅 | 上升沿弹一次(不自动消失) |

#### 信号灯:一条规矩,四种样子

**灯亮 = 这个名字代表的事正在发生**;灭 = 没发生;灰 = 不知道。

| 样子 | 画法 | 什么时候 |
|---|---|---|
| 灰 | `#4a5058` | **不知道** —— 没连接 / 轴上没遥测 / 丢过帧 / `60FDh` 不在映射里 |
| 灭 | `#20242b` 空心 | 这件事**没发生** |
| 绿亮 | `#33d17a` | 使能:带电 / 原点开关:正压着 |
| 红亮 | `#ff4d4d` | 出事了:故障 / 撞限位 / 正负限位开关压着 |

正常运行时只亮一盏(使能)。

- 四种样子**都画满**,不搞"只在出问题时才显示"。
- 灯和字**装在一个小容器里**(`lampUnit`),免得布局把它们排散。**现在只有状态栏那两盏还
  带字**(`○ 限位X 正常`);参数栏「轴信号」那块表**每格只有灯,没有字**(2026-09-21)。
- 状态栏那一格是**灯、字、字色一起变**的(`refreshAxisSignals` 最后一节),少写一样就会
  出现"绿灯配红字"。参数栏那边没有字可配,`setSignalCell` 只管一盏灯,所以它只记
  `LampGrid::lampLast` 一样东西。

### 参数栏最上面那块:「轴信号」(五个灯 + 故障复位)

```
        使能   故障   原点   正限位  负限位
 轴X     ●      ○      ●      ○      ○    [        ]
 轴Y     ○      ●      ○      ○      ○    [故障复位]
```

**每格只有一盏灯**(2026-09-21,用户要求"灯旁边不要有当前状态的文字说明"): 状态全由亮暗
说 —— 绿亮 / 红亮 / 灭 / 灰四种样子,含义见上面那张表。原先每盏灯旁还有一行字
(`● 已使能` / `○ 无故障` …),那是同一件事说两遍,而且五列并排时那行字占的宽度把灯挤小、
整块表看着像一张表而不是五个信号。**去掉字之后,一列的信息量全压在灯和 tooltip 上**,
所以每一格的 tooltip kTip 里都要自己说清"这一列亮/灭各是什么意思"(表头只有个名字,
而"亮"在五列里不是同一件事),再拼上那句 kLampRule。灰 = 不知道这件事也因此**只剩灯这一种
表达**,灯本身必须一眼能分出"灭"和"灰"。

**原先分成「轴信号」与「限位开关」两块,2026-09-20 合成一块: 一行一根轴, 复位在两行最右侧**
(用户要求)。合成时权衡的是这两件事:

- **宽度**。五列"灯 + 字"加复位那格**实测 ≈413px**(原先那块四列的是 ≈280px;
  参数栏当时按上一块的 394px 定宽)。参数栏的最小宽度因此从 ≈394 涨到 ≈413 ——
  画布少 20px, 默认 1360 宽的窗口下不影响用。这是这个版面唯一的代价。
  当年"4 个信号列是上限"那个估算(≈59px/列)偏保守, 实测每列 ≈50px。
  **2026-09-21 去掉每格那行字之后,这块表窄了一大截**: 列宽改由表头那两个汉字定
  (≈36px/列),五列加复位按钮那格远不到 413px 了。**参数栏的最小宽度没有重新实测** ——
  它取的是 `side`(340,写死)与各块框里最宽那个的较大值, 现在这一块已经不是最宽的了
  (输入框那几行才是), 所以这次改动不该让参数栏变窄或变宽。
- **语义**。它们回答的是上面那张表里**两个不同的问题**, 并排放在一行里就会看起来像
  同一个问题的两个答案 —— 而它们可以不一致。这一点靠两处保留: 表头上前两个名字(6041h)
  与后三个名字(60FDh)是分开的, 每一格的 tooltip 里写着自己问的是哪一个字、哪一位;
  判据在 `refreshAxisSignals()` 里也照旧**分两次算**, 两组连 `known` 的条件都不同。
  **合成的是版面, 不是数据。**

**「故障复位」跨两根轴, 在两行最右边那一格** —— 它是"两行各一个、按轴复位"的反面:
命令(`postFaultReset`)是全总线的, 只对 `6041h` bit3 置起的那几根动手, 所以按钮不带轴参数。

| 信号 | 位 | 亮起来的意思 |
|---|---|---|
| 使能 | `6041h` bit2 | 电机带电 —— **这个轴现在能不能走** |
| 故障 | `6041h` bit3 | 驱动器报故障(扫描中会自动中止) |
| 原点 | `60FDh` bit2 | 原点开关正压着(绿亮,**不会中止扫描**) |
| 正限位 | `60FDh` bit1 | 正限位开关正压着(红亮) |
| 负限位 | `60FDh` bit0 | 负限位开关正压着(红亮) |

- 信号名写在**表头**上,不是每格重复一遍;**每格只有一盏灯,连状态的字也没有**
  (2026-09-21 之前每格是 `lampUnit(灯, 字)`, "已使能/未使能"那样)。想知道某盏灯
  亮/灭/灰各指什么,鼠标停在灯上 —— kTip + kLampRule 拼出来的那句。
- 这一块排在参数栏**最上面**(它是最容易被滚动区裁掉的那一批)。
- **判据跟状态机完全一致**(`ScanController` 自动中止那一段用的就是 `!valid || !mirror_ok`)。
  判得比状态机宽的话会出现最坏的那种不一致:**灯说"正常",而程序已经因为"丢了过程数据帧"
  中止了** —— 而且此时 `sw` 是陈值。
- 限位在参数栏和状态栏**两处**都有,两处都由 `refreshAxisSignals()` 一次算出。
  **撞限位的判定本身只有一处**:`ecatcmd::limit_hit()`(定义在 `hmi/ecatworker.h`),
  在 `EcatThread::publish()` 里算一次,发成 `AxisTelem::limit_active`,界面只读不算。
- 只在**真变了**才动控件(`LampGrid::lampLast`, 2026-09-21 之前还有 `textLast`),
  30Hz 每帧给一堆控件重设样式表会把重绘刷爆(横幅那个上升沿判断是同一个理由)。

红色**不复用采失败那一格的 `C_FAIL`** —— 那个红的意思是"这一格没采到数"(数据问题),
这个是机械压在开关上(要立刻去处理)。
`bit11` 只说"有轴压着",不说方向;方向要看 `2310h`~`2312h`
(实测 **X0 = 原点 / X1 = 正限位 / X2 = 负限位**)。

#### 原点用绿灯

- 压到原点是**回零时的正常动作** —— 它是位置信息,不是故障。
- 原点用绿(亮 = 「原点开关正被压着」正在发生),不改画法。
- **代价**:三个格子用同一组词(压住 / 松开),于是**颜色是唯一说"这个会撞"的东西** ——
  所以原点的 tooltip 会说出来:「绿亮 = 正压着,这是位置信息不是故障 ——
  扫描经过原点开关不会中止」。

#### 原点那一位进不了判据

`ecatcmd::limit_hit(sw, dig_known, dig_pos, dig_neg)` 的参数里**根本没有原点那一位**。
`scan_selftest` 里有一条回归护栏:只把原点位压住,扫描必须一路跑到
`Done`,`autoAborted` 一次都不能响。

### `60FDh`:读不到是常态

`60FDh` bit2/1/0 = 原点 / 正限位 / 负限位,是 `2300h` 电平反转与 `2310h`~`2312h`
功能映射**之后**的结果 —— 调用方不再取反(反过来说:`2300h` 配反了三个灯一起反相)。

**本机实测生效的 `1A00h` 只有 `6041h`/`6064h`/`606Ch`
三项 10 字节**(`docs/ykd2205pe_ci402.md`),没有 `60FDh`。这时三个灯是**灰 + `--`**,
而那**不是**"三个都没压住" —— `AxisTelem::dig_known` 是单独一个字段,就是为了让
这两件事分得开:读不到 60FDh 时那三位也是 0,而 0 在"开关压着没有"这个问题上是个
**看起来完全正常**的答案。

两条出路,优先走第一条:

1. **用厂家上位机改一次驱动器的 `1A00h`** —— 零代码,而且断电也在;
2. 勾上「高级选项」框里那个「让 60FDh 进 TxPDO」,让主站在连接时补一次:
   仅写 RAM,收尾(断开 / 关窗)时还原,崩在收尾之前那一次改写会留在驱动器里直到断电
   —— 与当年那个 CLI 的 `motor_test --allow-pdo` 同一风险等级。过程数据从 10 字节变 14 字节。
   **这一项默认开着**(`scan.ini` 的 `adv/want_dig_in`)。

它是**连接期**参数:**改了不重连不生效**。连接期间照样能改(编辑门控不按连接态变灰),
但界面上会说清"下次「连接」才生效"。
`em_setup` 会打一行 `printf` 如实报告绑上了没有。

### 色标:冷到暖的彩虹色带,OKLab 插值

冷到暖的 13 级(`#0b2a5c` → `#e42b12`):**蓝 → 青 → 绿 → 黄 → 红,值越大越红**。
取色是**在 OKLab 里插值**的,**不是 sRGB** —— sRGB 插值在中段会发灰、发脏。

> **这是从"单色相顺序色标"换过来的,当时那条判据不再成立,是有意换的。**
> 原来那版是蓝色的 13 级(`#0d366b` → `#cde2fb`),过的是"明度严格单调、色相跨度 4°"
> 那一关。彩虹色带**明度不单调** —— 黄色最亮,红色反而比黄色暗。
> 换来的是"冷热一眼可读",代价由数字兜住(见下)。

最冷那一端(近零)压得很暗,于是它跟底色对比度低(**1.3:1**,原来那版是 1.5:1),
**必须有数字兜底** —— 右侧色标条上写着锁定的最小/最大值,鼠标移到格子上也出数。
**热力图永远不能只有颜色。**

色标条**跟画图区一样高**(上下各让 8px 给两端的数字):图多高条子就多长,一眼能跟格子对上。
原来封在 240px,窗口一拉大条子就比图矮一截,看着像另外半张图的东西。

> **色阶是锁定的,不跟着数据实时变。** 边采边自动缩放的话,
> 每来一个点整张图的颜色都会重排一遍。所以是两个数字(默认 0..1)加一个「按数据定标」
> 按钮,要改是**显式**改一次。超出范围的格子夹到两端,数值仍可在悬停里读到。

**「自动跟随数据」那个勾是上面这条规则的一个出口**(2026-09-21 加)。勾上之后色阶 =
**已采数据的最小/最大**,由 `MapCanvas::applyAutoFit()` 在 `paintEvent` 里每帧跟一次,
两个输入框变成只读的读数(值由程序写,打字进去下一拍就被覆盖),「按数据定标」跟着变灰 ——
它做的事每帧都在做了。

- 数据没有任何一个点时**保持现有色阶不动**(`wattsRange()` 返回 false),不除零;
- 只有一个点(或所有点都一样)时按 ±5% 加宽成一个窗口,免得整片一个颜色;
- 值没变时**不调 `setShadeRange()`** —— 那里面是 `update()`,而 `applyAutoFit` 是在
  `paintEvent` 里调的,每帧调一次就成了画布自己给自己排重画,一直空转;
- 它是**模式**,所以记进 `scan.ini`(`shade/auto_fit`,缺省**关**)—— 两个上下限是数值,
  仍然不记(见 §16.1)。勾一次就记住了,不必每次开程序重来;
- **代价就是上面那段警告**:新采到一个更极端的值,整张图重排一次颜色,"变化"里有一部分是
  色阶自己在动。所以要拿两张图对比时把它关掉 —— 关掉那一刻色阶就定在当场那个范围上。

**「最小」「最大」是一对,任何时候都得 `0 <= 最小 < 最大`**(色阶是拿这两个数做线性映射的,
反着的区间除零 —— `shadeOf()` 里有一条兜底走中间色,但那只是不崩,画出来是错的)。两条规矩
各有一处落点,而且**必须一致**:手动填的走控件自己的 `setRange(0, …)`(敲 -5 会被夹成 0),
按数据定标 / 自动跟随走 `MapCanvas::dataShadeRange()` 里的同一个 0 下限 —— 只管一头的话,
自动跟随开着时框里显示 0、画图用的是负数,界面上那个量程就是假的。

顶头了怎么办:**推着走**。改一个越过另一个,就把另一个一起推过去,**跨度不变**
(`onShadeLoChanged` / `onShadeHiChanged`,跨度的来源是画布上还没被覆盖的那一对值):

- 最小 0 / 最大 1,把最小改成 5 → 最大自己抬到 6(想把整段量程往上挪时最顺手);
- 上限往下压也一样,但**下限顶到 0 就到底**:再压下去只能掉头把上限抬回来,色阶可以很窄,
  不能反过来;
- 推的那一下**屏蔽信号**:不屏蔽的话被推的框会再发一次 `valueChanged`,它拿到的是半新半旧的
  一对值,中间会闪一次错的量程。

> 另一条路是"夹住改的那一头"(不让最小超过最大)。没选它:想把量程整体挪一格得先改另一个,
> 绕一圈,而且敲进去的数会被静默改掉,看着像吞键。推着走至少**改动都看得见**,还配一条横幅
> ("最小顶到最大上了 —— 最大跟着抬到 6 (跨度不变)")。
>
> 这两条规矩**没有自测覆盖**:`scan_selftest` 只链 `Qt6::Core`,这套逻辑在 `ScanWindow`
> 里(要 Widgets 与整扇窗口)。能测的只有"自动跟随这个模式记得住"那一条(§16.1)。

色标条本身(2026-09-21 一并改的): **高度封顶 320px**(原来 240,窗口拉大时它比图矮一截;
改成跟画图区等高又太长),**两端 + 中间整数刻度都写数字**。中间那几个刻度按 1/2/5×10^k
挑步长(`niceStep`,目标 5 段,于是 0..1 出 0.2/0.4/0.6/0.8 四个),写淡一档、带一个小刻度线;
两端是锁定色阶那两个数,写亮一档。挑不出整数刻度(量程特别偏/特别窄)就退回标中点,
条子矮于 140px 也不补 —— 数字会挤成一团。

**三种状态在画面上分得清清楚楚**:

| 状态 | 画法 |
|---|---|
| 还没扫到 | 只有底色的空位 |
| 扫到了、读数失败 | **紫红实心块**(`#c026d3`,常量 `C_NODATA`)—— 那才是要人去处理的一格 |
| 扫到了、有数 | 冷到暖的顺序色标 |

> **失败格为什么是紫红,不是红:** 色标最高档就是红的,失败格再来一块纯红就分不出
> "这一格没采到数"和"这一格功率最大"了。紫红在整个色带之外,一眼能分。
> 注意别跟 `C_FAIL` 混了 —— 那个红还在用,管的是**超量程的框**和框上那行红字。

> **实测位置那个点刻意是白的,不是 hmi 的蓝色。** 因为这块画布上蓝色已经是**数据**了
> (彩虹色带的冷端就是蓝)。白色在所有色阶上都最跳。
> hmi 那边画布上没有数据,所以它用蓝色。

### 刷新与缓存

热力图是一张 `nx×ny` 的 `QImage`(**一格一像素**),放大时用最近邻
(`SmoothPixmapTransform = false`)。3025 个像素比一次 `QPainter` 填充还便宜,
所以每帧重建;只有扫描路径是跟几何走的,才做几何变动的缓存 —— 而它缓存的是**单位**,
所以"窗口缩放了"这种几何变化不需要把缓存作废(见 §9)。

## 10. 安全护栏

| 场景 | 行为 |
|---|---|
| 程序启动 | **一个字节都不写总线**(只会 `postRange` 一个本地成员) |
| 「连接」 | `em_open` → `em_setup(...,1)` → `em_enter_op`。进 OP 开始发帧但**不发使能**;**不弹确认框** —— 它写什么由按钮 tooltip 一直说着 |
| 「使能」 | **让电机带电的两个按钮之一**(另一个是「回零」)。**不弹确认框、没有持久勾选、不自动使能**;"现在带不带电"由这颗按钮自己说:**已经使能时它是灰的、写着「已使能」**(判据是**每一根轴都已使能**;还有一根没使能就仍可按,按下去使能剩下的那些) |
| 「故障复位」 | **不弹确认框**(按下去就发)。**只对 6041h bit3 置起的轴写字节** —— 一根都没报故障时**一个字节都不写**,而这句话用横幅说出来("看起来没有轴报故障…这一下大概率一个字节都不会写");扫描进行中直接拒绝(先「中止」);复位成功后该轴停在**未使能**,要接着走请重新点「使能」;每轴最多 1 秒,期间**不可中断**、按钮显示"正在复位…" |
| 「X/Y 正/反向回零」及「X/Y 找正/负限位」 | 驱动器自带 HM 模式(**回零 = 方式 24 / 29**; **找限位 = 方式 18 / 17**, 手册 V2.4 p46~p48 叫"以限位为原点")。**不弹确认框**:事前的说明都在按钮 tooltip 上(**「驱动器会自己带电并移动,软件拦不住它撞开关」**、**该轴会先失能(竖直轴此时失去保持力矩)**、方向只说电机轴正反、方向不对就换按钮),框里**只有速度值与八个按钮**(八个按钮**共用同一个速度**;由它派生的找段 / 返回段速度、加减速、**最多走几圈**、几秒判超时只在**控制台**的回零收尾句里),出路是「停止」= 立即中止。**发起之前先过一道闸**(没连上 / 位置未知 / 丢帧 / bit3 故障 / 还有轴在走 → 拒绝且**一个字节都不写**);找限位在这道闸之后**再过第二道**(60FDh 读不到 / 正负限位同时有效 → 拒绝且**一个字节都不写**,并预告这一趟走 a) 还是 b) 分支);只对**被点的那一根**判据,不看另一根、**也不看它使能没使能**;回零期间「使能 / 失能 / 停止点 / 设为区域中心 / 开始扫描」全部锁住(「停止」除外,那时它兼任中止);回零结束后**自动切回 CSP 并保持使能**,并**从 `6064h` 重新锚定显示零点** |
| 找限位期间碰到限位 | **不弹红色「撞限位」横幅**(找限位就是要去撞它,那是这一趟的目的);但**限位灯与状态栏那格照常变红**、stdout 那行证据照打 —— 它们说的是"信号此刻有效",是事实。找完之后压着限位再启扫,那条红横幅与自动中止**照常发生** |
| 「停止」**在回零进行中** | **立即中止**(≤2ms 被 `em_home()` 的轮询看见),**并且保持使能** —— 中途位置不明,卸力会让竖直轴自由下滑。走的是 GUI 直呼 `em_request_stop()`(见 §2 那条例外),**不是**命令队列 |
| 「开始扫描」 | 过 Preflight;**不弹确认框** —— 这一趟的范围在按之前就全在眼前(参数栏里填的数 + 扫描栏那两行**网格 / 点数 / ±范围 / 预计全程** + 参数不合法时的红字)。按下去之后横幅把**出发的那一份**(区域 / 点数 / 预计时长 / 取样源 / 写到哪) 念一遍,并**不自动消失** |
| 暂停 / 中止 | 目标冻在当前位置,**保持保持力矩**(故意不写 `6040h=0x0000`) |
| 扫描中 WKC 掉 / bit3 故障 / bit11 撞限位 / 掉出 OP | **自动中止** + 红色横幅 + 模态 |
| 扫描中改参数 / 换取样源 | 控件**全部锁住**。几何改到一半的扫描没有意义 —— 落进 CSV 的 `(ix,iy)` 和实际位置就对不上了 |
| 关窗 / 断开 | **先中止扫描** → 失能 → 还原 PDO 映射 → 降 `PRE_OP` → 关网卡。扫描在跑时**也不再问一句** —— 关窗就是中止,已经采到的点都在 CSV 里 |
| 收尾未能确认失能 | **模态告警**,要求立即断驱动器动力电源(CLI 退出码 10) |
| 全程不写 | `2102h`(EEPROM)、`607Dh` 软限位、`2400h/2408h/2409h/2201h` |

> **收尾顺序不能反。** `disconnectAndStop()` 是**先中止扫描再断总线** ——
> 反过来的话状态机会看到"掉出 OP",然后作为一个**异常**去自动中止,
> 一条本来正常的收尾路径会变成红色告警。

> **启动时不弹任何对话框,动作前的确认框也一律没有。**
> "会发生什么"改由三样东西在**按之前**说清: **按钮自己的文字与 tooltip**
> (「使能」在已带电时就是灰的「已使能」)、参数栏里实时算出来的那些数、
> 扫描栏那两行(网格 / 点数 / 预计全程)。
>
> **留下来的模态只有三个,而且全是"出事后"的**: 扫描自动中止、收尾未能确认失能
> (可能仍带电)、收尾超时。它们不是确认框 —— 没有"取消"可点。

> **这一条只对 `scan` 成立。** `hmi/mainwindow`(以及 CLI 的 `--allow-*`)那边
> 确认框照旧, 一条没动 —— **上表里那几行与 `hmi` 不再逐条对应**。
> 共享的东西只有 `hmi/ecatworker`+`motor_api` 那层闸
> (哪些写能发、哪根轴该复位、回零的四条拒绝), 它们**一行没改**。

> **「故障复位」自己带一道闸。**
> `em_fault_reset()` 的动作顺序是**先写 `6040h = 0x0000`(Disable voltage = 卸力)
> 打十帧,再抬 bit7** —— bit7 是上升沿触发,不先把 0 压下去就构不成沿,这个顺序本身是对的。
> 问题在于它**到函数末尾**才报告"本来就没有故障":那时候十帧卸力已经打出去了。
> 对一根**健康的保持轴**做这件事,那一轴会**真的卸力,竖直滑台会掉下来**。
> 所以判据 (`ecatcmd::axis_needs_reset`) 必须在**调用之前**,
> 一根轴都没报故障时**一个字节都不写**。
> 状态未知的轴(`mirror_ok = false`)**跳过、不猜**。
> 复位的对象由 `6041h` bit3 决定,**不由操作员点了哪个按钮决定**:所以按钮不带轴参数,
> 一次复位所有报故障的轴。

## 11. 构建

`scan` 与 `hmi` 用**同一个 preset**(`hmi-qt-ucrt64`),**不改 preset、不加第二条
configure 命令**:

```cmake
option(EC_BUILD_SCAN "构建扫描采集程序 (需要 Qt6 + C++ 编译器)" ${EC_BUILD_HMI})
if(EC_BUILD_SCAN)
  add_subdirectory(scan)
endif()
```

`${EC_BUILD_HMI}` 作默认值 ⇒ 现有的 `cmake --preset hmi-qt-ucrt64` 一次把两个都编出来;
而只想编 hmi 的人可以 `-DEC_BUILD_SCAN=OFF`。

```bash
cmake --preset hmi-qt-ucrt64
cmake --build out/build/hmi-qt-ucrt64            # 全部
cmake --build out/build/hmi-qt-ucrt64 --target scan
```

产物:`bin/scan.exe`、`bin/scan_selftest.exe`。

`scan_selftest` **不链 SOEM 也不链 Widgets**(只用到 `Qt6::Core`)——
它几秒钟就能跑完,不需要设备、不需要网卡、不需要界面:

```bash
PATH="/c/msys64/ucrt64/bin:$PATH" ./bin/scan_selftest.exe
# ... 597 passed, 0 failed, 0 skipped
```

不带参数(它只把 `argv` 交给 `QCoreApplication`),退出码 = 有没有失败(0/1)。
组名与断言说明是中文,按 UTF-8 打在控制台上 —— 看到乱码先怀疑代码页与字体,
那是终端的事,不是它输出错了。

> **`scan_selftest` 被钉在 `-O1`。**
> 本目标在 `-O2`/`-O3` 下链接必然失败 —— `collect2: ld returned 5 exit status`
> (也见过 1/9/116),`ld` 自己的报错一个字都没有,输出文件被建出来但内容是**一片零**。

#### 实测:六条里答掉了四条,成因是**极性配反**

现场症状:扫描一按就开不了,拒绝的话说"轴0 的 6041h bit11 已经置起"。
`scan_out/scan_20260918_131031.csv` 只有表头、零行数据 —— 说明卡在**前置门禁**,
不是扫描中途掉下来的。**当时**一次只读运行(`motor_test.exe` 不带参数 +
`slide_motion.exe --dump-baseline`)读到的现场值如下 —— 这两个程序 2026-09-21 已删,
**下面这张表是当时测的,保留作为记录**:

| 对象 | 实测 | 结论 |
|---|---|---|
| `6041h` | `0x0A31` | Ready to switch on(电机**没使能**),**bit11 = 1** |
| `2310h`/`2311h`/`2312h` | `1` / `2` / `3` | **正是原点/正限/负限,映射没问题** |
| `2300h` | **`0`** | 输入有效电平逻辑 = **常开**(有效 = 高电平) |
| `607Dh:01` / `:02` | `-2000000000` / `2000000000` | 软限位大开,**不是它** |
| `6064h` | `61148` | 在行程内 |
| `1A00h` 生效映射 | 含 `60FDh:00 32 bit @ +10.0 字节` | **`60FDh` 在映射里**,`dig_known` 会是 true |

对应的条目:**1 答"在"**;**4 答"仍是 1/2/3"**(映射排除);**7 答"不是 0/0"**
(软限位排除);**5 答"配反了"**。

第 5 条为什么是成因:现场接线是 **NPN 传感器(高电平 = 未触发)**,而 `2300h = 0`
(常开)的含义是"**高电平算触发**"。两者正好反着 —— 空载时 X1/X2 停在高电平上,
驱动器把"没触发"读成"触发",于是 `60FDh` 的 bit1/bit2 **同时**置起、bit11 恒为 1。
"正负限位同时压着"这个物理上不可能的组合,就是极性配反的指纹(手册 V2.4 p84 那句
"这三位是 `2300h` 反转之后的结果"反过来读)。

电机当时还在 Ready to switch on、`bit3` 故障位也没置 ——
它不是"运动撞上去的",而是从静止就恒定的。

**修法有两条,层次不同:**

1. **改驱动器的 `2300h`**:bit0~bit2 置 1(常闭)→ `0x0007`。`2300h` 是 U16 RW
   (手册 V2.4 p84),高几位原样保留;**手册没写它会不会被驱动器自己落 EEPROM**。
   这一条修的是**根**:驱动器自己的限位保护、`60FDh`、`6041h` bit11、上位机一次全对,
   而且 bit11 那道闸**保持有效**。
   **这是程序现在的默认动作**:「高级选项」里的「写驱动器 2300h = 0x0007」默认勾着,
   连接时逐轴读原值 → 写 bit0~bit2 → 回读确认,收尾写回原值(`em_di_set_logic`
   / `em_shutdown`),**从不写 `2102h`**。任一根读不到原值就整体拒绝,一个字节都不写。
2. **「上位机侧取反」**(见下):只治软件这一侧。
   **`60FDh` 与 bit11 都是驱动器给的,勾这个框不会让驱动器改变主意** ——
   它自己的限位保护仍按那套错的极性算。能改 `2300h` 就该去改它。

**两条同时上 = 双反相,不是"等于没反",是更坏**:判据 `LIMIT_RULE_INVERT` 看的是
反相后的两个限位开关,双反之后它们空载时都是 1 → 判据**恒成立** → 扫描永远开不了
(只多报,不漏报)。界面上这两个勾一起出现时有一行红字(`editgate::doubleInvertWarning`)。

#### 「上位机侧取反」—— 它必须连判据一起换

给 `2300h` 改不动(或不想动驱动器)的场合留的一条路。实现在
[hmi/ecatworker.h](../hmi/ecatworker.h) 的 `ecatcmd::LimitRule`:

| 判据 | 何时生效 | 式子 |
|---|---|---|
| `LIMIT_RULE_BIT11` | 默认 | `bit11` |
| `LIMIT_RULE_REFINED` | `kRefineLimitWithDigIn` 打开 | `bit11 && (正/负限位压着)`,未知退回 `bit11` |
| `LIMIT_RULE_INVERT` | **取反开着** | `正/负限位压着`,未知**一律中止** |

- **取反生效时 bit11 完全不参与。** 这台机器上它恒为 1 —— 它不是判据了,是个常数。
  写成独立的第三条而不是复用 `bit11 && (...)` 的形式:bit11 恒 1 时两者等价,
  而哪天 `2300h` 被改对、取反忘了关,bit11 一变 0 就会把
  `bit11 && ...` **整条恒置为 false**,保护静悄悄地全没。
- **取反必须连带换判据,不能做成两个独立开关。** "取反开着而判定仍只看 bit11"
  在这台机器上就是"永远开不了扫描"。绑在一起之后,"取反"这一个动作的语义才是完整的:
  **把限位判定从"驱动器的意见"换成"开关的真实状态"**。
- **读不到 `60FDh` 时一律中止。** 三条判据里只有这一条把"未知"判成中止,因为此时
  **退无可退**(bit11 不用了,开关又读不到)。它不会在扫描中误触发:`dig_known` 里的
  `mirror_ok` 是**闩锁**的(`em_dig_in_known` = `off_dig_in >= 0 && mirror_ok`,
  而 `mirror_ok` 只在轴初始化时清零)—— 所以这一支只可能在连接之后、第一帧完整过程
  数据到达**之前**命中。

**默认关,进了 ini**(`adv/npn_sw_invert`,见 `scan/scanprefs.h`):取反是"这台机器的
X0~X3 就是这么接的"的一条**断言**,而断言错了的后果不是"灯显示不对",是**保护反过来**
(真压着限位时它说没压着)。默认关是因为「写驱动器 `2300h`」那条正路默认开着 ——
两条一起开就是上面那个双反相。真要单独靠它,得由人在「高级选项」里点「编辑」勾上、
再点「保存」;这是**运行期**参数,勾一下下一帧就生效。

文案也跟着分了两套(`limit_switch_text` / `limit_hit_advice` / `limit_hit_headline`
都多了一个 `di_invert`):同一个"正负限位同时压着",**取反关着**是极性配反(去查
`2300h`),**取反开着**就只能是两路输入真的都被读成低电平(去查供电与接线)。

回归护栏在 `scan/selftest.cpp` 的 `limitsw` 那一组,末尾那条端到端的是重中之重:
**现场原样搬进去(bit11 置起 + 两个限位都报压着),取反关着必须拦得住、开着必须放得行。**

#### 回零(HM):只有真机才能验的六件事

**回零是软件唯一兜不住的动作** —— 发起之后朝哪走、什么时候停、撞不撞开关,全由驱动器按
`6098h` 与它自己读到的原点信号决定。所以下面这些**必须在设备旁、手放在物理急停上**做,
而在这之前**一个字节都不能写**:

0. **先修极性,而且只能修 `2300h`。**
   上面那条实测已经定了:这台机器是 NPN 传感器 + `2300h = 0`,极性配反,
   `60FDh` 的 bit1/bit2 空载就都置起。**而回零用的是驱动器自己读到的开关电平,不是上位机
   算出来的那一份** —— 所以「高级选项」里的「上位机侧取反」**对回零一点用都没有**
   (它只改上位机这一侧的中止判据)。极性不修就去回零,驱动器会认为限位恒压着。
   **能改 `2300h` 就去改它**(bit0~bit2 置 1 → `0x0007`); 这也是程序的默认动作
   (「高级选项」的「写驱动器 2300h」默认开,连接时写、收尾还原)。

1. **`em_home()` 这条调用链本身。** 从头到尾一次都没在真机上跑过。**现在全仓库唯一
   的调用方是界面**(`ecatworker.cpp` 的 `doHome()` —— 「原点模式」框那八个按钮);
   原先 CLI 那一侧 (`motor_test --home`) 已经在 2026-09-21 删掉了,所以**以后要验它
   只能靠真机界面**。
2. **收尾那五步的顺序,尤其是"先失能 → 再切 CSP → 再使能 → 再重新锚定"。**
   `em_arm()` 是在**使能那一刻**把 `607Ah` 钉到当时的 `6064h`;重新锚定排在它**之后**,
   三者(`origin`/`tgt` / `607Ah` / `6064h`)才自洽。**验收点:回零做完之后再点一次画布,
   必须没有意外运动。**
3. **`g_stop` 的纪律。** 回零被「停止」中止一次之后,再点一次「使能」或「故障复位」,
   看它是否正常执行 —— 不会做的话说明 `drainCommands()` 里那次 `em_clear_stop()`
   没生效(故障复位那条尤其危险:它是在**已经卸力之后**才会失败的)。
4. **中止延迟。** 回零中点一次「停止」,应当是**几十毫秒内**停下(轮询是 2ms,
   界面上按钮到 30Hz 刷新那一拍另算),**并且保持使能**。控制台应打出
   `[中止] 撤掉 6040h bit4, 保持使能`。
5. **那两段失能窗口有多长、竖直轴会滑多少。** `6098h` 只能未使能时写、切回 CSP 也只能
   未使能时改,所以轴在**回零之前**与**收尾**各失能一次,竖直轴这两段都会失去保持力矩。
   拿秒表/相机量一下这个时间(**这个数要写回本文件**),再决定竖直轴能不能这么用。
6. **方式 24 在这台机器上到底朝哪个物理方向走。** 「正向」说的是**电机轴**的正反向,
   与画布上的哪一边没有必然关系。所以第一次要在**低速下限 100 pul/s**、人在急停旁边
   的条件下点一次,看它朝哪边走。**反向不对就换另一个按钮,
   别硬顶**;找不到开关就先手动把滑台挪到开关附近再回零。
   **速度框的缺省是 50000 (1 圈/秒), 第一次必须手动把它压到下限 100** ——
   缺省值取的是"能干活的速度",不是"第一次该用的速度"(见 §18.7)。
   100 pul/s 在 30 秒里只走 0.06 圈,所以压到下限试方向时
   **必须先把滑台挪到开关旁边**,否则它只会超时,看不出方向对不对。

> 2 与 5 这两条是**互相咬合**的:收尾那一段失能窗口里滑台会下滑,而重新锚定是在重新使能
> **之后**做的,所以下滑的那一段被算进了新零点里。量下滑量的时候顺手就验了第 2 条。

- **手动速度不进 `Params`。** 它跟扫描几何无关,也不该写进 CSV 表头(CSV 表头是用来判

  `ScanController::start()`;扫描一结束/中止,`running` 变假,`refresh()` 自己就把手动

> 属于 §13「尚未验证」那一类里最轻的一档:**没有人在真机上验过手动速度真的生效**。

依据:[ykd2205pe_ci402.md](ykd2205pe_ci402.md) 的位定义与端子功能实测。

四处全部改正:`scanwindow.cpp`(tooltip + 横幅)、`scancontroller.cpp`(两处中止文案)、
`scancontroller.h`(注释)、本文。

| 要求 | 做法 | 落在哪 |
|---|---|---|
| 每根轴三个限位信号 | 原先是独立的一组「限位开关」:原点 / 正限位 / 负限位,读 `60FDh` bit2/1/0 (**2026-09-20 并进「轴信号」, 见上**) | `ScanWindow::buildAxisPanel()` |
| 加一个复位按钮,驱动器显示故障时可以复位 | 原先是「轴信号」组第三行、跨全部列; **2026-09-20 起在两行最右边那一格、跨两根轴**, 清 `6040h` bit7 | `ScanWindow::onFaultResetClicked()` → `postFaultReset()` |
| 原点与正负限位要分开 | 原点 **绿亮不中止**,正/负限位红亮 | `LampGrid` 两块 (仍在, 排在同一张表上) + `ecatcmd::limit_hit()` |

#### 一个决定性的实测事实

**本机生效的 TxPDO (`1A00h`) 只有 3 项 / 10 字节**:`6041h`/`6064h`/`606Ch`。
ESI 声明里那份 12 项 / 39 字节的清单(含 `60FDh:32`)**不是生效的映射** ——
同一份文档自己写着「不要相信任何一份『出厂映射』」。

所以 `60FDh` 走**两条路**:默认**只绑不补**(它本来就在映射里才绑,零副作用),
另加一个**默认关闭**的连接期开关 `setWantDigIn()` 可以在连接时补一次(仅写 RAM,
收尾还原)。界面只给一个勾选框,而且**只在未连接时可改** —— 改了不重连不生效,
不锁住就会出现"勾了没反应"。**优先走厂家上位机改一次 `1A00h` 那条零代码路径。**

#### 撞限位:收成一处

统一成 `ecatcmd::limit_hit()`,在 `publish()` 里算一次,发成 `AxisTelem::limit_active`,
`SCAN_LIMIT_BIT` 这个宏**删掉了**。

发布的行为 = **bit11 单独判定**。精判据(bit11 **且** 60FDh 说正/负限位压着,
原点不算)写好了但藏在 `#define kRefineLimitWithDigIn 0` 后面,规则本身做成带参数的形式,
于是**两条分支在同一次构建里都可测**。不打开的理由是有一类配置会让它变弱
(`2310h`~`2312h` 功能码改成 0 时 `60FDh` 三位恒为 0,而 bit11 照样会因限位置起;
此时 `dig_known = true` 而精判据永不成立,保护就没了)。**先按真机实测结果决定。**

> 另一件记录在案、本轮**不改**的事:`healthProblem()` 对 bit11 **没有消抖** ——
> WKC 要连续 10 帧坏才中止,而 bit11 单帧置起就中止。文档自己写着开关脉宽要大于 10ms、
> 而输入滤波设的是 2,所以暂态是可设想的。**不投机加消抖**(20000 pul/s 下 100ms 消抖
> 要花掉约 2000 pul)。改为:在上升沿那一支**顺带 `printf` 出当时的 `60FDh`** —— 见 §13。

#### 踩的坑

| 坑 | 现象 | 修法 |
|---|---|---|
| `setColumnStretch(N+1, 1)` (**同一个坑第二次**) | 凭空多出一个空列,文字被挤成一个字宽 | 列数写成枚举 `AX_NCOL`/`LIM_NCOL`,造列和拉伸**读同一个值**;拆成两块之后列号不再是常数 3 |
| 判据写在 `.cpp` 里 | `scan_selftest` **不编 `ecatworker.cpp`**,逻辑写在那儿就等于永远验不到 | 纯判据全部做成 `hmi/ecatworker.h` 里的 `inline`(`ecatcmd` 命名空间) |
| 测试自己写错:`dig_pos=true` 却期望"不撞" | 红了一条 —— 那一位压着本来就该算撞 | 见下 |
| `resetting` 只靠 `publish()` 往遥测里拷 | 界面**永远**看不到"正在复位…" | 复位里那两次**加锁直写** `m_telem.resetting` 才是起作用的那半,见下 |

**第四个坑是一个真 bug。** `publish()` 与 `doFaultReset()` 跑在**同一根线程**上
(`run()` 里 `drainCommands` 在循环顶、`publish` 在循环底),而复位那一整段是**阻塞**的
(每轴最多 1 秒)。所以那两三秒里 `publish()` 一次都跑不到,等它跑到时 `m_resetting`
已经被置回 `false` —— 只把 `t.resetting` 做成"从成员每周期拷一份"(和 `m_busy` 一样的
写法)的话,`BusTelem::resetting` **恒为 false**,界面上「正在复位…」文案、按钮禁用、
tooltip 里"期间按钮不可用"那句承诺全是死代码。

当时(2026-09-20)让界面看见的是**复位里那两次加锁直写 `m_telem.resetting`**:界面线程是
独立的 30Hz 轮询 `telemetry()`,工作线程阻塞期间它照样读得到。**两处都要**,而且删掉
任何一处都会悄悄退化成"按钮看起来没反应"。规则写下来:

> **凡是"某个阻塞命令执行期间界面要看的状态",都必须由那条命令自己加锁写进 `m_telem`,
> 不能只依赖 `publish()` 的每周期拷贝。**

> **2026-09-21 补**:上面这条规则现在有了更强的那个版本 —— 让**阻塞期间照样每帧发一次遥测**
> (`em_set_cycle_hook` + `EcatThread::BlockTick`,见 §21)。直写仍然是"第一个字节之前就
> 写上"的那半(界面靠它立刻把「停止」换成立即中止),但**"每帧都在变的量"只能靠每帧发**:
> 回零/找限位期间那三盏开关灯就是这么修好的。规则因此改写成:直写管"状态位在动作开始前
> 就位",`BlockTick` 管"动作全程都在刷新" —— **两样都要,且都不能表达对方的另一半**。

同一条规则也说明**既有的 `m_busy` 有这个毛病**(不是本轮引入的):`doConnect()` 置
`m_busy = true`,但连接也是阻塞的,同样两秒内一次 `publish()` 都跑不到,所以
**连接期间按钮其实不会变形态**。这是**既有行为,本次没动**(见 §13 小瑕疵)。

#### 真机反馈:勾选框勾不上 + 一句说错的"已撞上"

| 坑 | 现象 | 修法 |
|---|---|---|
| `doConnect()` 两条早退路径漏清 `m_busy` | 连接**失败过一次**之后 `busy` 永远是 `true` → 界面把 `onair` 当成"占着总线",于是 `m_connected` 永远为真:使能/设零点/开始扫描全亮着而底下什么都没有;勾选框 `setEnabled(!onair)` 于是再也勾不上 | `doConnect()` 拆成**壳 + 内层**:`m_busy` 只在壳里写一对(置起 / 清掉),内层七条出口一条都不管 |
| 把"连接期参数"实现成"连上了就不许改" | 人恰恰是**连上之后**看见三个灯全灰才知道要勾它,而那时框是灰的 | 永远可勾,改用"说出来":已经连上了就提示"**下次「连接」才生效**"。勾错代价为零 —— `em_require_dig_in()` 只在 `em_setup` 里读一次 |
| 横幅把"驱动器报了一位"讲成"已撞上限位" | 操作员看到的是一句**事实错误**的话,于是去处理一个不存在的问题 | 只说知道的两件事(bit11 置起 + `60FDh` 说了什么),按三种情况给三种"现在能做什么" —— 见下 |

**第二个坑的教训**:`setEnabled(!onair)` 把**发现问题的时刻**和**能改的时刻**拆开了 ——
而人只会在前者想到后者。"灰掉一个控件"和"说一句为什么"之间,凡是两者都能做的时候
都应该选后者。

**第三个坑是措辞**:bit11 是 CiA402 的 `internal limit active`,本机到底拿它表示什么
**还没实测过**(§13 那六条里的第 2、3 条)。所以横幅现在按三种情况说话:

| `60FDh` 的情况 | 横幅说的 |
|---|---|
| 读不到 | 分不清是原点还是限位 —— 并告诉人**怎么让它可读**(勾那个框,或用厂家上位机改一次 `1A00h`) |
| 正/负限位有一位压着 | "先手动把它走离压着的那个开关" |
| 只有原点压着 | 明说**"压着的是原点开关"**,而"任何开关压着就置起"这件事本机还没实测过 |
| 三个都没压着 | 往别处找:607Dh 软限位?还是 `2310h`~`2312h` 功能码没配?—— 但**这两个数现在没有程序会打印**(原先那个只读诊断的 CLI 已删,`em_setup` 也不打 `607Dh`),要看得自己临时加 `em_rd_i32` |

状态栏那一格同时从 `限位X 撞上!` 改成 **`限位X 有效!`** —— 它只有一格宽,
那就放驱动器自己那句话,别替它下结论。

横幅是 `hint(s, true)`(**不自动消失**);bit11 下降沿 / 丢帧 / 断开都会把它清掉,
而且**只清"还是我们自己那条"的**(比对原文,免得把中止之类别的消息抹掉)。

第三条:**失败的那条断言是测试写错了,不是产品错了。**
它把"只压原点"写成了 `(dig_pos=true, dig_neg=false)` —— 而 `dig_pos=true` 正是
"正限位压着",命中才是对的。
**`limit_hit()` 的参数里根本没有原点那一位**,所以「原点不算」不是靠一条 `if` 记得写对,
而是**传不进去**。

## 16. 三条现场反馈:记参数 / 滚轮 / 卡死

1. 每次开程序都要在十条 `\Device\NPF_{GUID}` 里重新认出上次那张网卡;
2. 参数框上滚一下滚轮就改了值 —— 参数栏本身就是要滚的,手一滑就改错;
3. **参数调到某些值,程序直接卡死。**

第 3 条是缺陷,前两条是可用性。

### 16.1 记忆:exe 旁边的 `scan.ini`(`scanprefs.h/.cpp`)

新文件 `scan/scanprefs.{h,cpp}`,**只链 `Qt6::Core`** —— `scan_selftest` 不链 Widgets,
把 ini 的读写放进一个能用自检真跑一遍的文件里,"键名写错一个字母"这种
**不报错、只是下次记不住**的错才有人抓。所以读写与
`Prefs` 结构体单独一个文件:`Params params; QString nic; int manual_speed; int home_vel;`
加上「高级选项」那三个 bool,加上色标那个 `shade_auto`。

- **位置**:`QCoreApplication::applicationDirPath()/scan.ini` —— exe 旁边。跟着程序走,
  一眼能找到;想清零就删了它。`QSettings` 用 `IniFormat`,**不用注册表**。
- **记**:区域 X/Y、分辨率、1 单位 = ? 脉冲、速度、停留、稳定、采样、蛇形、起始方向、
  **上次连的网卡**、手动点画布用的速度、**回零速度**(`ui/home_vel`)、
  **「高级选项」那三项**(`adv/want_dig_in` / `adv/npn_write_drive` / `adv/npn_sw_invert`)、
  **色标是不是自动跟随**(`shade/auto_fit`)。
  手工改坏的 ini 会被夹回量程内(`ecatcmd::home_vel_from_pref`)。
  **改键的坑**:`QSettings` 对缺项给一个无效 `QVariant`,`toBool()` 一律 false ——
  读那几个 bool 必须显式带缺省,否则一个旧 ini 会把"默认开"读成"用户关掉了"。
- **不记**:
  - **CSV 路径** —— 文件名带时间戳,记住它等于把上趟的数据盖上或者把新数据写到别处;
  - **色标上下限** —— 它是"这一张图"的显示参数,把上趟锁的小范围套到新数据上,
    新图会**看着是空的**;每次都从 0..1 起。
    注意这跟上面那条"色标自动跟随**记**"不矛盾:**模式**记不住就得每次开程序重新勾一遍,
    而**数值**记住就是把上趟的量程套到新数据上 —— 前者记的是"怎么显示",后者记的是
    "显示到什么范围",后者一旦是陈的就会把人骗了;
  - **功率计选择** —— 真机与模拟源
    之间切换是有代价的 (选到真机会马上去开设备,几百毫秒到一两秒),而记住它意味着
    下次开程序**一进去就去找表头** —— 表头不在时那是一次注定失败的打开,还会在状态栏
    留一句红字。同理不记波长/量程/模式三项:那是**设备**的当前配置,由设备自己报回来,
    在 ini 里存一份就成了第二个真相。
- **什么时候写**:①按「连接」时(**连之前先记住这张卡** —— 否则连上了再改掉下拉框,
  记下的是最后选的那条而不是真连上的那条);②关窗时;③点某一框的「保存」时。
  那两处顺手写的同时会把正在编辑的那一框的当前值一起记下,并把它的快照跟上
  (否则「取消」会退回一份已经不在 ini 里的"上次保存值")。
- **写不进去不算错**:目录只读、盘满、文件被占着,都只是"这一次没记住"。
  `prefsSave()` 里没有返回错误这一路。
- **过不了 `validate()` 的当前参数不覆盖旧的**(`prefsMergeParams`):
  在 **连接时** 和 **关窗时** 都只记"能用得起来的那份"。
  判据用的就是界面「开始扫描」按不按得动的那一条(`validate`)。
- **量程(`range_pul`)一律归零**:它是从区域算出来的(`autoRangePul`)。

**网卡怎么选回来**:`buildUi()` 里那个 `adaptersListed` 读回 `m_savedNic`,
在 `\Device\NPF_{GUID}` 里 `findData()`;找不到(换了机器、卡拔了)**退回第一项**,
状态栏给一句"上次用的网卡 (…) 不在列表里 —— 请重新选一块。(记在 exe 旁边的 scan.ini 里)"。
**不弹模态框**。

### 16.2 滚轮:先选中,再滚(`WheelNeedsFocus`)

规矩:**只有选中的那个输入框才认滚轮**;选中的意思就是它拿着焦点(点一下就有)。
没有选中时,滚轮**不吃这一滚**,让它继续往上传给参数栏滚动区 —— 于是同一个滚轮
在参数栏上照旧是滚动条。

**错在"事件到底落在哪个控件上"。** 过滤器只装在 `QDoubleSpinBox` 这些外层控件上时,
探针直接 `sendEvent` 给 spin box 是"过了",而真机上不是这么走的。
装在 `qApp` 上的探针抓下来的真实投递顺序是:

```
QWidgetWindow  ->  QLineEdit 'qt_spinbox_lineedit'  ->  QDoubleSpinBox
```

**先接到滚轮的是 spin box 内部那个 `QLineEdit`**,而 `QAbstractSpinBox` 正好
在那个 line edit 上装了自己的事件过滤器(内部编辑框的按键与滚轮都走那一条),
**值就是在那一条里被改掉的**。过滤器只装在 spin box 上,这一滚根本轮不到。
同理:判"选中没有"必须从
**收到事件的那个控件往上找**到被闸的输入框再比焦点(`guardedAncestor`),
拿 line edit 自己去比是永远比不上的(焦点在 spin box 上)。

所以现在:

```cpp
/* 装在输入框 + 它的每一个子控件上 */
void guard(QWidget *w) {
   m_guards.insert(w);
   w->installEventFilter(this);
   for (QWidget *k : w->findChildren<QWidget *>())
      k->installEventFilter(this);
}

/* 收到事件的那个控件 -> 找到它属于哪个被闸的输入框 */
QWidget *input = guardedAncestor(w);
if (input == nullptr)      return false;   /* 这一滚不落在参数框上 */
if (hasFocusInside(input)) return false;   /* 选中过了: 按 Qt 原来的规矩改值 */
e->ignore();                               /* 没选中: 不吃, 交给父级去滚 */
return true;
```

第三处:**名单是"找出来的",不是手写的**。手写的表**漏了不报错** ——
只是那个框还在被滚轮改。现在改成遍历窗口里所有
`QAbstractSpinBox` 与 `QComboBox`,能漏的唯一方式是"新加了一个既不是
`QAbstractSpinBox` 也不是 `QComboBox` 的输入控件"。

**还有一条"翻页不作废选中"的坑。** 点过之后焦点一直留在那个框上,
而人要滚参数栏时**鼠标正是从参数框上划过去的** —— 路过刚点过的那个,它照样改值。
所以 `buildUi()` 里还接了一条:

```cpp
connect(sideScroll->verticalScrollBar(), &QScrollBar::valueChanged, this, [sideScroll](int) {
   QWidget *fw = QApplication::focusWidget();
   if (fw != nullptr && sideScroll->isAncestorOf(fw))
      fw->clearFocus();       /* 人在翻页, 不是在改参数 -> 选中作废 */
});
```

只清**滚动区里面**那个焦点(顶栏那张网卡表在滚动区外面,不受影响)。
加上这一条之后,"翻页"这个动作本身**永远改不了任何参数**。

两个实现细节:

- **`e->ignore()` 与 `return true` 要一起用**。Qt 的规矩是"滚轮事件沿着父链上传,
  直到被接受";过滤器返回 `true` 就**吃掉了**这一次投递,父级 `QScrollArea` 再也收不到,
  参数栏就**滚不动了**。先 `ignore()`(于是 `accepted=false`)再把 `true` 返回,
  才是"我不改值,这一滚交给上面去滚页面"。
- **不能用 `w->hasFocus()`**:焦点在内部那个 `QLineEdit`/`QDoubleSpinBox` 上,
  谁是焦点跟"哪个是我要闸的输入框"是两件事,只能沿父链找。

**范围**:只闸 `QAbstractSpinBox` 与 `QComboBox`,不是全局。
`QLineEdit`(CSV 路径)不闸 —— 滚轮改不了它的文字,它那一滚照旧落给参数栏。

### 16.3 卡死:点数上限 200000(`kMaxPlanPoints`)

**根因**。`ScanController::rebuildPlan()` 从前是"参数一动就照着算",
`nx*ny` 有多大就建多大(改之前的原文):

```cpp
m_nx   = axisCount(m_p.area_x_unit, m_p.res_unit);
m_ny   = axisCount(m_p.area_y_unit, m_p.res_unit);
m_plan = buildPlan(m_p);                      /* nx*ny 个 Point */
m_plan_p = m_p;

const size_t n = (size_t)std::max(0, m_nx) * (size_t)std::max(0, m_ny);
m_done.assign(n, 0);                          /* 再加三份同样大的 */
m_have.assign(n, 0);
m_watts.assign(n, 0.0);
```

而 `validate()` 里那条"点数 200000 太多"的提示**只是一句话** —— 它挡「开始扫描」,
但**不挡 `rebuildPlan()`**。区域上限 500、分辨率下限 0.001 ⇒ **2.5e11 个点**。

数值小一点(比如 1e8 个点、约 4 GB)时 `assign` **会成功** —— 于是没有崩溃、没有报错,
只有:填 `plan` 的那个循环一直在跑,加上 `MapCanvas::paintEvent` 每帧重建
`QImage(nx, ny)` 再逐像素填。**界面从此不动了**,而且**也没崩**,所以看起来就是"卡死"。

**修法**。上限提成**一处定义**(`scanplan.h`):

```cpp
constexpr long long kMaxPlanPoints = 200000;
```

`validate()` 与 `rebuildPlan()` **读同一个常量** —— 一处分界,两处执行。
`rebuildPlan()` 现在先算 `nx/ny/total`,超限就**什么都不建**:

```cpp
if (nx <= 0 || ny <= 0 || total > kMaxPlanPoints)
{
   m_nx = m_ny = 0;                    /* ← 这两行不能省, 见下 */
   m_plan.clear(); m_done.clear(); m_have.clear(); m_watts.clear();
   m_plan_p = m_p;
   return;
}
```

- **`m_nx = m_ny = 0` 是必须的**:`cellDone()` 里按下标访问 `m_done[iy*m_nx+ix]`,
  留下 `m_nx/nx` 而把数组清空就是**越界读**。零化之后"没有网格"在全程序里只有一种表示。
- **空网格在别处都安全**:`rebuildImage()` 见到 `nx<=0` 直接返回(画布空着)、
  `start()` 判 `nx<=0` 就拒绝、参数栏用 `paramsError()` 把「开始扫描」按住。
- **画的是"要的那张网格",不是"建出来的那张"**:参数栏与状态栏显示的是
  **算出来的 `nx/ny/total`**(哪怕超限),因为操作员要的是
  "我要的这一片到底有多少点" —— 显示 0×0 会让人以为分辨率没生效。
  超限时那一行写清 `网格 400 × 501 = 200400 点 … 超过上限 200000 —— 网格没有建
  (画布此刻是空的, 「开始扫描」按不动)`。

**200000 是资源闸**:`plan` 是 `Point` 数组、`m_done/m_have/m_watts`
各一份、热力图要一张同尺寸的 `QImage`、还有一条预览路径。两万个点以内怎么都轻松,
二十万个点是一张 447×447 的图 + 几十 MB。`validate()` 里那句话也照着它写:
"先确认分辨率是不是少打了个零"。

## 17. 「读一次」按钮 + 三个模拟源的自检

### 17.1 动机:接上表头之后第一件想做的事,原来做不到

真机那一路接通之后,界面上能证明"接上了"的只有一行状态行 (表头/探头型号 + 序列号)。
想看到**一个数**,必须先开一趟扫描 —— 而一趟扫描是一小时。

所以功率计面板里加了一个 **「读一次」** 按钮:向**当前取样源**要一个数并显示,
不用跑整趟扫描。它走的是扫描用的同一条路 (`requestReading` → `readingReady`/
`readingFailed`),所以**这一下通了就等于采集那条路也通了**。

显示里带**一次往返的实测毫秒数**:那个数必须远小于扫描参数里的读数超时,否则真机上
会每点都超时。

### 17.2 它为什么必须有一条硬闸

`PowerMeter` 的约定是"**恰好**回一次" + "**调用方**负责保证同一时刻只有一个未决请求"
(`powermeter.h`)。关键词是**调用方**——而现在调用方**有两个**:

| 调用方 | 什么时候发 |
|---|---|
| `ScanController` | 扫描进行中,一整趟几千次 |
| 「读一次」按钮 | 人工点 |

两个请求撞在同一个源上时:

- **模拟源**:老老实实回两次,两个数分给两边 —— 于是扫描的 CSV 里**悄悄少一个点或
  错一个点**,不报任何错;
- **真机 (Ophir)**:它按时间戳只认严格更新的采样,于是其中一边**白等到超时**。

两种都是默默发生的。所以闸门只能由界面来把:**控制器不在 `Idle` 时按钮禁用**
(`ScanWindow::refresh` 里那条 `setEnabled`),并且按钮的 tooltip 会说明为什么按不了。

两个槽 (ready/failed) 里还多比了一次 `sender() != m_meter`:换取样源时那个未决请求会
作废,但**旧源的回话可能已经排在事件队列里**了,比一次 `sender()` 就不用赌队列顺序。

### 17.3 顺序:先摆好状态,最后才发请求

`onReadOnceClicked()` 里 `m_readPending` / 起始时刻 / 兜底定时器**全部摆好之后**才调
`requestReading()`。源有一个**同步回话**的口子:没打开时三个模拟实现
都是直接 `emit readingFailed` 然后 return(在 `requestReading()` 的调用栈里就回来了)。
把顺序倒过来就是**在别人的调用栈里改自己的状态**。(§7 那条
"`emit` 一定在调用栈之外"的说法**只在打开之后成立**。)

### 17.4 自检:三个模拟源

三个模拟源**此前没有一条测试**,本轮补上一组
(本轮 **288 → 307** 条;这 19 条里 4 组是新用例,其余是组内多条断言),钉的就一件事,
也正是那条闸所依赖的:

> **一次请求恰好回一次** (`readingReady` 或 `readingFailed`,不多不少),且值对得上。

- 手动源:没打开 → 恰好一次失败、零个读数;打开 → 恰好一个读数、值就是设进去的那个;
- 随机源:跑十次,**每一次**都只许回一个数,且落在 `基值±噪声` 之内,并且十次不能全撞在
  同一个数上 (那说明 `setNoise` 没接上,热力图会是一片死色);
- 脚本源:`#` 注释与空行跳过 → 按行取 → **取完一轮绕回第一行**,`cursor()` 对得上;
- 最后一条**不是**在验某个源,是在验那条约定本身:两个未决请求撞在一起时,源会**老实回
  两次**(`checkEq(n, 2)`),谁也不知道哪个数属于哪一次 —— 这就是 §17.2 那条闸必须存在的
  理由。这层逻辑在界面上 (要 Qt Widgets),而本自检按约定**不链 Widgets**,所以它是
  "用测试说明为什么必须挡",不是"用断言验挡没挡住"。

**踩到的坑 (自检直接段错误,而且一行输出都没有)**:第一版是每个请求就地写
`QObject::connect(&meter, signal, [&loop](...){...})` —— 这个三参数重载的连接宿主是
**信号发送方** (那个源),而 lambda 按引用捕获的 `QEventLoop` 早就析构了。下一次请求
回话时,**上一次留下的那个 lambda 也会被叫起来**,碰的正是那个已经没了的循环。
收进一个 `ask()` 助手,把连接挂在 `loop` 自己身上 (context 传 `&loop`,loop 一析构连接
就断) 之后才好。顺带还发现:同步回话那一支会让 `loop.quit()` 在 `exec()` 之前被调用,
而 Qt 对"循环没在跑时的 quit"是**什么都不做** —— 于是每次白等到超时 (不报错,只是慢)。

输出为什么一行都没有:`printf` 到管道是块缓冲的,段错误把整个缓冲区丢了。

### 17.5 另外补的两处

- **`m_lReadout` / `m_lMeter` 明写 `Qt::PlainText`**:这两格显示的是**设备来的字**
  (探头型号、序列号、过量程原因)。QLabel 默认 `AutoText`,那串字里只要有个 `<`
  就会被当 HTML 解析 —— 于是要么显示不全,要么被标签吃掉。
- **换取样源时清掉那一格**:一个从没读过的源旁边挂着一个数,是最坏的一种残留;
  未决请求同时作废。

### 17.6 这一轮动到的文件

- `scan/scanwindow.h/.cpp`:`m_btnRead` / `m_lReadout` / `m_readTimer` / `m_readPending` /

## 18. 回零:驱动器自带的正/反向找原点

需求:**「加入驱动器自带的正方向和负方向寻找原点功能 当然找原点的时候我按停止键
依然能做到直接停止」** —— 后半句才是这件事的难点。

### 18.1 驱动器侧的原语

`em_home()` ([ec_motor_motion.c](../motor_api/ec_motor_motion.c)) 完整实现了回零的全部
动作:写 `6098h` 方式 / `6099h:01`·`:02` 速度 / `609Ah` 加减速 / `607Ch` 偏移 →
`6060h = 6 (HM)` → 抬 `6040h` bit4 启动 → 每 2ms 轮询 `6041h` bit12(到位)/ bit13
(回零错)/ bit3(故障),而且**自己泵帧**。**唯一的调用方是界面**(`doHome()`) ——
原先还有 `motor_test --home`,那个程序 2026-09-21 删了。

**正/负方向就是方式 24 与 29**(见
[ykd2205pe_ci402.md](ykd2205pe_ci402.md) 那张表):24 = 原点信号为原点、**正向**高速先找;
29 = **反向**高速先找。**35 没用** —— 它是"以当前位置为机械原点",它**不去找**,
不是这两个按钮的意思。

**「按停止键直接停」也早就埋在 `em_home()` 里**:轮询里有一句
`em_stop_requested()`,**命中就撤掉 `6040h` bit4 并**保持使能**(中途位置不明,
卸力会让竖直轴自由下滑)。缺的是**怎么把那个"停止"送进去**。

### 18.2 队列救不了回零

停止请求今天只能经 `postStop()` / 命令队列进来,而队列是在 `EcatThread::run()` 顶部
由**同一个会被回零阻塞住的线程**排空的。回零期间投一条 `CMD_STOP`,要等 `em_home()`
退出来才被看见 —— 也就是**最长 30 秒之后**。

所以「停止」在回零期间必须**绕过队列**:由 GUI 线程直呼 `em_request_stop()`。
这就碰到了 [hmi/ecatworker.h](../hmi/ecatworker.h) 顶部那条不变量 ——
**「GUI 线程一个 motor_api 函数都不调」**。

处理方式是**明写出来** —— 那条不变量正是这块代码可审计的全部依据,
**违反它比改写它更糟**。新例外安全的理由也是结构性的:`em_request_stop()` 只往一个
`static volatile sig_atomic_t` 里存 1,不碰 `em_bus_t`、不碰网卡、不做 I/O;
motor_api 自己就是按「信号处理器里也能调」来设计它的。

用它的地方**只有两处**(见 §2 那节与 §10 的护栏表):「停止」按钮在回零中的那一支,
以及 `disconnectAndStop()` 的第一步。**`hmi` 不受影响** —— 它没有回零功能,
那两个按钮的连线一个字没改。

### 18.3 收尾那五步

`em_home()` 有**五条返回路径**,没有一条留下的状态是调用方可以不管的:

| 路径 | 它留下什么 |
|---|---|
| 到位 | 使能 + HM + bit4 已放下 |
| 被「停止」中止 | 使能 + HM + bit4 已撤(**不切模式**) |
| bit3 故障 / bit13 回零错 / 超时 | 使能 + HM + **bit4 还举着** |

所以 `doHome()` 只能有**一个出口**,收尾无条件执行:

```
0. em_clear_stop()                 // 见 18.4
1. em_disable(ax)                  // ★ 超时那条路上, 这一步才是真正让它停下来的
2. em_set_mode(ax, EM_MODE_CSP)    // 已使能时会被拒 —— 所以必须在 1 之后
3. em_enable(ax)                   // em_arm 会把 607Ah 钉在 6064h
4. 重新锚定: m_origin[ax] = em_pos(ax); m_tgt = 0; m_want = 0;   // ★ 必须在 3 之后
5. 读实测状态判定结局, 复位 m_homing, 一条汇总 note()
```

- **第 1 步不是冗余**:超时/bit13 那条路上,`em_home()` 返回时驱动器**还在找**,
  让它停下来靠的就是这一步(那几个控制字都没有 bit4)。
- **第 4 步的位置**:`em_arm()` 是在**使能那一刻**把 `607Ah` 钉到当时的
  `6064h`。若先锚定再使能,失能窗口里滑台自重下滑的那一段会让 `m_origin` 停在**下滑
  之前**、而 `607Ah` 钉在**下滑之后** —— 下一次 `interpolate()` 就会以旧位置为目标
  **全速把滑台开回去**。这就是 18.5。

### 18.4 `g_stop` 是进程级的,而且会粘住

`em_clear_stop()` 在**全仓库此前一次都没被调用过**,是块死代码。
不清的后果:回零时被置起的那个 1 会留给**下一条命令**,让它在自己的第一次检查处当场中止
(`em__cw_step` / `em__wait_sw` / `em_set_mode` / `em_home` / `em_fault_reset` 都读它)。
表现是「点了使能没反应,控制台说被中止了」;而**故障复位那条更糟** ——
它是在写完 `6040h = 0x0000`(**已经卸力**)之后才中止的。

纪律:**`drainCommands()` 里每出队一条命令就 `em_clear_stop()` 一次。**
于是每条命令都从干净开始,运行中被置起的标志只由正在跑的那一条理会。

**唯一的洞是收尾**:回零被中止后,收尾那几步会**立刻**被那个还没清的标志打断
(第一步 `em_disable` 内部就有 `em__cw_step`),轴就停在「使能 + HM + bit4 可能还举着」
—— 正是要防的状态。所以 `doHome()` 的收尾第一步**再清一次**:那个停止请求瞄的是
**运动**,而收尾的全部职责是抵达一个确定状态。

### 18.5 陈旧的显示原点是这次改动里最危险的一行

回零之后驱动器自报的 `6064h` 会跳到它的回零坐标系(等不等于 0 由 `2214h` 决定,
`em_home()` 刻意不断言)。**不重新锚定 `m_origin` 就是一次没人按过按钮的全速运动。**

所以重新锚定是**无条件**的,而且**必须在重新使能之后**(18.3 第 4 步)。

配套的不变量:**工作线程在所有它真动过的路径上重新锚定,GUI 每次派发回零都 `m_epoch++`
一次。** 于是「锚定而不 +1」(危险方向)结构上不可能;「+1 而不锚定」只是让续扫多问一句
(那是保守的错误方向)。GUI 无法知道工作线程那道闸是拦还是放,所以**宁可多发一代**。

### 18.6 闸必须在动作之前

`em_home()` 自己的四条拒绝(已使能 / 无完整帧 / 有故障 / 方式越界)**全部在第一次写之前**。
**危险的是外围**:`doHome()` 第一步 `em_disable()` **真的会撤掉
保持力矩**(竖直轴当场下滑)。等 `em_home()` 去发现"不该做",力矩早撤了。

所以闸读的是**刚取到的**状态(不是上一轮发布的遥测快照,同 `doFaultReset` 的规矩),
判据顺序也是定的:`!bus_ready → !origin_ready → !mirror_ok → fault → any_axis_moving`。
`mirror_ok` 排在 `fault` **前面** —— 一个从没收到过的状态字里的 bit3 不是信息
(同 `axis_needs_reset` 那条规矩)。`any_axis_moving` 用工作线程自己的真相
(`m_want[k] != m_tgt[k]`),不看有 33ms 滞后的遥测:回零期间插补器是停的,
另一根还在走的轴会**停在半途**。

### 18.7 界面上是怎么摆的

- **框名叫「原点模式」,里面只有一个速度值和八个按钮**(逐轴,可以只回一根)。
  **速度右边那一格是这块框的`[编辑][保存][取消]`,顶着框的右边界**(见 §19.4)。
  版面是**一行一根轴,四个按钮**: 行首一个「轴X / 轴Y」标签,右边依次
  **正向回零 / 反向回零**(方式 24/29,基准是**原点开关 X0**)、
  **找正限位 / 找负限位**(方式 18/17,基准是那一侧的**限位开关**,见 §20)。
  按钮文字里**不带轴名** —— 一行四个按钮,每个再带个"X "就排不下,而"这行是哪根轴"
  正是错点一下代价最大的那件事,所以轴名写在行首(同「轴信号」那块表的行标签)。
  发起按钮**只看被点的那一根**的判据,不看另一根,**也不看它使能没使能** ——
  未使能也能回零(`em_home()` 自己会先失能再使能,而且它**要求**未使能才能写 `6098h`)。
  八个按钮**共用同一个速度值**:`6099h:01/:02` 与 `609Ah` 是同一对参数,再放一个速度框
  会出现"哪个在生效"这种界面上看不出来的组合。
- **回零中只改正在动的那一根的按钮文字**:回 X 时 Y 那两个不动;找限位时左边两列仍写着
  "正向/反向回零"(那一趟不是找原点),找原点时右边两列仍写着"找限位" —— 说反了人会以为
  "找完还要再找一次"。文字变短("回零中…")也不会把列宽撑开。
- **速度输入框**喂 `6099h:01`;**`6099h:02` 与 `609Ah` 都由它派生**
  (返回速度 = 1/4,式子就是 `ecatcmd::home_vel_slow()` 那一句;加减速按**斜坡时间 0.1 秒**算,
  见下面那条)。上下限与工作线程的夹取**读同一对宏**,所以**界面上显示的数就是线上发的数**。
  **不进 `scan.ini`** —— 同"错了就是安全问题的值必须每次由人重申"那条。
- **速度的上限是 `HMI_VEL_MAX`(100000 pul/s),缺省是驱动器自己 `6099h:01` 的实测值
  50000**。第一版这里写的是 2000/500 —— 照 `em_home_cfg_default()` 那个值
  抄的,而它跟机器自己的配置差 25 倍。「手动速度」+ 点画布
  本来就能以 100000 pul/s 朝同一个开关走,把回零单独压到 2000 并不构成一道真实的保护,
  只是让这个功能没法用(500 pul/s = 0.01 圈/秒,30 秒走 0.3 圈)。**真正该防的是
  "找不到还不肯停",那由超时兜着。**
- **加速度是"斜坡时间 0.1 秒"推出来的**(`ecatcmd::home_accel_for`)。
  写死 5000 配 2000 pul/s 是 0.4 秒斜坡;配上放开的 100000 就是 **20 秒**
  斜坡,一次回零整个花在加速上,**操作员把速度调上去却看不出任何区别**。
  0.1 秒这个数来自驱动器自己那对实测值:`6099h:01 = 50000` 与 `609Ah = 500000`
  相除就是它。速度超过 50000 之后加速度**封顶在 500000**(器件自己那个数,
  `6083h`/`6084h` 也是它),斜坡变长到 0.2 秒 —— **这个程序里没有哪一处该比机器自己
  配的加速度更硬**。
- **不弹确认框,框里也不再写说明文字**。那三段话只剩两个常驻的地方:
  · **按钮 tooltip**(事前):「**驱动器会自己带电并移动,软件拦不住它撞开关**」、
    **该轴会先失能(竖直轴此时失去保持力矩)**、轴 / 方向 / 方式号、以及"方向不对就换
    另一个按钮,别硬顶";
  · **速度输入框的 tooltip**(事前):"够不着开关请先把滑台挪近,**不要**为了够得着
    去调高速度"(这句原先在框里那行随速度变的字上,那行删了之后搬进 tooltip)。
  出路是「停止」= 立即中止(回零中唯一写着出路的地方是顶上那条**不自动消失**的横幅)。
- **2026-09-20 删掉框里那两行小字**(一行随速度实时变: 本速度 / 返回速度 / 加减速 /
  最多走几圈 / 几秒判超时;一行报两根轴的 `6061h`): 面板只剩速度与八个按钮。
  前者的**数**不再在界面上露出(要回看只有控制台回零收尾那条结论句),
  后者的**证据仍然在**控制台结论句里(`EcatThread::doHome` 的 `note` 单独一格打印
  `6061h`,且把期望值 `EM_MODE_CSP` 一起写进去) —— 所以工作线程那一次读与
  `AxisTelem::mode_disp` 都**留着**,不是"没人用的死字段"。
- **回零期间**:该轴按钮文字变「回零中…」、顶部出横幅(那条横幅**不自动消失** ——
  它是这 30 秒里唯一写着出路的地方;**它浮在画布顶上、不占布局体积**,见 §9「横幅不进布局」)、
  「使能 / 失能 / 停止点 / 设为区域中心 / 开始扫描」全部锁住。**「停止」除外**。
- **回零结束后自动切回 CSP 并保持使能**,停在落点带保持力矩,
  一次点完就能接着点画布。
- **超时是 30 秒,而它同时是一条距离上限**:速度 × 30 秒。
  按缺省速度 50000 pul/s 算是 **30 圈** —— 而缺省扫描区域才 27 单位(27 圈),
  也就是说**缺省状态下从区域一头找到另一头也够**。速度调低时能找的范围跟着缩小
  (2000 pul/s 只有 1.2 圈),所以碰不到开关时该做的是**先把滑台手动挪近**,
  不是把速度调快。

## 19. 「高级选项」框 + 参数框的编辑门控

两个需求合在一轮做:把让限位灯与开关对得上的那两件事做成**默认开**、集中到一个新框里;
再给每一块参数框加一道门 —— 平时只读,点了这一框的「编辑」才能改。

### 19.1 现场那个根,以及两条修法的层次

`60FDh` 的 bit1/bit2 空载就同时置起 → `6041h` bit11 恒为 1 → `2204h = 0`(超程停车)
把两个方向都挡死 → 回零进得去、一动不动(§13 的实测)。修法两条,层次不同:

| | 动作 | 治哪一侧 | 谁读它 |
|---|---|---|---|
| **写驱动器 `2300h`** | `bit0~bit2 = 1`(常闭)→ `0x0007`,高几位原样保留 | **根**:驱动器自己的限位保护、`60FDh`、`6041h` bit11 一次全对 | 驱动器 |
| **上位机侧取反** | 只换本程序的判据(`LIMIT_RULE_INVERT`) | 上位机:三个灯与中止判据 | 本程序 |

**两条一起上 = 双反相,而且不是"等于没反",是更坏**:判据此时只看反相后的两个限位开关,
双反之后它们空载时都是 1 → 判据**恒成立** → **扫描永远开不了**(只多报,不漏报)。
所以:第一条默认开,第二条默认关;两个都勾着时界面上出一行红字
(`editgate::doubleInvertWarning`,判据与措辞都被 `scan_selftest` 钉住)。

回零是**驱动器**自己按它读到的电平走的 —— 上位机侧取反对回零一点用都没有 (§13 第 0 条)。

### 19.2 写 `2300h`:三步,任一步不确认就整体拒绝

`motor_api` 里原先**没有任何写参数的路径**。新增的只有两个入口:

- `em_allow_param_write(bus, on)` —— 与 `--allow-pdo` **分开的一道授权**
  (改映射是通信配置,改驱动器参数是另一回事,代价不同);
- `em_di_set_logic(bus, want)` —— ① 先逐轴读原值(`em_rd_any`,
  **宽度按驱动器自报的来**,只认 1 / 2 字节,别的宽度不猜也不写)→ **任一根读不到就整体
  拒绝,一个字节都不写**;② 已经等于 `want` 的轴跳过;③ 写后逐轴回读 `memcmp` 确认。

回读不是可选项:本仓库这份 SOEM 在加急路径 (`psize<=4`) 把 SDO abort 当写成功
(`ec_motor.c` 顶上那条不变量),`em__verified_write` 就是为这个存在的。

收尾**挂在 `em_shutdown` 的失能之后、还原映射之前**,判据是 `di_logic_changed[]`,
**不查授权**(授权管"改",还原是把这一趟改掉的撤掉;再要一次授权会导致"没授权时收尾反而
留下改动")。**从不写 `2102h`**,所以不进 EEPROM 那条路。
**手册没写 `2300h` 会不会被驱动器自己落盘** —— 所以对外文案里不许出现"断电即回"。

CLI 侧(2026-09-21 起已删,下面是当时的改动):`motor_test` 多一行只读诊断
(顺带把它在 `sm_baseline.c` 里的宽度从 U8 改成 U16,
手册 V2.4 p84 是 U16 RW;`sm_bytes_to_i64` 的宽度取自 SDO 回包、`dt` 只管符号,
所以这次改的是标签,基线文件与行为都不变)+ `--allow-param` / `--npn`
(`--npn` 不带 `--allow-param` 直接拒绝,退出码 `EM_EXIT_USAGE`)。

### 19.3 「高级选项」框

摆在参数栏最底下 (设好了就别再动的东西)。三项,全部进 `scan.ini`:

| 项 | 默认 | 时机 | 说明 |
|---|---|---|---|
| 让 `60FDh` 进 TxPDO | **开** | 连接期 | 连接时补写 `1A00h`,收尾还原,仅 RAM;过程数据 10 → 14 字节 |
| 写驱动器 `2300h = 0x0007` | **开** | 连接期 | 见 §19.2 |
| 上位机侧取反 | 关 | **运行期** | 勾一下下一帧生效,并整个换掉限位判据 |

**顺序硬约束**:`loadSettings()` 是在 `buildParamPanel()` 里面被调的,而它要把存下来的值
写进那三个勾 —— 所以 `buildAdvPanel()` **必须排在 `buildParamPanel()` 之前**
(布局上仍摆在最后)。

`hmi.exe` 的行为**一字不变**:`EcatThread` 侧那两个成员初值都是 `false`,由 `ScanWindow`
按 `scan.ini` 推过去。`hmi` 那边唯一的新输出是每根轴一行**只读**的 `2300h = …`。

### 19.4 编辑门控:状态机在头里,`setEnabled` 只有一个写点

`scan/editgate.h`(**唯一的新文件,纯逻辑、不依赖 Qt**,所以 `scan_selftest` 能覆盖):

```
Gate { editing, dirty, discarded }
begin / markDirty / undirty / drop / save / cancel / titleMark / doubleInvertWarning
```

界面侧:

- 每块框一个 `PanelGate { Gate; box; btnEdit/btnSave/btnCancel; title_base; items; snapshot }`,
  成员表 `GateItem { w, lock_running, need_dev, need_manual }` —— **那三个按钮不进成员表**
  (进了编辑态它们反而必须按得动);
- `[编辑][保存][取消]` 那一行插在框首 (`QFormLayout::insertRow(0, …)`);
  回零框是 `QGridLayout` 而它只有三行 (速度 0 / 轴X 1 / 轴Y 2),**摆在速度右边那一行**
  (2026-09-21 改, 原先是框底单独一行 `(3,0,1,5)`): 这一框里只有速度是参数, 那三个按钮
  管的也就是它 —— 摆在同一行一眼能看出"这三个按钮管的是这个数", 还省下一行高。
  它占 3~4 列, 并且传 `Qt::AlignRight` **顶着框的右边界**(不传的话这一格被填满、
  按钮贴在速度框后面, 右边空一大块);
- **`ScanWindow::refreshEditability()` 是这些控件 `setEnabled` 的唯一写点**,
  由 30Hz 的 `refresh()` 每拍调用。原先 `refresh()` 里那张"扫描中锁住"的批量表
  (原来 19 个控件)整段删掉,搬进各框的 `lock_running`。
  写在按钮槽里没用 —— 下一拍就被覆盖;
- `enabled = 编辑态 && !(运行中 && lock_running)`,下拉框另需 `count() > 0`,
  真机那三项另需 `meterDevOk()` (与 `onMeterInfoChanged` **共用这一个判据**),
  色标的「按数据定标」另需 `need_manual`(自动跟随**关着** —— 开着时它做的事每帧都在做,
  灰掉)。别的框不留神写一句 `setEnabled` 会当场被盖掉,所以这一条也写在这个函数里;
- 屏幕上的七块框里**五块在表里**: 扫描参数 / 功率计 / 原点模式 / 高级选项 / 色标(功率)。
  「轴信号」与「扫描控制」不在 —— 它们只有按钮和灯, 没有"值"可回滚。
  「色标 (功率)」一度被摘出去过(2026-09-21),
  理由是"纯显示设置, 改它不碰滑台也不碰总线, 何必先点一次「编辑」" —— **又挂回来了**, 因为
  摘出去之后那一框没有`[编辑][保存][取消]`, 屏幕上一块框跟旁边六块长得不一样, 而里边
  「自动跟随数据」明明是**要记进 ini 的模式**, 却找不到一处该按"保存"的地方。
  门控在这一框唯一做的事就是"先点一下编辑", 代价很小;
- 这一框没有 `lock_running` 项: 色阶怎么画与滑台怎么走无关, 运行中也能改;
- 进编辑态拍快照;`dirty` 不是"改过没有"的布尔标记,而是**逐项与快照比对**算出来的
  (`gateDirty`):程序自己也会改控件值,布尔标记分不出是谁改的,而且改回原值也不会自己
  消失(`editgate::undirty` 干这件事)。比对只在编辑态里做,非编辑态不碰标题;
- 「取消」**先**退出编辑态**再**回灌控件 —— 回灌的每个信号都会经 `gateDirty`,顺序反了那个
  「未保存」标记永远清不掉。回灌**刻意不挂 `QSignalBlocker`**:
  "改动当场生效"就是靠那些信号重新下推的,拦了就成了"界面回到旧值、控制器还拿着新值";
- 但回灌**只对 SpinBox/ComboBox/CheckBox 有效** —— `QLineEdit::setText` 不发 `textEdited`,
  所以「功率计」那一框回灌完要补一次 `pushScriptPath()`(框里的文本和实际读的那份脚本是
  两份东西),"取消"才算真退回去;
- 程序自己改控件值的地方(色标那一框的**两个数**:按数据定标与自动跟随每拍刷的读数、
  **真机三项重填选项表**、**CSV 缺省名**)末尾调 `gateRebase()`:把那一项的快照跟上再重算标记
  —— 只动这一项,整框重拍会把同框里别处的未保存改动一起"原谅"掉。漏了它的症状是:程序改过的
  值会被「取消」滚回一份陈值,而滚完程序又改一次,两边打架。
  自动跟随那条路(30Hz 调的)还多一句"值没变就直接返回":`gateRebase` 会重写框标题,
  每拍重设一次标题就是每拍重排一次版面。
- **被推着走的那个框不算"程序改的"**:「最小」「最大」是一对,改一个顶到另一个头上会把
  另一个一起推过去(见 §色标),推的那一下信号是拦掉的,`gateRebase` 也**不调** ——
  那是操作员这一改的**后果**,不是程序自己定的值。「取消」就该把这一对一起退回去。
  (推完那个框照样会显示「未保存」,因为 `gateDirty` 是逐项比对算的,不是靠信号点灯。)

### 19.5 运行中哪些能改

| 框 | 成员 | 运行中 |
|---|---|---|
| 扫描参数 | 区域 X/Y、分辨率、1 单位 = ? 脉冲、方向、方式、CSV 路径 + 「…」、恢复默认 | **锁住** |
| 扫描参数 | 扫描速度、手动速度、单点停留、稳定窗口、每点采样 | 可改 |
| 功率计 | 取样源、手填值、噪声、脚本 + 「…」、真机三项(另需设备开着) | 可改 |
| 色标 | 上下限、自动跟随数据、按数据定标 | 可改 (自动跟随开着时上下限是读数, 打字改不动) |
| 回零 | 回零速度 | 可改 |
| 高级选项 | 三个勾 | 可改 |
| 轴信号 (内含限位灯) / 扫描控制 / 顶栏 | 只有按钮和灯 | 不门控 |

锁住的那一组都是**"这一趟怎么走 / 往哪写"**:跑到一半改掉,落进 CSV 的 (ix,iy)
就和滑台实际站的地方对不上了 —— 那张表按扫描开始时定的几何算出来的。

没锁的那些是**当场生效**的:扫描速度/稳定窗口/每点采样由控制器**每个点**读一次,
改完从下一个点起算 —— 于是同一张表里前后两段的节拍会不一样,而 CSV 的 meta 段记的是
**开始时**那一份。要可复现就把这一趟跑完再改。

### 19.6 三件事的取舍

- **「保存」就是现成的 `saveSettings()`**,不另写一份。理由是同一时刻**最多一块框**
  处于编辑态 —— 别块框此刻持有的必然是上次保存的值,所以重写整份 ini 不丢东西。
  **推论:切框时的静默丢弃不是界面上的客气,是这条正确性的前提,省不掉。**
- **「连接」与关窗也会落盘**(原行为)。它会把正在编辑那一框的当前值一起写进去 ——
  所以那之后要把它的快照跟上、标记清掉,否则「取消」会退回一份已经不在 ini 里的
  "上次保存值",而那个按钮承诺的就是 ini 里那一份。
- **「恢复默认」受门控**(它一按就是几何全变),并且会把「高级选项」那三个勾也带回缺省
  —— 否则那个按钮对这三个勾就是句空话。**回零速度刻意不在它的范围内**:
  为试回零特意压小的速度不该被顺手抬回去。

变的只有原点那一位,正/负限位那两位两趟都是有效。这趟 `2004h` 读到 `X0=低`。

## 20. 「找限位」:以限位开关为原点

现场还有一种基准需求:**不找原点开关 X0,而是把那一侧的限位开关本身当成机械基准**。
手册正文把它叫「找限位」:方式 **18 = 原点 = 正限位**,方式 **17 = 原点 = 负限位**
(V2.4 p46~p48)。这一轮把它加进界面与 CLI —— 与「回零」是两个按钮排,
但走的是**同一条** `em_home()`。

### 20.1 只有基准不同,别的都一样

| | 按钮 | 方式号 | 基准 |
|---|---|---|---|
| 回零 | X/Y 正向 / 反向回零 | 24 / 29 | **原点开关 X0** |
| 找限位 | X/Y 找正限位 / 找负限位 | 18 / 17 | **正限位 / 负限位开关** |

`motor_api` 侧**一行逻辑都不用改**:`em__home_method_ok()` 的白名单本来就含 17/18,
而 `em_home()` 里**没有任何按方式分支的代码** —— 它只负责写 `6098h`/`6099h`/`609Ah`/`607Ch`、
切 HM 模式、使能、抬 `6040h` bit4、等 `6041h` bit12/bit13。朝哪走、什么时候停、走几段,
全部由**驱动器自己**按方式号决定。

缺的只有三处:**白名单**(`doHome()` 里那道)、**界面**、**CLI**。

### 20.2 手册的两条分支,与那张真值表

只有 17/18 这两个方式,手册才分 a)/b) 两条分支。分岔的判据是**回零启动那一刻,
减速点(= 那一侧的限位开关)信号有效还是无效**:

| 方式 | 原点 / 减速点 | a) 启动时**没**压着 | b) 启动时**已经**压着 |
|---|---|---|---|
| 17 | 负限位 | 反向**高速** → 遇上升沿减速停止 → 正向**低速** → 遇下降沿后停机 | **正向低速**运行 → 遇下降沿后停机 |
| 18 | 正限位 | 正向**高速** → 遇上升沿减速停止 → 反向**低速** → 遇下降沿后停机 | **反向低速**运行 → 遇下降沿后停机 |

两条分支的终点都是**开关的释放点**(刚退开一点的那个位置)。b) 就是"从压着的开关上
退开"的正规做法 —— **它的首段方向与 a) 相反**,这是现场最容易看错的地方:
按「找正限位」它却朝反方向走,操作员会以为点错了按钮。所以发起之前**必须**先预告走哪条。

方向与快慢的文案**只从 `ecatcmd::home_method_first_dir()` 出**(原来是从"方式号等不等于 29"
推出来的,那套对 24/29 够用,对 17/18 会把 a) 说成 b)):

```
                 tgt_active = false    tgt_active = true
   24 (原点/正向)      正向                 正向        <- 24/29 不随"压着没有"变
   29 (原点/反向)      反向                 反向
   18 (正限位)         正向                 反向        <- b) 与 a) 相反
   17 (负限位)         反向                 正向        <- 而 17 与 18 本身又是反的
```

`scan/selftest.cpp` 把这张表钉死了(含"24/29 两格相等"那两条 —— 挡住"顺手把 17/18
那一套套到 24/29 上")。

### 20.3 两道否决,以及为什么只有两道

找限位比回零多一道闸,**位置在现有那道 `home_refusal` 之后、宣告 `m_homing = true`
与 `em_disable()` 之前** —— 早了没状态(状态字可能还没收到),晚了已经卸力(竖直轴会滑)。
拒绝时**一个字节都不写**,文案里必须有「拒绝」两个字(界面横幅靠关键词上红色)。

| 条件 | 为什么拒绝 | 出路 |
|---|---|---|
| `60FDh` 读不到 | 分不出这一趟该走 a) 还是 b) —— 而两条分支的首段方向**相反**,分不出来就不能发起 | 「高级选项」里勾上「让 60FDh 进 TxPDO」再重新「连接」 |
| 正/负限位**同时**有效 | 滑台不可能同时在两头,这一对读数里至少有一个不是真的 | 查 `2300h`(极性)与 `2310h`~`2312h`、以及 X0~X3 的接线 |

判据用的是**驱动器自己**那两位(`em_di_poslim`/`em_di_neglim`,即 `2300h` + `2310h`
之后的结果),**不是**界面反相后的 `dig_pos`/`dig_neg` —— 驱动器按它自己的读数决定怎么走,
上位机反相只改显示。这一点是这两道否决与界面那排限位灯分道扬镳的地方。

**为什么只否决这两条**:b) 分支本身是正规做法不是要拦的情形;"另一侧压着"更没事
(朝目标去正好是远离那一侧)。而"极性配反导致单边认反"(驱动器以为正限位压着,
其实是负限位压着)这一条**拦不住** —— 它的征兆与"真的压着"完全一样,软件无从分辨。
所以现场的前置条件是**先把 `2300h` 修对**(见 §19),那件事在那之前就已经是默认动作了。

不做的事:**不在 worker 里偷偷 SDO 读一次 `60FDh` 再放行**。界面侧让操作员先把那个勾
打开,比在后台悄悄读一次更可解释;而且 `60FDh` 本机已经在生效映射里,这条否决平时走不到。
`motor_test` 那一侧是例外(诊断工具),它**有** SDO 兜底 —— 见 §20.6。
(那个诊断工具 2026-09-21 已删;界面侧这条路本来就**不**做 SDO 兜底,现在也一样。)

### 20.4 界面上那条红色「撞限位」横幅必须闭嘴

找限位**故意**去撞限位,所以 `6041h` bit11 / 目标那一位置起是这一趟的**目的**。
但 `refreshAxisSignals()` 那条路会**弹红色「撞限位」横幅并把它当故障**,而且它和
"正在找限位"那条**状态**横幅争同一个 `m_banner` —— 争赢的结果是唯一一句
"按「停止」可立即中止"被顶掉。

豁免条件 `finding_limit && i == t.homing_axis`:

- **跳过 `hint(banner, true)`**;
- **保留**那一行 stdout 证据(它说的是"这个信号此刻有效",是事实)与
  **限位灯 / 状态栏那格**(照常变红);
- `m_limShown[i]` 照常置 true(不反复重算)、`m_limBanner[i]` **刻意不写** ——
  这样限位掉下去时清理分支把它归 false,于是**找完限位之后压着限位再启扫,
  那条红横幅与自动中止照常发生**。这条豁免只覆盖"正在找限位的那一根"。

### 20.5 落点 = 释放点,所以坐标 0 会贴在那一头

找完之后 `m_origin[axis] = em_pos(ax)`(收尾第 4 步,与方式无关)把这个释放点定为
显示坐标 0。**那一侧几乎没有行程** —— 继续用旧扫描区域跑会一路撞限位。
所以按钮 tooltip 上常驻这句话,提醒先按实测行程重算区域。

**不自动改区域**:改区域是操作员的决定。也**不加 `607Ch` 原点偏移控件** ——
17/18 的"原点"就是它停下的那个释放点,偏移保持 0;想把 0 挪到别处,界面上已经有
「零点」那一个按钮了。再加一个偏移来源会让"0 到底在哪"多一个不可回溯的地方。

## 21. 阻塞命令期间遥测不断流(`em_set_cycle_hook` + `EcatThread::BlockTick`)

**现场反馈(2026-09-21)**:"在回原点或者找限位的过程中信号灯不会实时更新"。

### 21.1 根因:一根线程,一个循环,而阻塞命令把这一圈顶住了

`run()` 的每一圈是 `drainCommands()` → `interpolate()` → `em_service()` → `publish()`,
**四个都在同一根工作线程上**。而回零 (`doHome`) 里的 `em_home()` 自己是**阻塞**的:
它在内部跑自己的过程数据循环 (2ms 一帧,`em__cycle`),直到找完才返回 —— 最长
`HMI_HOME_TMO_MS` = **30 秒**。这 30 秒里 `run()` 那一圈的 `publish()` 一次都跑不到,
于是 `m_telem` 冻在按下按钮那一刻的样子:**使能灯、三个开关灯、状态栏、位置全不动**。

要紧的是"找限位"这一趟:它的目的就是**去把那个限位开关压上** —— 灯不跟着亮,操作员就
没有任何东西能说明它压上了,只能靠控制台里那几行字猜。

这与 §15 第四个坑(`resetting`)是**同一个根**,当时只补了那一条命令的一半:
`doFaultReset()` 加锁直写 `m_telem.resetting`,界面才看得见"正在复位…"。
回零当时也照抄了一份(直写 `homing` 那三个字段),**但方案本身只够表达"某个状态位",
表达不了"这三个开关现在什么样"** —— 后者是每帧都在变的量,只能靠"每帧发一次"。

### 21.2 改法:给总线加一个每周期回调,阻塞命令期间把它挂上

| 在哪 | 改什么 |
|---|---|
| `motor_api/ec_motor.h` | 新增 `em_cycle_fn` 与 `em_set_cycle_hook(bus, fn, user)`:每收完一帧(镜像更新之后)回调一次,`fn = NULL` 注销,**不挂 = 行为与本函数不存在时一模一样** |
| `motor_api/ec_motor_internal.h` | `struct em_bus` 多两个字段(`cycle_fn` / `cycle_user`)。`calloc` 建的 bus,所以初值天然是 NULL |
| `motor_api/ec_motor.c` | `em__cycle()` 末尾调一次回调(**短帧那一支也调**:"这帧不完整"本身就是调用方要知道的事) |
| `hmi/ecatworker.h` | 新增嵌套类 `EcatThread::BlockTick`(RAII:构造挂、析构摘) |
| `hmi/ecatworker.cpp` | 回调体就是 `publish(wkc)`;`drainCommands()` 里**四条会阻塞的命令**各套一个 `BlockTick` |

四条挂上的命令: **`CMD_ENABLE` / `CMD_DISABLE` / `CMD_FAULT_RESET` / `CMD_HOME`**。
不挂的四条(`CMD_STOP` / `CMD_ZERO` / `CMD_CENTER` / `CMD_RANGE`)只改几个成员,不碰总线。
**`CMD_CONNECT` 刻意不挂**:那几秒里 `m_bus` 已经非空而 `m_naxis`/`m_ax` 还没建好,
从那些帧里 `publish()` 出去的是"连上了但一根轴都没有"的半成品。所以
§13 那条"连接期间按钮不变形态"的小瑕疵**照旧存在**,见 §21.4。

三个必须守住的约束(漏一个就是自锁或行为漂移):

1. **回调在调用者线程里同步跑**,每帧一次 —— 里面不许再做重活,更不许调 `em_home`
   这类阻塞函数,也不许再收发帧(`publish()` 只读镜像,所以它合规);
2. **不许在持有 `m_mtx` 的作用域里构造 `BlockTick`** —— `publish()` 自己要拿这把锁,
   而它是非递归锁,同线程再进一次当场自锁。四个挂点都在锁的作用域之外;
3. 回调是**只读**的:它不发帧、不写 `607Ah`、不碰输出镜像 —— 回零的时序一个字节都没变。

### 21.3 为什么不是别的做法

- **把 `em_home()` 拆成"HMI 侧自己跑循环"**:那是把回零那套状态机(写 `6098h`~`607Ch`、
  抬/撤 `6040h` bit4、等 bit12/bit13、超时)抄第二份 —— 一份安全关键逻辑两个实现,
  这是最坏的选法;
- **另起一根线程读 `em_axis_t`**:那些字段是 `em__cycle` 在写、工作线程在读的,
  多一根线程读就是数据竞争;
- **只加锁直写某个状态位**(即 §15 那套):表达不了"每帧都在变的量",正是本节要修的东西。

### 21.4 边界(说清楚它没做哪些事)

- **回调不等于"界面 30Hz"**:它每帧 (2ms) 都发,界面仍旧按自己的 33ms 轮询读。
  多出来的不是刷新率,是"数据不再冻住";
- **连接期间看不到** `BusTelem::busy` 的老毛病**没动**(§13),理由见 §21.2;
- **`hmi.exe` 免费得到同一份修复**(`ecatworker.cpp` 两个目标共用),但它的按钮形态判据
  里没有回零那几条,所以对它而言只是"灯和位置不再冻住";
- **`motor_test` / `slide_motion` 完全不受影响**:它们没调 `em_set_cycle_hook`,
  `em__cycle` 里那一句就是一次空判断。

### 21.5 这一轮动到的文件

- `motor_api/ec_motor.h` / `.c` / `ec_motor_internal.h` —— 回调那一套(纯增量);
- `hmi/ecatworker.h` / `.cpp` —— `BlockTick`、四个挂点、两处注释(原先写着"直写是
  界面能看见的唯一原因",现在不是唯一了,已改)。

### 21.6 验证到什么程度

**验了**(不需要设备):

- 全量重建 **0 warning 0 error**(`ninja` 全目标:`scan` / `hmi` / `scan_selftest`
  —— 当时还有 `motor_test` / `slide_motion` 两个目标,它们**在那次构建里也是干净的**);
- `scan_selftest` 全绿;
- 逐个看过四个挂点都**不在** `QMutexLocker` 的作用域里(约束 2);
- 逐个看过 `doHome` / `doFaultReset` 里那些 `m_telem` 直写的字段(`homing` 三个 +
  `resetting`)**与同名成员同时置起**,所以回调里 `publish()` 覆盖不掉它们。

**没验**(需要设备):

- 回零那 30 秒里灯确实在动 —— 要看的是**找限位那一趟**:压上开关的那一刻,那一格灯
  该在 ≤ 一个界面周期 (33ms) 内变红;
- 回零时序**没有**被这次改动扰动(约束 3 是"只读"的,但真机才是证据):
  方式 18 与方式 24 各跑一次,与 §20.7 那几条一起看。

## 22. 驱动器故障要给出故障码(603Fh)

**现场反馈(2026-09-21)**:"当驱动器故障要给出故障代码"。

### 22.1 问题:6041h bit3 只说"有故障",说不了是哪一个

故障位立起来之后,界面上原本只有一句话(红横幅 + 自动中止那句"驱动器报故障")。
而驱动器那一侧,**过流 / 过压 / 欠压 / 动力线 / 通讯 / 传感器告警的处置办法完全不搭界**
(查机械 / 查供电 / 查接线 / 查干扰 / 查编码器),它们在界面上长得一模一样。
手册里分辨它们的东西就一个:**603Fh 故障码**(U16 RO,与 1003h 低 16 位同源,
表见 `docs/ykd2205pe_ci402.md` §报警与指示灯)。

**603Fh 不在生效的 TxPDO 映射里**(本机只有 6041h / 6064h / 606Ch,60FDh 是可选的第四项),
所以它只能 SDO 读 —— 而 `publish()` 是每帧 (2ms) 跑的,**里面不许有 SDO**:
一条 SDO 读就是几毫秒,挂在 2ms 的圈里等于把圈期交给 SDO 的往返时间,插补会抖。
这条约束与 §21 里 6061h 那条是同一个(见 `EcatThread::readModeDisp` 的注释)。

结论:码**一定是"故障沿之后一拍"才到**的。这不影响正确性,但决定了这个功能的形状 ——
界面上必须能容忍"故障起来了但码还没到"那一拍,而且不能在那拍编一个码出来。

### 22.2 改法:牌子挂在 `publish()` 里,读在圈顶做

| 在哪 | 改什么 |
|---|---|
| `hmi/ecatworker.h` | `AxisTelem` 多一个 `fault_code`;两个哨兵 `HMI_FAULT_CODE_UNREAD` (-2) / `_FAIL` (-1);判据与措辞 `fault_code_meaning` / `fault_code_action` / `fault_code_text` / `fault_axis_text` / `faulted_axes_text` / `fault_code_line` / `fault_banner_text`;`EcatThread` 多 `serviceFaultCodeReads()` 与 `m_fault_code[]` / `m_fault_read_want[]` |
| `hmi/ecatworker.cpp` | `run()` 圈顶(插补之前)调一次 `serviceFaultCodeReads()` —— 唯一的 SDO 读点;`publish()` 只搬值 + 挂牌子;`teardown()` 把码与牌子一起清;`doFaultReset()` 失败那一格带上复位前的码 |
| `hmi/mainwindow.h` / `.cpp` | 同 scan 侧那一套(`m_faultCodeShown[2]` + 两拍)。`hmi.exe` 与 `scan.exe` 共用 `ecatworker.cpp`,**两处的说法必须一致**,所以这里也改了 |
| `hmi/axispanel.cpp` | 单轴状态那行原来只写"故障: <状态字>",现在后面接一个"· 故障码 0xFF02 (过压)" |
| `scan/scanwindow.h` / `.cpp` | `m_faultCodeShown[2]`(横幅上**已经说过**的那个码);故障横幅分**两拍**弹;「故障」灯的 tooltip 点明码在哪看 |
| `scan/scancontroller.cpp` | `healthProblem()` 那句自动中止带上每一根故障轴的码 |
| `scan/selftest.cpp` | `FakeBus::setFaultCode` 注入点 + 四组断言(见 §22.5) |

数据流一句话:`publish()` 看见某轴 bit3 = 1 且 `m_fault_code[i]` 还是 UNREAD → 挂
`m_fault_read_want[i]`;下一圈圈顶 `serviceFaultCodeReads()` 摘牌子、读 603Fh、
把结果写进 `m_fault_code[i]` 并 `note()` 一整句(码 + 意思 + 下一步查哪儿);
再下一帧 `publish()` 把它搬进遥测,界面在那一帧补上横幅的第二拍。
**从故障沿到界面上有码,是两圈 (约 4ms) 加一个界面周期 (33ms)**。

四个必须守住的约定:

1. **一个故障回合只读一次**:读到存值,读不到存 `FAIL`,两种都把牌子摘掉。
   牌子要是每帧重挂,读不到时就成了每 2ms 一条 SDO 去撞一个不应答的驱动器(要等超时),
   比读不到本身糟得多。bit3 掉下去之后 `publish()` 把码置回 UNREAD,于是下一次故障会重新读;
2. **`0000h` 不许兼"还没读"**:它是"无错误"这个真实读数。所以是两个负数哨兵,
   与 §18 里 6061h 的 `HMI_MODE_DISP_UNREAD` 同一个坑、同一个解法;
3. **只在 `run()` 圈顶读**:`publish()` / `interpolate()` 以及 §21 那个回调里都不许出现 SDO;
4. **`m_fault_code` / `m_fault_read_want` 只有工作线程碰**,`teardown()` 里清干净 ——
   换了台驱动器还挂着上一台的码,是最难查的那种假象。

### 22.3 三种"不知道"是分开说的

| 取值 | 界面上的说法 | 什么时候出现 |
|---|---|---|
| `HMI_FAULT_CODE_UNREAD` (-2) | 还没读到 (正在读) | 故障沿那一拍,或阻塞命令期间(§22.4) |
| `HMI_FAULT_CODE_FAIL` (-1) | 读不到 (SDO 没应答) | 试过了,这一趟没拿到 |
| `0x0000` | 0000 (无错误) | 真读到了,驱动器自报无错误(多半是上一轮的故障位没清) |
| 其他 | `0xFF02 (过压)` 这样 | 真读到了 |

手册之外的码照实报十六进制加一个"(手册之外)",**不猜名字** —— 猜一个名字比说不知道坏得多
(与 §18 里 `mode_text` 对模式号 2 的处理同一条规矩)。

### 22.4 边界

- **阻塞命令期间读不到**:`em_home` / `em_fault_reset` 那几秒里 `run()` 的圈顶跑不到
  (那是 §21 修的另一件事),`publish()` 由 `BlockTick` 从帧里被调到,只挂得上牌子。
  所以**找限位途中报故障,横幅立刻有、码要等这一条命令退出来**;
- **码不跟着故障清掉而保留**:bit3 一掉,`publish()` 就把码置回 UNREAD。
  要留痕看控制台 —— `note()` 那条不会被擦掉。一根健康的轴旁边挂着一句 `0xFF02 (过压)`,
  等于在说它现在过压;
- **不解析 1003h 的故障历史**:那是 10 条环形缓冲,读法完全不同,这一轮不做;
- **不做"按码自动处置"**:码只是信息,驱动器的动作(退电/停机)由它自己按手册决定。

### 22.5 验证到什么程度

**验了**(不需要设备):

- 全量重建 **0 warning 0 error**(`ninja` 全目标:`scan` / `hmi` / `scan_selftest`)。
  中间有一轮 `scan.exe` 链接被占用挡住(旧的那份还在运行,`ld` 报 `Permission denied`),
  所有 `.obj` 那一轮就编过了;关掉窗口后补的那一次链接正常;
- `scan_selftest` **597 passed / 0 failed**;新增四组(下面那些)全绿;
- 逐条对过手册那张表 (`docs/ykd2205pe_ci402.md` §报警与指示灯);
- 新增的判据都是 `inline` 放在 `hmi/ecatworker.h` 的 `ecatcmd` 命名空间里 ——
  与 §18 同一个理由:`scan_selftest` **不编 `ecatworker.cpp`**,写在 .cpp 里就永远验不到。
  新增的断言:

  1. 表逐条 (0000/FF01/FF02/FF03/FF04/FF06/FF08) + 十六进制要照实写 + 相邻的码不许抄串 +
     手册之外的码说"(手册之外)";**表里每个码都要有一句处置办法**(少一条,红横幅上就少半句),
     而**手册之外的码不给处置办法**(没有依据的建议比没有建议坏);
  2. 两个哨兵是负数、互不相同、都不等于 0,而且 `还没读到` / `读不到` / `无错误`
     **三句话两两不同**;
  3. 拼进 `"轴X 603Fh = ……"` 之后 **`603Fh` 只出现一次**(值那一段要是自带索引,
     整句会变成"轴X 603Fh = 正在读 603Fh…");
  4. 横幅:没故障时不许提 603Fh;只有轴Y 故障时不许点名轴X;
     两根都故障时**各自的码都要在**;有真实码时带上"下一步查哪儿";
     带真实码的自动中止那句话里要有 `6041h bit3` / `0xFF02` / `过压` / `轴X`(且不出现 `轴Y`);
     UNREAD 那一拍照实说"还没读到"且**不许出现任何十六进制数**。

**没验**(需要设备):

- 真机报故障时读回来的码是否与面板 ALM 灯的红闪次数对得上。手册里 ALM 的闪次就是这几个
  数字 (1 过流 / 2 过压 / 3 欠压 / 6 通讯 / 8 传感器),**对不上就先别信这条 SDO 读**;
- 驱动器正在报故障时它的邮箱通道还答不答 SDO(应答的话第一拍之后就有码,不应答就要等
  `FAIL`)。这是"一个回合只读一次"这个决定的对赌点:真机上更常见的若是"应答得慢但不是
  不应答",那这一条应当改成**限次重试**,而不是一次就放弃。
