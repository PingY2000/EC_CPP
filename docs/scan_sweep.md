# `scan`:滑台蛇形扫描 + 逐点功率采集

控制滑台在一个矩形区域里**蛇形(逐行往返)扫描**,每到一个网格点停下来,读一次功率计,
把 `(X, Y, 功率, 时间戳)` 追加进 CSV,最后得到一张功率分布图。

它与 [hmi](hmi_click_position.md) 是**并存的两个程序**,不是一个程序的两种模式:

| | `bin/hmi.exe` | `bin/scan.exe` |
|---|---|---|
| 干什么 | 手动调试台:点哪里走哪里 | 自动采集:自己走完一个区域 |
| 面板 | 两根一维轨道 | 一块二维面板 + 热力图 |
| 会自己动吗 | 不会 | 会,而且一次一两小时 |
| 共用 | **同一个 `hmi/ecatworker.cpp` 编进来的** —— 线程模型 / 坐标零点 / CSP 插补 / 全套护栏只有一份实现 | |

**功率计型号待定**,所以这一版只有抽象接口 + 三个模拟源。真机协议定下来之后要做的
只是再写一个 `PowerMeter` 子类,状态机、界面、CSV 一个字都不用动。

所以它要能脱离 Qt、脱离总线、脱离硬件单独编出来验。

## 2. 线程模型:总线线程一个字不改

现有边界是 **`EcatThread` 独占总线,GUI 侧只经 `post*` / `set*` / `telemetry()` 与它交互**。
扫描完全落在这条边界的 GUI 一侧:

```
GUI 线程                                  工作线程 (2ms 循环, 不动)
─────────                                 ──────────────────────────
ScanController (30Hz, 时钟由外面喂)
  ├─ BusView::setTarget(axis, want)  ───▶  m_want[]  ─┐
  ├─ BusView::telemetry()            ◀──  BusTelem   │ interpolate(dt)
  └─ 状态机: Moving→Dwelling→Reading→Log             └─▶ em_csp_set_target
```

**为什么中间要有一层 `BusView`(只有四个方法)而不是直接拿 `EcatThread` 用**:
[hmi_click_position.md](hmi_click_position.md) 的「尚未验证」一节写得很清楚 ——
**hmi 的「连接」那条路一次都没在真机上跑过**。也就是说这个仓库目前**没有可用的真机回路**
来验扫描状态机。而状态机里真正会出错的是暂停/继续/中止、到位窗口、外部改目标、
续扫从哪接上这些**时序**问题,它们跟总线没关系,只跟状态机有关。
换成 `FakeBus`(自己按速度推 `pos`,能注入掉帧/故障/失能/限位),整个状态机就能
**在没有硬件的情况下跑通** —— 这就是 `scan_selftest` 干的事。

**节拍是外部喂的**(`tick(now_ms)`),不是状态机自己起定时器。理由只有一个:
单测里换一只手拨的时钟,整轮扫描就能在几毫秒内跑完。
时间一律用**单调钟**(`QElapsedTimer`)—— 墙上时间会被 NTP 和对时往回拨,
那样"停留了 200ms"可能永远不成立,扫描会卡在那一点上。

30Hz 对到位判据够用:换行一次移动要几百 ms,停留最少也有 100ms 量级。

## 3. 单位、坐标与量程

```
1 单位 = 1 圈 = 50000 脉冲     (2400h 实测值, 是可调参数 pulses_per_unit)
显示坐标 = 6064h 原始值 − 软件零点
零点     = 「连接」那一刻读到的位置, 或「设为区域中心」按下的位置
区域     = 27×27 单位, **以原点为中心** → ±13.5 单位 = ±675000 脉冲
```

### 量程必须跟着区域走(本次唯一改到 `hmi/` 的地方)

`HMI_RANGE` 原来是编译期常量 `500000`,扫描区域要 ±675000。它在 `ecatworker.cpp` 里
夹了 **4 次**(`setTarget()` 两次、`interpolate()` 两次)。直接复用会把区域边缘
**悄悄削掉** —— 最坏的一类 bug:不报错,只是永远扫不到边。

改法(**纯增量,`hmi.exe` 行为逐字节不变**):

- `m_range` 从常量变成 `std::atomic<int32_t>`,**默认仍是 `HMI_RANGE`**
- 新增 `postRange(int32_t)`,走 `m_cmds` 队列(与 `postCenter` 同一个模式)
- `hmi` 自己从不调 `postRange`,于是它拿到的永远是 500000

```
量程脉冲 = ceil((max(area_x, area_y) / 2 + 1.0) * pulses_per_unit)
         = ceil((13.5 + 1.0) * 50000) = 725000     (默认参数)
```

`+1.0` 的余量是给**手动对位**用的:扫描区域之外还能手动走一点。
`range_pul` **不暴露给操作员**,永远按区域自动算 —— 它是个会因为手滑而把区域边缘
悄悄削掉的量,让人去填它没有任何好处。

> **`postRange` 有个必须绕开的陷阱。** `interpolate()` 是**先夹 `m_tgt`、再用 `m_tgt`
> 算 CSP 目标**的。所以如果把量程**改小**、而滑台此刻正停在旧量程的边缘外,那一夹就会
> 把 `m_tgt` 拽回来 —— **等于凭空产生一次运动,而且是没人按过任何按钮的运动**。
> 所以 `doRange()` 的规矩是:**放大无条件允许;缩小只在新范围装得下所有轴的当前
> `m_tgt` 时才允许,装不下就拒绝**并提示"先把滑台走回区域内"。绝不为了迁就新量程
> 去改 `want`/`tgt`。

## 4. 网格与蛇形

```
n     = floor(area / res) + 1        // 27 / 0.5 + 1 = 55
span  = (n - 1) * res                // 27.0
坐标[i] = -span/2 + i * res          // -13.5 .. +13.5, 共 55 个
```

`area / res` 除不尽时取 `floor` 并**把网格居中**(此时 `span < area`),
于是永远**不会越出区域** —— 宁可少扫一点也不扫到框外去。

轴 0 = **X**(行方向,快轴),轴 1 = **Y**(列方向,慢轴)。默认蛇形(逐行往返),
也可以改成每行同向。第一行的方向由「起始方向」定。

> **一个很有用的性质:蛇形里每一步只动一根轴。** 行内走 X、Y 不动;到行尾时下一个点
> 就在下一行的同一列上,于是 X 不动、只有 Y 进一格。稳态下**不会出现两轴同时走的斜线** ——
> 唯一一次斜着走是「从当前位置到第一个网格点」那一步(以及续扫/重测时)。
> 这既让时间估算好算(每步要么是 `res` 的距离、要么是行尾一格 `res`),
> 也让"到位"判据更干净。

### 时间估算

`estimatePerPointMs()` 是**线性**的:

```
移动   = res * pulses_per_unit / speed * 1000 = 25000 / 20000 * 1000 = 1250 ms
每点   = 移动 * 1.30 + settle + dwell + 50 * samples
       = 1625 + 100 + 200 + 50 = 1975 ms
全程   = 3025 * 1975 ms ≈ 100 分钟
```

`* 1.30` 是给**进近段减速**留的粗估,`50 * samples` 是采样本身占位
(模拟源是 0,真机未知)。界面上会明说这是线性估计、**实际更长** ——
不写这一句的话,跑起来比预计慢 20% 就会被当成"卡住了"。

## 5. 到位判据

`AxisTelem::at_target` 只是 `want == tgt`(`ecatworker.cpp`),那是**插补器自己走完了**,
**不等于实际位置到了**。所以判据是**两个都要**:

```
到位(i) = telem.ax[i].at_target                     // 插补目标已到终点
       && |telem.ax[i].pos - want_i| <= pos_tol     // 6064h 实测也在容差内
```

并且要**连续 `settle_ms`(默认 100ms)成立**才算稳定 —— 单帧瞬时满足可能在高速
掠过时误判。窗口一旦被打破就**重新计时**。

`pos_tol` **由步长推出来,不暴露给操作员**:固定 50 pul 在 25000 pul 的步长下是 0.2%
(合适),但有人把步长调到 500 pul 时就变成"允许偏 10% 个格子"(不合适)。
所以按步长取 1/20,并夹在 `[50, 步长/4]` —— 默认参数下是 **1250 pul**。

**没有单独的 `Settling` 状态**:稳定窗口就长在 `Moving` 里,界面想问"现在是在走
还是在等稳定",用 `settlingNow()` 读。让状态机多一个状态、多一套进出条件,
那些状态迁移分支是纯粹的自找麻烦。

## 6. 状态机

```
Idle ──开始──▶ Moving ──到位且稳──▶ Dwelling ──停够──▶ Reading ──采到──┐
                 ▲                                                      │
                 └──────────────── 下一个点 ◀──────────────────────────┘
                 全部走完 ▶ Done

Paused / Aborted 可以从上面任意一个状态进来, 且**立刻生效**。
```

- **Preflight**(缺一不可,全过才动):在 OP · 已使能 · 两轴 `mirror_ok` · 功率计已开 ·
  CSV 可写 · 参数合法 · 区域半宽 + 余量 ≤ 量程 · 点数 ≥ 1 且 ≤ 200000
- **Moving**:`setTarget(0, x_pul)` + `setTarget(1, y_pul)`(显示坐标),等两个轴都到位
- **Dwelling**:停 `dwell_ms`
- **Reading**:发一次 `requestReading()`,等信号回来(异步)。超时(默认 2s)
  或 `readingFailed` → 该点标为失败,CSV 里功率列写空、带一列错误原因,
  **扫描继续**(一个点读不到不该毁掉整轮)
- **Log**:追加一行 CSV + `flush` + 刷新热力图 → 下一个点

**`samples_per_point > 1`** = 到点后连采 n 次取平均。代价是每点多 n 倍**读数时间**
(真机串口一次几百 ms 时这项很贵),不是塞在停留期里白拿 —— 停留期是"等机械稳定",
两件事不该混。

### 暂停 / 继续 / 中止

- **暂停**:立即 `postStop()` 冻在当前位置(**保持保持力矩,不卸力**),
  当前点标记为未完成。**响应是立即的** —— 不会出现"按了暂停还要等一分钟这一行走完"。
- **继续**:**重新走向该点并重新采样**,所以不会写进半点数据的半成品。
- **中止**:同样冻住,状态转 `Aborted`,**已完成进度留在 CSV 里**。

> 暂停/中止走的是 hmi 的「停止」语义:**故意不写 `6040h=0x0000`**,那是卸力,
> 滑台会因自重下滑。

### 自动中止(每个 tick 都查)

扫描是**一次一两小时、没人看着**的长动作,所以下面这些在**每个 tick** 都查,
命中就立刻自动中止(而不是继续默默往下扫,把一整轮数据全采在错的地方):

| 条件 | 备注 |
|---|---|
| 掉出 OP / 连接断了 | |
| 任一轴 `6041h` bit3 故障 | `EcatThread` 已经会冻结目标,但扫描必须停下来 |
| 任一轴 `6041h` bit11 撞硬件限位 | 判据读 `AxisTelem::limit_active`(只有 `ecatcmd::limit_hit()` 一处算出)。**这一条最可能真触发**。中止文案会把 `60FDh` 那一行一并写出来(哪个开关压着 / 状态未知) |
| WKC 连续 10 帧不足 | 拔网线就是这个表现 |
| 任一轴丢帧(`mirror_ok` 掉)或掉使能 | |
| 有人从**旁路**改了目标 | 见下 |
| 走到位的最后期限 | `max(5000, 距离/速度*3 + 3000)` 封顶 120s —— 卡住/被夹住时的兜底 |
| CSV 写失败 | 宁可停,也不要默默少采几千点 |

中止时弹**红色横幅 + 模态框** —— 正是因为它无人值守,一闪而过的提示等于没提示。

> **`externalWantChanged()` 的两个坑,都是单测逼出来的。**
>
> 1. `setTarget()` → `publish()` 之间差一个 2ms 周期,所以下发之后不能立刻比 ——
>    那样会把自己当成外部干预。于是有一道"等它出现"的确认门(`m_want_ok`)。
>    但这道门**可能永远开不了**:如果在我们自己的值出现**之前**就有别人改了目标,
>    扫描会跟着别人的目标一路走下去,直到 120s 的移动期限才停。
>    所以加了 `WANT_CONFIRM_MS = 200`:下发 200ms 内没看到自己的值,就判定为外部干预。
> 2. **暂停时目标本来就"不是我们下发的那个了"** —— `postStop()` 把它冻在当前位置
>    (`want := tgt`),而那正是我们要的。不在暂停时放行的话,**一按暂停就会被自己
>    判定成"有人从别处改了目标"然后自动中止 —— 暂停按钮变成了中止按钮。**

## 7. 功率计接口(异步)

真机很可能是串口/SCPI,一次往返几百毫秒。**同步接口会把整个界面冻在那儿**,
而扫描一次要采几千个点,那就是几千次卡顿。所以是**请求 + 信号**:

```cpp
class PowerMeter : public QObject {
   Q_OBJECT
public:
   virtual QString kind() const = 0;
   virtual bool    open(QString *err) = 0;
   virtual void    close()            = 0;
   virtual void    requestReading()   = 0;   // 非阻塞; 恰好回一次 ready 或 failed
   bool isOpen() const;                      // Preflight 要问这一句
signals:
   void readingReady (double watts);
   void readingFailed(const QString &err);
};
```

三个模拟实现(**这一版全部做完**):

| 实现 | 用途 |
|---|---|
| `ManualMeter` | 界面上现填一个数,每次采回来都是它。用来手对流程 |
| `RandomMeter` | 基值 + 噪声,可调延迟。用来压热力图的配色与刷新 |
| `ScriptMeter` | 读一个每行一个数的文本文件,**每次请求取下一行**。可以配延迟 |

`ScriptMeter` 是没有功率计时最有用的一个:**它能让整条流水线(状态机 → CSV → 热力图 →
断点续扫)完整跑一遍,而且数据是可预测、可断言的**。

三个实现都用 `QTimer::singleShot(...)` 把 `emit` **挪出调用栈**
(`ManualMeter` 是 `0`,另两个是那个可调的 `delay_ms`,默认 20ms)。
这一点不是装饰:如果 `requestReading()` 直接 emit,状态机的 `readingReady` 槽会在
`requestReading()` 内部**嵌套执行** —— 状态机正在 Reading 里发请求,槽又把它推到下一步,
于是所有"进入某状态后紧接着做的事"都会踩到自己。延时投递之后,模拟源与真机
(串口回来了才 emit)的行为**完全一致**,状态机只需要考虑一种时序。

**不做工厂 / 注册表 / 配置文件**:一个基类 + 三个子类 + 界面上一个下拉框的 `switch`
就是终态。也不支持并发请求 —— 一个时刻只允许一个未决请求,状态机才能有确定的 Reading。

## 8. CSV:它本身就是进度文件

**不另存 sidecar 状态文件** —— 边采边写的 CSV 里已经有全部信息,再维护一份"扫到哪了"
就是两份真相,迟早对不上。

```csv
# scan v1
# area_x_unit=27.000000 area_y_unit=27.000000 res_unit=0.500000 pulses_per_unit=50000.000000
# speed_pul_s=20000 dwell_ms=200 settle_ms=100 samples=1 serp=1 start_pos=1
# range_pul=725000 pos_tol_pul=1250 zero_epoch=1
# started=2026-09-17T10:00:00
index,ix,iy,x_unit,y_unit,x_pul,y_pul,watts,ok,flags,pos_x_pul,pos_y_pul,spread_x_pul,spread_y_pul,unix_ms,elapsed_ms
0,0,0,-13.5,-13.5,-675000,-675000,0.001234,1,,−675000,−675000,60,45,1758096000123,412
```

- **每采一点追加一行 + `flush`** → 中途崩了/断电了,已采的数据一行不丢
- 列名一律 ASCII、数值用 C locale 格式化(`%f`/`%lld` 本来就是)—— 中文列名在中文
  Windows 上会被 Excel 按 GBK 打开成乱码,而某些区域设置会把小数点变成逗号、
  把整列解析搞崩
- `watts` 用 `%.9g`,**采不到时留空而不是写 0** —— 0 是一个合法的读数,
  拿它当"没采到"的哨兵,以后就没法区分"这儿真的没有功率"和"这儿没读上"了
- **`ok` 与 `flags` 是一对**:`ok=0` 时 `flags` 写原因(如 `timeout`),`ok=1` 时留空。
  单点重测写 `flags=retest` —— 重测**不是一个单独的列**,而是与失败原因共用这一列
  (两者可以同时成立,那时用 `|` 连起来,如 `timeout|retest`)。热力图与统计一律取
  **该格最后一行**
- `pos_*_pul` 是**采样那一刻的实测位置**,和网格点的理论值放一起就能看出这一点的
  定位误差;`spread_*_pul` 是稳定窗口内 `pos` 的极差:**振没振,在这儿看得见**

### 断点续扫

打开一个已有 CSV → 读表头**校验几何参数一致**(区域 X/Y、分辨率、每单位脉冲数;
不一致就拒绝并**指出哪个变了**)→ 读所有 `(ix,iy)` → 剩下没采的补扫 →
**继续往同一个文件追加**。

速度/停留/采样次数这些**不影响几何**的随便改,不该拦。

读回数值还有一个必须做的理由:不做的话,续扫打开的局面是**前半场的数据在文件里、
在图上却是空的** —— 而这张图正是这个程序存在的理由。

### 零点世代(`zero_epoch`)

每次「连接」或每次「设为区域中心」,**零点世代 +1**,写进 CSV 表头。

为什么需要它:连接时 `tryInitOrigin()` 会把零点重设为"当时所在的位置"。
所以断线重连之后,**同一个显示坐标指的可能已经是另一个物理位置** ——
那下半场的数据会和上半场拼在一张图上,而图上不会有任何异常的样子。

续扫时世代对不上**不是错误,是"要你确认一下"**:界面弹出一个说清差异的模态框,
确认后才继续。

### 单点重测

在画布上 **左键**选中一格 → 点「重测选中点」→ 走回那一点再采一次,
**追加一行**(带 `flags=retest`),不改动别的格子。热力图与统计取**该格最后一行**。

> **`ScanLog::beginAppend()` 会先把没写完的那半行切掉。** 追加写是掉电留下的残行是
> **正常情况**,不是异常情况;而 `QIODevice::Append` 会把下一行**粘在那半行后面**,
> 于是产生一行字段错位的垃圾,并且**它之后的所有行都跟着错位**。
> 切回最后一个 `'\n'` 是唯一不丢东西的做法 —— 那半行按定义就是没写完的。

> **跑完之后日志不关。** "刚跑完看一眼图、随手重测几个可疑点"是最自然的用法,
> 关掉之后重测就没地方追加了。中止也一样不关。

## 9. 二维面板与配色

`MapCanvas` 是 hmi 那两条一维轨道的二维版本,语义照搬:
**实心点 = `6064h` 实测位置,橙色 = `want`(Shift+点击给的),绿色虚线 = `tgt`(本周期下发的)**。
多出来的一层是热力图 —— 以及**棋盘上那两种左键**:见下面的「两个左键」。

- **可视量程固定 30×30 单位**(每边 ±15 再各留 1 单位余量,`MapCanvas::kViewHalfUnits = 16`),
  **不跟着区域缩放**;网格 + 每 5 单位一条淡线 + 零点十字
- **坐标标尺**:下边 X、左边 Y,每 1 单位一个小刻度、每 5 单位一个带数字的,
  位置与网格线**同一组**(都走 `pxOf(u)`,u 为 5 的倍数),所以线和对得上的数永远是同一个;
  零点用亮色,别的用灰。单位写在两根标尺交会的那只角上
- **区域框**:超出量程时**标红并写明"边缘会被静默夹掉"**
- **扫描路径预览**:开始前画出将要走的蛇形折线
- **当前点高亮** + 剩余点数 / 预计剩余 / 悬停读数(单位 + 脉冲)
- **左键 = 查看那一格**(选中 + 读出数值 / 索引 / 坐标);**Shift + 左键 = 手动定位**;
  手动定位在扫描进行中一律吞掉,查看随便点
- **撞硬件限位时**,实测位置那个点外面套一圈红环 + 写下是哪根轴(见下)

### 视野为什么是固定的

从前是"区域多大、框就画多大":区域一小,框照样铺满整块画布 —— 两次不同尺寸的扫描
画出来一模一样大,颜色也看不出疏密,**图与图没法比**。固定成 ±16 单位之后:

- 1 单位恒等于固定的一格,热力图可以直接叠着比;
- 区域框反而成了**图里的一个量** —— 默认 27×27 时每边还剩 2.5 单位余量;
- 每 5 单位一条的网格线落在 ±5/±10/±15 上,正好与 30×30 的边界对齐。

窗口变大变小,变的是这块方形的**像素边长**,不是它的量程。正方形画布现在**居中**
(以前钉在左上角,窗口一宽右边就剩一大块空白),区域尺寸写在左上角第三行。

> **画布上的东西一律"按单位存,画的时候才换成像素"。** 热力图、蛇形轨迹、滑台位置
> 都是这么画的,所以窗口一拉伸是**整张图一起缩放**。
>
> 蛇形轨迹曾经不是:它把 `pxOf()` 的结果(像素)缓存进 `m_path`,而缓存只在
> "网格数/点数变了"时才失效 —— 窗口缩放这两样都没变,于是热力图跟着长了,
> 折线却停在旧的像素位置上,画布拉大后只占左上角一小块。像素不是这份数据的属性,
> 存它就得靠一个容易忘的失效标记去救。现在 `m_path` 存的是**单位**(扫描点本来的样子),
> 像素由 `drawPath()` 用 `QTransform` 现算 —— 这类 bug 就不存在了。
>
> 那个变换里 `QPen::setCosmetic(true)` **不能省**:世界变换会把线宽一起放大 k 倍
> (k ≈ 20),不写的话那条 1px 的预览线会变成一条 20px 的灰带,把整张热力图盖掉。

> **手动定位被夹在"当前生效量程"之内。** 视野固定之后,画布上会有一圈既在扫描区
> 外面、也超出量程的地方;不夹的话在那儿点一下就是一次走到量程尽头的长动作,而界面上
> 完全看不出"我要的是 16 单位、实际只走到 14.5"。夹掉之后橙色三角停在量程边上,
> 那一停就是说明。

### 两个左键:查看给左键,动滑台给 Shift + 左键

| 动作 | 干什么 | 扫描中 |
|---|---|---|
| **左键** | 查看那一格:选中 + 显示数值 / `[ix, iy]` / 单位坐标 | **能用**(只读) |
| **Shift + 左键** | 手动定位到那一点(与 hmi 的点击同义,走显示坐标) | 吞掉,只留一行提示 |

**动滑台的多按一个键,是刻意的。** 画布上最常见的动作是"看看这一点采到多少" ——
扫描完一屏数据、想逐格读的时候更是一路点过去。那一下如果同时会把滑台支出去,就没人
敢随便点了。动作分给两个键之后,**会动的那一个永远要多做一步,顺手的那一个永远是空手**。

查看是只读的,所以不受扫描那道闸限制;点在没有网格的地方(区域框外那圈余量)
**取消选中**,而不是什么都不做 —— 否则选错的那个框会一直赖在图上,而人以为自己点掉了。

数值那一行**没采到也写出来,写"未采集"**:空着的话跟"这里根本没选中"分不清,
而这两种情况的下一步动作完全不同(一个去重测,一个去检查是不是点歪了)。

### 布局:画布随窗口长,参数栏自己滚

左画布 | 右参数栏,中间一根**可以拖的分隔条**(`QSplitter`)。窗口变宽,多出来的地方
全给画布(那是唯一要看的东西);参数栏塞在 `QScrollArea` 里,自己上下滚 ——
六组框加起来约 1330px,而窗口通常只给它 670,从前窗口一矮最下面的「色标」就被挤没了。

> 参数栏**不能用"固定宽度"**。里面那些输入框有自己的最小宽度,固定宽度一旦压到它
> 下面,`QScrollArea` 就把右边**裁掉** —— 横向滚动条关着的话连拖都拖不回来。
> 交给 `QSplitter` 之后宽度分配由它算,拖不动就是真的放不下了。

### 限位相关的显示:**四个地方、两个问题**

这是这块界面最容易看错的一处,所以先把问题分开:

| 问题 | 谁回答 | 在哪儿看 |
|---|---|---|
| **扫描会不会中止** | `6041h` bit11 | 状态栏那对灯 + 画布红环 + 横幅 |
| **开关本身压着没有** | `60FDh` bit2/1/0 | 参数栏「限位开关」六个灯 |

两者**可能不一致**(开关压着而驱动器没置 bit11,或者反过来),**不一致时以 bit11 为准**。

**几处同时说同一件事**,因为撞限位是会自动中止扫描的那一类:

| 位置 | 内容 |
|---|---|
| 状态栏(常显,两根轴各一个) | **信号灯 + 文字**:`○ 限位X 正常` / `● 限位X 有效!`(红底) / 不知道时灰灯 + `限位X --` |
| 参数栏「轴信号」(见下) | 每根轴两个信号:使能 / 故障 |
| 参数栏「限位开关」(见下) | 每根轴三个信号:原点 / 正限位 / 负限位 |
| 画布 | 实测位置点外面一圈红环 + `X 轴撞限位` |
| 横幅 | 上升沿弹一次(不自动消失) |

#### 信号灯:一条规矩,四种样子

**灯亮 = 这个名字代表的事正在发生**;灭 = 没发生;灰 = 不知道。这是配电柜上的老规矩,
每一格只需要读一个字就懂。

| 样子 | 画法 | 什么时候 |
|---|---|---|
| 灰 | `#4a5058` | **不知道** —— 没连接 / 轴上没遥测 / 丢过帧 / `60FDh` 不在映射里 |
| 灭 | `#20242b` 空心 | 这件事**没发生** |
| 绿亮 | `#33d17a` | 使能:带电 / 原点开关:正压着 |
| 红亮 | `#ff4d4d` | 出事了:故障 / 撞限位 / 正负限位开关压着 |

> **为什么不是"绿 = 没事"。** 那样的话正常运行时是**一片绿灯常亮**(没故障、没撞限位),
> 而真正要处理的那一秒也是绿的 —— 灯就成了墙纸。现在正常运行时只亮一盏(使能),
> 那一盏恰恰是"电机带电,动手之前先看清楚"的意思:它是信息,不是墙纸。

- 四种样子**都画满**,不搞"只在出问题时才显示":不知道时它坐在灰上,于是"看不见灯"
  本身不会跟"灯灭了"混淆 —— 那正是"一个只在出问题时才出现的指示器"会骗人的地方。
- 灯和字**装在一个小容器里**(`lampUnit`),免得布局把它们排散。
- **一格的灯、字、字色是一起变的**(`setSignalCell`),少写一样就会出现"绿灯配红字"。

### 参数栏两块:「轴信号」与「限位开关」

```
       轴信号                          限位开关
        使能      故障                   原点      正限位     负限位
 轴X  ● 已使能  ○ 无故障          轴X  ● 压住   ○ 松开    ○ 松开
 轴Y  ○ 未使能  ● 有故障          轴Y  ○ 松开   ○ 松开    ○ 松开
 [      故障复位      ]            [x] 让 60FDh 进 TxPDO
```

**为什么要分成两块**,不是挤在一块里:

- **宽度**。参数栏约 370px,一行摆五个"灯 + 字"会被挤成一团(轴名 ≈36px,
  每个 `lampUnit` ≈59px,五个就是 ≈330px,再加间距与组框边距就爆了)。
  四列 ≈250px,宽裕。**4 个信号列是上限。**
- **语义**。它们回答的是上面那张表里**两个不同的问题**。并排放在一行里,就会看起来像
  同一个问题的两个答案 —— 而它们可以不一致。

| 信号 | 位 | 亮起来的意思 |
|---|---|---|
| 使能 | `6041h` bit2 | 电机带电 —— **这个轴现在能不能走** |
| 故障 | `6041h` bit3 | 驱动器报故障(扫描中会自动中止) |
| 原点 | `60FDh` bit2 | 原点开关正压着(绿亮,**不会中止扫描**) |
| 正限位 | `60FDh` bit1 | 正限位开关正压着(红亮) |
| 负限位 | `60FDh` bit0 | 负限位开关正压着(红亮) |

- 信号名写在**表头**上,不是每格重复一遍 —— 每格都写一遍的话,这块地方会变成一片字,
  而灯反而看不见了。
- 两块都排在参数栏**最上面**。这一列比窗口高是常态(六组框约 1330px),而它们是**状态** ——
  要滚才能看到的状态指示器不算状态指示器。两块加起来七行,挤不掉什么。
- **判据跟状态机完全一致**(`ScanController` 自动中止那一段用的就是 `!valid || !mirror_ok`)。
  判得比状态机宽的话会出现最坏的那种不一致:**灯说"正常",而程序已经因为"丢了过程数据帧"
  中止了** —— 而且此时 `sw` 是陈值,那个"正常"根本不是现在的状态。
- 限位在参数栏和状态栏**两处**都有,两处都由 `refreshAxisSignals()` 一次算出 ——
  分开算就会有一天两边说的不一样,而"两个指示器互相矛盾"比"少一个指示器"坏得多。
  **撞限位的判定本身只有一处**:`ecatcmd::limit_hit()`(定义在 `hmi/ecatworker.h`),
  在 `EcatThread::publish()` 里算一次,发成 `AxisTelem::limit_active`,界面只读不算。
  从前这个判断在控制器 / 参数栏 / 画布**三处各写一遍**,那正是"总有一天两边不一样"的做法。
- 只在**真变了**才动控件(`LampGrid::lampLast` / `textLast`),30Hz 每帧给一堆控件重设
  样式表会把重绘刷爆(横幅那个上升沿判断是同一个理由)。

红色**故意不复用采失败那一格的 `C_FAIL`** —— 那个红的意思是"这一格没采到数"(数据问题),
这个是机械压在开关上(要立刻去处理),同一块画布上两种红必须分得开。
`bit11` 只说"有轴压着",不说方向;方向要看 `2310h`~`2312h`
(实测 **X0 = 原点 / X1 = 正限位 / X2 = 负限位**)。

#### 原点为什么不是红的

三个开关都"压着了",但**只有两个是要立刻处理的**:

- 压到原点是**回零时的正常动作** —— 它是位置信息,不是故障。用红的话,回零那一刻
  面板上会亮起一片红,而那正是操作员最不需要惊慌的时候。
- 所以原点用绿:在新语法下它完全通顺(亮 = 「原点开关正被压着」正在发生),而且
  **绿色本来就是这个面板里"是信息、不是报警"的颜色**。不用新加一个枚举值,不动画法。
- **代价**:三个格子用同一组词(压住 / 松开),于是**颜色是唯一说"这个会撞"的东西** ——
  所以原点的 tooltip 必须**说出声**:「绿亮 = 正压着,这是位置信息不是故障 ——
  扫描经过原点开关不会中止」。

#### 这是怎么保证的:原点那一位进不了判据

`ecatcmd::limit_hit(sw, dig_known, dig_pos, dig_neg)` 的参数里**根本没有原点那一位**。
「原点不算」不是靠一条 `if` 记得写对,而是**传不进去**。
`scan_selftest` 里有一条回归护栏专门钉这件事:只把原点位压住,扫描必须一路跑到
`Done`,`autoAborted` 一次都不能响。

### `60FDh`:读不到是常态

`60FDh` bit2/1/0 = 原点 / 正限位 / 负限位,是 `2300h` 电平反转与 `2310h`~`2312h`
功能映射**之后**的结果 —— 调用方不再取反(反过来说:`2300h` 配反了三个灯一起反相)。

**它多半不在生效的 TxPDO 里。** 本机实测生效的 `1A00h` 只有 `6041h`/`6064h`/`606Ch`
三项 10 字节(`docs/ykd2205pe_ci402.md`),没有 `60FDh`。这时三个灯是**灰 + `--`**,
而那**不是**"三个都没压住" —— `AxisTelem::dig_known` 是单独一个字段,就是为了让
这两件事分得开:读不到 60FDh 时那三位也是 0,而 0 在"开关压着没有"这个问题上是个
**看起来完全正常**的答案。

两条出路,优先走第一条:

1. **用厂家上位机改一次驱动器的 `1A00h`** —— 零代码,而且断电也在;
2. 勾上「限位开关」框里那个「让 60FDh 进 TxPDO」,让主站在连接时补一次:
   仅写 RAM,收尾(断开 / 关窗)时还原,崩在收尾之前那一次改写会留在驱动器里直到断电
   —— 与 `motor_test --allow-pdo` 同一风险等级。过程数据从 10 字节变 14 字节。

它是**连接期**参数:**改了不重连不生效**,所以只在未连接时可改(勾选框在连接期间是灰的)。
`em_setup` 会打一行 `printf` 如实报告绑上了没有 —— **上机的第一件事是看那行字,不是看灯**。

### 色标:单色相顺序色标,OKLab 插值

蓝色的 13 级(`#0d366b` → `#cde2fb`),取自仓库里既有的强调色 `#4a9eff` 那一族,
于是新程序看起来还是同一个程序。取色是**在 OKLab 里插值**的,**不是 sRGB** ——
sRGB 插值在中段会发灰、发脏,一眼就能看出色带分节。

顺序色标该过的那一关**跑过,过了**:明度严格单调、色相跨度 4°(不分叉成两种颜色)。
(同一份校验里"相邻色阶 ΔL 太小"那条是 FAIL,但那是给**离散色块**用的判据 ——
这里色标是连续插值的,相邻两级的差别本来就不该看得出来,所以不适用。)

暗色底上的方向是 **暗 = 小,亮 = 大**,与"近零应该退回底色"是同一条规则:
亮的地方就是功率大的地方。代价是最小值那一端跟底色对比度低(1.5:1),
于是**必须有数字兜底** —— 右侧色标条上写着锁定的最小/最大值,鼠标移到格子上也出数。
**热力图永远不能只有颜色。**

> **色阶是锁定的,不跟着数据实时变。** 这一点是刻意的:边采边自动缩放的话,
> 每来一个点整张图的颜色都会重排一遍,操作员看到的"渐变"其实只是自己在动 ——
> 那种图不能用来判断任何事。所以是两个数字(默认 0..1)加一个「按数据定标」按钮,
> 要改是**显式**改一次。超出范围的格子夹到两端,数值仍可在悬停里读到。

**三种状态在画面上分得清清楚楚,不靠深浅去猜**:

| 状态 | 画法 |
|---|---|
| 还没扫到 | 只有底色的空位 |
| 扫到了、读数失败 | **红框** —— 那才是要人去处理的一格 |
| 扫到了、有数 | 顺序色标 |

> **实测位置那个点刻意是白的,不是 hmi 的蓝色。** 因为这块画布上蓝色已经是**数据**了
> (热力图就是蓝色色标)。位置标记再用蓝色,就变成"一个中值的格子和滑台现在在哪儿"
> 分不清 —— 而这两个意思完全不同。白色在所有色阶上都最跳,也正是"现场光标"该有的样子。
> hmi 那边画布上没有数据,所以它用蓝色没问题,不必跟着改。

### 刷新与缓存

热力图是一张 `nx×ny` 的 `QImage`(**一格一像素**),放大时用最近邻
(`SmoothPixmapTransform = false`)—— 一格就是一个方块,不该被糊成渐变。
3025 个像素比一次 `QPainter` 填充还便宜,所以每帧重建,不值得为它做脏标记;
只有扫描路径是跟几何走的,才做几何变动的缓存 —— 而它缓存的是**单位**,
所以"窗口缩放了"这种几何变化根本不需要谁去记得把缓存作废(见 §9)。

## 10. 安全护栏(与 hmi / CLI 逐条对应,一条都不许退化)

| 场景 | 行为 |
|---|---|
| 程序启动 | **一个字节都不写总线**(只会 `postRange` 一个本地成员) |
| 「连接」 | `em_open` → `em_setup(...,1)` → `em_enter_op`。进 OP 开始发帧但**不发使能**;点之前弹模态说清它写什么 |
| 「使能」 | **唯一让电机带电的按钮**。每次点击都弹模态确认(人在设备旁、手放在物理急停上),**没有持久勾选、不自动使能** |
| 「故障复位」 | 每次点击都弹模态确认(含"**竖直轴下面没有人**")。**只对 6041h bit3 置起的轴写字节** —— 一根都没报故障时**一个字节都不写**;扫描进行中直接拒绝(先「中止」);复位成功后该轴停在**未使能**,要接着走请重新点「使能」;每轴最多 1 秒,期间**不可中断**、按钮显示"正在复位…" |
| 「开始扫描」 | 过 Preflight;另外弹一个把**区域 / 网格 / 点数 / 预计时长 / 数据流向**再报一遍的模态 —— 区域填错一个数字就是一头撞上限位 |
| 暂停 / 中止 | 目标冻在当前位置,**保持保持力矩**(故意不写 `6040h=0x0000`) |
| 扫描中 WKC 掉 / bit3 故障 / bit11 撞限位 / 掉出 OP | **自动中止** + 红色横幅 + 模态 |
| 扫描中改参数 / 换取样源 | 控件**全部锁住**。几何改到一半的扫描没有意义 —— 落进 CSV 的 `(ix,iy)` 和实际位置就对不上了 |
| 关窗 / 断开 | **先中止扫描** → 失能 → 还原 PDO 映射 → 降 `PRE_OP` → 关网卡 |
| 收尾未能确认失能 | **模态告警**,要求立即断驱动器动力电源(CLI 退出码 10) |
| 全程不写 | `2102h`(EEPROM)、`607Dh` 软限位、`2400h/2408h/2409h/2201h` |

> **收尾顺序不能反。** `disconnectAndStop()` 是**先中止扫描再断总线** ——
> 反过来的话状态机会看到"掉出 OP",然后作为一个**异常**去自动中止,
> 一条本来正常的收尾路径会变成红色告警。

> **启动时不弹任何对话框。** 每次启动都要点一次的弹窗只会被条件反射地关掉;
> 真正危险的三个动作各有自己的模态确认。常驻的一行须知比启动弹窗看得见。

> **「故障复位」为什么必须自己带一道闸(而不是"调一下让它自己发现没故障")。**
> `em_fault_reset()` 的动作顺序是**先写 `6040h = 0x0000`(Disable voltage = 卸力)
> 打十帧,再抬 bit7** —— bit7 是上升沿触发,不先把 0 压下去就构不成沿,这个顺序本身是对的。
> 问题在于它**到函数末尾**才报告"本来就没有故障":那时候十帧卸力已经打出去了。
> 对一根**健康的保持轴**做这件事,那一轴会**真的卸力,竖直滑台会掉下来**。
> 所以判据 (`ecatcmd::axis_needs_reset`) 必须在**调用之前**,
> 一根轴都没报故障时**一个字节都不写**。
> 状态未知的轴(`mirror_ok = false`)**跳过、不猜** —— 不知道它有没有故障,就不碰它。
> 复位的对象由 `6041h` bit3 决定,**不由操作员点了哪个按钮决定**:所以按钮不带轴参数,
> 一次复位所有报故障的轴。

## 11. 构建

`scan` 与 `hmi` 用**同一个 preset**(`hmi-qt-ucrt64`),所以**不改 preset、不加第二条
configure 命令**:

```cmake
option(EC_BUILD_SCAN "构建扫描采集程序 (需要 Qt6 + C++ 编译器)" ${EC_BUILD_HMI})
if(EC_BUILD_SCAN)
  add_subdirectory(scan)
endif()
```

`${EC_BUILD_HMI}` 作默认值 ⇒ 现有的 `cmake --preset hmi-qt-ucrt64` 一次把两个都编出来;
而只想编 hmi 的人可以 `-DEC_BUILD_SCAN=OFF`。

```bash
cmake --preset hmi-qt-ucrt64
cmake --build out/build/hmi-qt-ucrt64            # 全部
cmake --build out/build/hmi-qt-ucrt64 --target scan
```

产物:`bin/scan.exe`、`bin/scan_selftest.exe`。

`scan_selftest` **不链 SOEM 也不链 Widgets**(只用到 `Qt6::Core`)——
它几秒钟就能跑完,不需要设备、不需要网卡、不需要界面:

```bash
PATH="/c/msys64/ucrt64/bin:$PATH" ./bin/scan_selftest.exe
# ... 188 passed, 0 failed
```

> **`scan_selftest` 被钉在 `-O1`,这是绕开一个工具链 bug,不是偷懒。**
> 本目标在 `-O2`/`-O3` 下链接必然失败 —— `collect2: ld returned 5 exit status`
> (也见过 1/9/116),`ld` 自己的报错一个字都没有,输出文件被建出来但内容是**一片零**。
> `bin/scan.exe` 与 `bin/hmi.exe` 在同样的 `-O3` 下链接正常。
>
> 症状**只跟优化级别有关**,与代码写法无关:`-O0`/`-O1` 成功,`-O2`/`-O3` 失败;
> 单独 `ld -r` 同一组目标文件是成功的,只有完整链接才炸;
> `-ffunction-sections`、`-fno-asynchronous-unwind-tables`、`-fno-ipa-icf` 都试过,没用。
> 所以这是 **GCC 16.1.0 (MSYS2 UCRT64) 这一套 `ld` 自己的问题**,不是本仓库代码的问题。
> 出厂的 `bin/scan.exe` 保持 `-O3` 不变 —— 为一个自检程序的毛病去动 ship 出去的东西
> 是拿芝麻换西瓜。**GCC/binutils 一升级就可以把那行删掉**,然后重跑一遍自检确认。

#### 只有真机才能定的六件事(§15 末节那一轮新增)

**代码能保证、也必须保证的**三条:`dig_known == false` 时**永不**渲染开关状态(灰 + `--`);
`kRefineLimitWithDigIn == 0` 时 `60FDh` **永不**参与中止判定;
撞限位只有 `ecatcmd::limit_hit()` 一处定义。**下面这六条是代码答不了的**:

1. **`60FDh` 在不在生效的 `1A00h` 里?** 新加的那行 `em_setup` 输出一次运行就答了。
   现有证据说**不在** —— 所以**上机的第一件事是看那行 `printf`,不是看灯**。
2. **只有原点开关压住时,bit11 会不会置起?**(电机释放、不发指令,同时读 `6041h` 与 `60FDh`。)
   这就是 §9「原点为什么不是红的」那个岔路口 —— 若会,扫描经过原点就会误中止。
3. bit11 是不是**方向门控**的(只在朝开关发指令时置起)。
4. `2310h`/`2311h`/`2312h` 是否仍是 1/2/3(`sm_baseline.c` 已把它们当作危险项)。
5. `2300h`(输入有效电平逻辑)与接线是否一致 —— **配反了三个灯全反**。
   `sm_baseline.c` 把 `2300h` 记为 WARN 级正是这个原因。
6. 扫描中压限位会不会中止,以及**新灯与 bit11 在现场是否自洽**。

第 2 条那条诊断不用另写工具:`refreshAxisSignals()` 在 bit11 的**上升沿**会把当时的
`sw` 与 `60FDh` 三位一起 `printf` 到 stdout —— 30Hz 的面板灯可能一闪而过,stdout 会把
证据留下。**它是这条待验证问题的现场答案,不是调试残留。**

#### 追加第 7 条:bit11 的另一半可能(真机反馈"说 X 轴已撞上"引出来的)

上面六条问的都是"bit11 在什么**时候**置起",漏了一个方向:**它认的是哪一路信号**。
CiA402 把 bit11 定义成 `internal limit active`,而"内部限位"到底指硬件限位开关还是
**`607Dh` 软限位**,规范没规定死。所以候选原因多了一个:

7. **`607Dh:01`/`:02` 是不是 0/0?** 若是,则任何位置都在软限位窗口之外 → bit11 可能
   **恒为 1**,而那与"有没有开关压着"完全无关。
   诊断**不用改代码、不用 `--allow*`**:`bin/motor_test.exe` 不带参数跑一次(S0~S2,
   一个字节都不写),它会打印 `607Dh:01 负向软限位` / `:02 正向软限位` / `6064h 当前位置`
   —— 三个数放一起看就够定这件事。横幅现在也会把人往这条上引。

> 这一条的价值在于"现象相同、成因相反":第 2 条说"真有开关压着,只是原点",第 7 条说
> "**根本没有开关压着**"。两者在界面上长得**一模一样**(bit11 置起),但一个开
> `kRefineLimitWithDigIn` 就能修,另一个开着反而更糟(`60FDh` 三位恒 0 → 精判据永不成立
> → 保护没了)。所以**必须先拿到证据再翻那个开关** —— 这正是本轮把措辞改老实的原因:
> 一句"已撞上"会让人以为成因已经确定了。

  保持 `0`,要等第 2 条实测结果才开。扫描区域本来就可能正好停在一个开关上,
  用监视量去触发会白中止一趟一小时的活。

  OP 的诱因;要读就把它放进 PDO。
- **不给 `hmi` 加故障复位按钮** —— 但共享的那条 note 措辞**在两边都成立**。
  (若之后想加:约 15 行,一个按钮 + 照抄「使能」那道模态。)
- (原写着"不修 `doConnect()` 漏 `m_busy = true` 那个既有 bug" —— **后来修了**,
  因为真机反馈"勾选框勾不上"的根子就是它。见 §15 追加节的第五个坑。)

### 追加:每根轴三个限位开关 + 故障复位(同日,紧接着)

用户指出上一节那个「限位」**建模是错的**:每根轴物理上有**三个**开关输入,
不是"一个限位":

| 开关 | 含义 | 端子功能 (`2310h`~`2312h`) | `60FDh` 位 |
|---|---|---|---|
| X0 | 原点 | `2310h` = 1 | bit2 |
| X1 | 正限位 | `2311h` = 2 | bit1 |
| X2 | 负限位 | `2312h` = 3 | bit0 |

依据:[ykd2205pe_ci402.md](ykd2205pe_ci402.md) 的位定义与端子功能实测。
代码里之前那句 `2310h X1 = 正 / X2 = 负` 是**错的**(把 `2311h` 的值写成了 `2310h`),
四处全部改正:`scanwindow.cpp`(tooltip + 横幅)、`scancontroller.cpp`(两处中止文案)、
`scancontroller.h`(注释)、本文。

| 要求 | 做法 | 落在哪 |
|---|---|---|
| 每根轴三个限位信号 | 新组「限位开关」:原点 / 正限位 / 负限位,读 `60FDh` bit2/1/0 | `ScanWindow::buildLimitPanel()` |
| 加一个复位按钮,驱动器显示故障时可以复位 | 「轴信号」组第三行,跨全部列,清 `6040h` bit7 | `ScanWindow::onFaultResetClicked()` → `postFaultReset()` |
| 原点与正负限位要分开 | 原点 **绿亮不中止**,正/负限位红亮 | `LampGrid` 两块 + `ecatcmd::limit_hit()` |

#### 一个决定性的实测事实(它推翻了最初的方案)

**本机生效的 TxPDO (`1A00h`) 只有 3 项 / 10 字节**:`6041h`/`6064h`/`606Ch`。
ESI 声明里那份 12 项 / 39 字节的清单(含 `60FDh:32`)**不是生效的映射** ——
同一份文档自己写着「不要相信任何一份『出厂映射』」。

**我一开始照着 ESI 那份判,以为 `60FDh` 是可读的。** 差一点就写成一个"跑起来才发现
三个灯永远灰着"的实现。所以这次除了改正代码,还在 `ykd2205pe_ci402.md` 里给那份 39 字节
的清单**加了一个前向指针**指向实测的 10 字节表 —— 别人还会再误判一次。

于是 `60FDh` 走**两条路**:默认**只绑不补**(它本来就在映射里才绑,零副作用),
另加一个**默认关闭**的连接期开关 `setWantDigIn()` 可以在连接时补一次(仅写 RAM,
收尾还原)。界面只给一个勾选框,而且**只在未连接时可改** —— 改了不重连不生效,
不锁住就会出现"勾了没反应"。**优先走厂家上位机改一次 `1A00h` 那条零代码路径。**

#### 撞限位:收成一处,而且**今天一个比特都没改**

`(a.sw & SCAN_LIMIT_BIT)` 从前在**三处**各算一遍(`scancontroller.cpp`、
`scanwindow.cpp`、`mapcanvas.cpp`)—— 正是"分开算就会有一天两边说的不一样"。
现在统一成 `ecatcmd::limit_hit()`,在 `publish()` 里算一次,发成 `AxisTelem::limit_active`,
`SCAN_LIMIT_BIT` 这个宏**删掉了**。

发布的行为 = **今天的 bit11 单独判定**。精判据(bit11 **且** 60FDh 说正/负限位压着,
原点不算)写好了但藏在 `#define kRefineLimitWithDigIn 0` 后面,规则本身做成带参数的形式,
于是**两条分支在同一次构建里都可测**。不打开的理由是有一类配置会让它变弱
(`2310h`~`2312h` 功能码改成 0 时 `60FDh` 三位恒为 0,而 bit11 照样会因限位置起;
此时 `dig_known = true` 而精判据永不成立,保护就没了)。**先按真机实测结果决定。**

> 另一件记录在案、本轮**不改**的事:`healthProblem()` 对 bit11 **没有消抖** ——
> WKC 要连续 10 帧坏才中止,而 bit11 单帧置起就中止。文档自己写着开关脉宽要大于 10ms、
> 而输入滤波设的是 2,所以暂态是可设想的。**不投机加消抖**(20000 pul/s 下 100ms 消抖
> 要花掉约 2000 pul)。改为:在上升沿那一支**顺带 `printf` 出当时的 `60FDh`** —— 见 §13。

#### 踩的坑(与上一节那张表同源)

| 坑 | 现象 | 修法 |
|---|---|---|
| `setColumnStretch(N+1, 1)` (**同一个坑第二次**) | 凭空多出一个空列,文字被挤成一个字宽 | 列数写成枚举 `AX_NCOL`/`LIM_NCOL`,造列和拉伸**读同一个值**;⚠️ 拆成两块之后列号不再是常数 3 |
| 判据写在 `.cpp` 里 | `scan_selftest` **不编 `ecatworker.cpp`**,逻辑写在那儿就等于永远验不到 | 纯判据全部做成 `hmi/ecatworker.h` 里的 `inline`(`ecatcmd` 命名空间) |
| 测试自己写错:`dig_pos=true` 却期望"不撞" | 红了一条 —— 那一位压着本来就该算撞 | 见下 |
| `resetting` 只靠 `publish()` 往遥测里拷 | 界面**永远**看不到"正在复位…" | 复位里那两次**加锁直写** `m_telem.resetting` 才是起作用的那半,见下 |

**第四个坑值得单独说,因为它是这一轮里唯一一个"自查出来的真 bug",而且将来一定会再遇到。**

`publish()` 与 `doFaultReset()` 跑在**同一根线程**上(`run()` 里 `drainCommands` 在循环顶、
`publish` 在循环底),而复位那一整段是**阻塞**的(每轴最多 1 秒)。所以那两三秒里
`publish()` 一次都跑不到,等它跑到时 `m_resetting` 已经被置回 `false` ——
只把 `t.resetting` 做成"从成员每周期拷一份"(和 `m_busy` 一样的写法)的话,
`BusTelem::resetting` **恒为 false**,界面上「正在复位…」文案、按钮禁用、tooltip 里
"期间按钮不可用"那句承诺全是死代码。

真正让界面看见的是**复位里那两次加锁直写 `m_telem.resetting`**:界面线程是独立的 30Hz
轮询 `telemetry()`,工作线程阻塞期间它照样读得到。**两处都要**,而且删掉任何一处都会
悄悄退化成"按钮看起来没反应"。规则写下来:

> **凡是"某个阻塞命令执行期间界面要看的状态",都必须由那条命令自己加锁写进 `m_telem`,
> 不能只依赖 `publish()` 的每周期拷贝。**

⚠️ 同一条规则也说明**既有的 `m_busy` 有这个毛病**(不是本轮引入的):`doConnect()` 置
`m_busy = true`,那段注释写着"界面据此把按钮锁住, 免得点两下" —— 但连接也是阻塞的,
同样两秒内一次 `publish()` 都跑不到,所以**连接期间按钮其实不会变形态**。
这是**既有行为,本次没动**(见 §13 小瑕疵):改了会影响 `hmi` 那边同一套按钮,
属于另一件事,不该顺手塞进本轮。

#### 真机反馈:勾选框勾不上 + 一句说错的"已撞上"(同日,再追加)

两条反馈都指向同一段代码,而且**都不是"哪里写漏了",是两处思路上的错**。
记在这里的原因是它们各自会以别的样子再出现一次。

| 坑 | 现象 | 修法 |
|---|---|---|
| `doConnect()` 两条早退路径漏清 `m_busy` | 连接**失败过一次**之后 `busy` 永远是 `true` → 界面把 `onair` 当成"占着总线",于是 `m_connected` 永远为真:使能/设零点/开始扫描全亮着而底下什么都没有;勾选框 `setEnabled(!onair)` 于是再也勾不上 | `doConnect()` 拆成**壳 + 内层**:`m_busy` 只在壳里写一对(置起 / 清掉),内层七条出口一条都不管 |
| 把"连接期参数"实现成"连上了就不许改" | 人恰恰是**连上之后**看见三个灯全灰才知道要勾它,而那时框是灰的 | 永远可勾,改用"说出来":已经连上了就提示"**下次「连接」才生效**"。勾错代价为零 —— `em_require_dig_in()` 只在 `em_setup` 里读一次 |
| 横幅把"驱动器报了一位"讲成"已撞上限位" | 操作员看到的是一句**事实错误**的话,于是去处理一个不存在的问题 | 只说知道的两件事(bit11 置起 + `60FDh` 说了什么),按三种情况给三种"现在能做什么" —— 见下 |

**第二个坑的教训比它本身大**:`setEnabled(!onair)` 看着像"体贴"(防止改了不生效的困惑),
实际是把**发现问题的时刻**和**能改的时刻**拆开了 —— 而人只会在前者想到后者。
"灰掉一个控件"和"说一句为什么"之间,凡是两者都能做的时候都应该选后者。

**第三个坑是措辞**:bit11 是 CiA402 的 `internal limit active`,本机到底拿它表示什么
**还没实测过**(§13 那六条里的第 2、3 条)。所以横幅现在按三种情况说话:

| `60FDh` 的情况 | 横幅说的 |
|---|---|
| 读不到 | 分不清是原点还是限位 —— 并告诉人**怎么让它可读**(勾那个框,或用厂家上位机改一次 `1A00h`) |
| 正/负限位有一位压着 | "先手动把它走离压着的那个开关" |
