# `scan`:滑台蛇形扫描 + 逐点功率采集

控制滑台在一个矩形区域里**蛇形(逐行往返)扫描**,每到一个网格点停下来,读一次功率计,
把 `(X, Y, 功率, 时间戳)` 追加进 CSV,最后得到一张功率分布图。

它与 [hmi](hmi_click_position.md) 是**并存的两个程序**,不是一个程序的两种模式:

| | `bin/hmi.exe` | `bin/scan.exe` |
|---|---|---|
| 干什么 | 手动调试台:点哪里走哪里 | 自动采集:自己走完一个区域 |
| 面板 | 两根一维轨道 | 一块二维面板 + 热力图 |
| 会自己动吗 | 不会 | 会,而且一次一两小时 |
| 共用 | **同一个 `hmi/ecatworker.cpp` 编进来的** —— 线程模型 / 坐标零点 / CSP 插补 / 全套护栏只有一份实现 | |

**功率计型号待定**,所以这一版只有抽象接口 + 三个模拟源。真机协议定下来之后要做的
只是再写一个 `PowerMeter` 子类,状态机、界面、CSV 一个字都不用动。

它是整个程序里唯一有真逻辑的部分(网格边界、蛇形顺序、续扫的兼容性判定),
而"这一点的坐标到底是多少"错了是**静默错**:扫描照跑、数据照出,只是整片区域偏了。
所以它要能脱离 Qt、脱离总线、脱离硬件单独编出来验。

## 2. 线程模型:总线线程一个字不改

现有边界是 **`EcatThread` 独占总线,GUI 侧只经 `post*` / `set*` / `telemetry()` 与它交互**。
扫描完全落在这条边界的 GUI 一侧:

```
GUI 线程                                  工作线程 (2ms 循环, 不动)
─────────                                 ──────────────────────────
ScanController (30Hz, 时钟由外面喂)
  ├─ BusView::setTarget(axis, want)  ───▶  m_want[]  ─┐
  ├─ BusView::telemetry()            ◀──  BusTelem   │ interpolate(dt)
  └─ 状态机: Moving→Dwelling→Reading→Log             └─▶ em_csp_set_target
```

**为什么中间要有一层 `BusView`(只有四个方法)而不是直接拿 `EcatThread` 用**:
[hmi_click_position.md](hmi_click_position.md) 的「尚未验证」一节写得很清楚 ——
**hmi 的「连接」那条路一次都没在真机上跑过**。也就是说这个仓库目前**没有可用的真机回路**
来验扫描状态机。而状态机里真正会出错的是暂停/继续/中止、到位窗口、外部改目标、
续扫从哪接上这些**时序**问题,它们跟总线没关系,只跟状态机有关。
换成 `FakeBus`(自己按速度推 `pos`,能注入掉帧/故障/失能/限位),整个状态机就能
**在没有硬件的情况下跑通** —— 这就是 `scan_selftest` 干的事。

**节拍是外部喂的**(`tick(now_ms)`),不是状态机自己起定时器。理由只有一个:
单测里换一只手拨的时钟,整轮扫描就能在几毫秒内跑完。
时间一律用**单调钟**(`QElapsedTimer`)—— 墙上时间会被 NTP 和对时往回拨,
那样"停留了 200ms"可能永远不成立,扫描会卡在那一点上。

30Hz 对到位判据够用:换行一次移动要几百 ms,停留最少也有 100ms 量级。

## 3. 单位、坐标与量程

```
1 单位 = 1 圈 = 50000 脉冲     (2400h 实测值, 是可调参数 pulses_per_unit)
显示坐标 = 6064h 原始值 − 软件零点
零点     = 「连接」那一刻读到的位置, 或「设为区域中心」按下的位置
区域     = 27×27 单位, **以原点为中心** → ±13.5 单位 = ±675000 脉冲
```

### 量程必须跟着区域走(本次唯一改到 `hmi/` 的地方)

`HMI_RANGE` 原来是编译期常量 `500000`,扫描区域要 ±675000。它在 `ecatworker.cpp` 里
夹了 **4 次**(`setTarget()` 两次、`interpolate()` 两次)。直接复用会把区域边缘
**悄悄削掉** —— 最坏的一类 bug:不报错,只是永远扫不到边。

改法(**纯增量,`hmi.exe` 行为逐字节不变**):

- `m_range` 从常量变成 `std::atomic<int32_t>`,**默认仍是 `HMI_RANGE`**
- 新增 `postRange(int32_t)`,走 `m_cmds` 队列(与 `postCenter` 同一个模式)
- `hmi` 自己从不调 `postRange`,于是它拿到的永远是 500000

```
量程脉冲 = ceil((max(area_x, area_y) / 2 + 1.0) * pulses_per_unit)
         = ceil((13.5 + 1.0) * 50000) = 725000     (默认参数)
```

`+1.0` 的余量是给**手动对位**用的:扫描区域之外还能手动走一点。
`range_pul` **不暴露给操作员**,永远按区域自动算 —— 它是个会因为手滑而把区域边缘
悄悄削掉的量,让人去填它没有任何好处。

> **`postRange` 有个必须绕开的陷阱。** `interpolate()` 是**先夹 `m_tgt`、再用 `m_tgt`
> 算 CSP 目标**的。所以如果把量程**改小**、而滑台此刻正停在旧量程的边缘外,那一夹就会
> 把 `m_tgt` 拽回来 —— **等于凭空产生一次运动,而且是没人按过任何按钮的运动**。
> 所以 `doRange()` 的规矩是:**放大无条件允许;缩小只在新范围装得下所有轴的当前
> `m_tgt` 时才允许,装不下就拒绝**并提示"先把滑台走回区域内"。绝不为了迁就新量程
> 去改 `want`/`tgt`。

## 4. 网格与蛇形

```
n     = floor(area / res) + 1        // 27 / 0.5 + 1 = 55
span  = (n - 1) * res                // 27.0
坐标[i] = -span/2 + i * res          // -13.5 .. +13.5, 共 55 个
```

`area / res` 除不尽时取 `floor` 并**把网格居中**(此时 `span < area`),
于是永远**不会越出区域** —— 宁可少扫一点也不扫到框外去。

轴 0 = **X**(行方向,快轴),轴 1 = **Y**(列方向,慢轴)。默认蛇形(逐行往返),
也可以改成每行同向。第一行的方向由「起始方向」定。

> **一个很有用的性质:蛇形里每一步只动一根轴。** 行内走 X、Y 不动;到行尾时下一个点
> 就在下一行的同一列上,于是 X 不动、只有 Y 进一格。稳态下**不会出现两轴同时走的斜线** ——
> 唯一一次斜着走是「从当前位置到第一个网格点」那一步(以及续扫/重测时)。
> 这既让时间估算好算(每步要么是 `res` 的距离、要么是行尾一格 `res`),
> 也让"到位"判据更干净。

### 时间估算

`estimatePerPointMs()` 是**线性**的:

```
移动   = res * pulses_per_unit / speed * 1000 = 25000 / 20000 * 1000 = 1250 ms
每点   = 移动 * 1.30 + settle + dwell + 50 * samples
       = 1625 + 100 + 200 + 50 = 1975 ms
全程   = 3025 * 1975 ms ≈ 100 分钟
```

`* 1.30` 是给**进近段减速**留的粗估,`50 * samples` 是采样本身占位
(模拟源是 0,真机未知)。界面上会明说这是线性估计、**实际更长** ——
不写这一句的话,跑起来比预计慢 20% 就会被当成"卡住了"。

## 5. 到位判据

`AxisTelem::at_target` 只是 `want == tgt`(`ecatworker.cpp`),那是**插补器自己走完了**,
**不等于实际位置到了**。所以判据是**两个都要**:

```
到位(i) = telem.ax[i].at_target                     // 插补目标已到终点
       && |telem.ax[i].pos - want_i| <= pos_tol     // 6064h 实测也在容差内
```

并且要**连续 `settle_ms`(默认 100ms)成立**才算稳定 —— 单帧瞬时满足可能在高速
掠过时误判。窗口一旦被打破就**重新计时**。

`pos_tol` **由步长推出来,不暴露给操作员**:固定 50 pul 在 25000 pul 的步长下是 0.2%
(合适),但有人把步长调到 500 pul 时就变成"允许偏 10% 个格子"(不合适)。
所以按步长取 1/20,并夹在 `[50, 步长/4]` —— 默认参数下是 **1250 pul**。

**没有单独的 `Settling` 状态**:稳定窗口就长在 `Moving` 里,界面想问"现在是在走
还是在等稳定",用 `settlingNow()` 读。让状态机多一个状态、多一套进出条件,
那些状态迁移分支是纯粹的自找麻烦。

## 6. 状态机

```
Idle ──开始──▶ Moving ──到位且稳──▶ Dwelling ──停够──▶ Reading ──采到──┐
                 ▲                                                      │
                 └──────────────── 下一个点 ◀──────────────────────────┘
                 全部走完 ▶ Done

Paused / Aborted 可以从上面任意一个状态进来, 且**立刻生效**。
```

- **Preflight**(缺一不可,全过才动):在 OP · 已使能 · 两轴 `mirror_ok` · 功率计已开 ·
  CSV 可写 · 参数合法 · 区域半宽 + 余量 ≤ 量程 · 点数 ≥ 1 且 ≤ 200000
- **Moving**:`setTarget(0, x_pul)` + `setTarget(1, y_pul)`(显示坐标),等两个轴都到位
- **Dwelling**:停 `dwell_ms`
- **Reading**:发一次 `requestReading()`,等信号回来(异步)。超时(默认 2s)
  或 `readingFailed` → 该点标为失败,CSV 里功率列写空、带一列错误原因,
  **扫描继续**(一个点读不到不该毁掉整轮)
- **Log**:追加一行 CSV + `flush` + 刷新热力图 → 下一个点

**`samples_per_point > 1`** = 到点后连采 n 次取平均。代价是每点多 n 倍**读数时间**
(真机串口一次几百 ms 时这项很贵),不是塞在停留期里白拿 —— 停留期是"等机械稳定",
两件事不该混。

### 暂停 / 继续 / 中止

- **暂停**:立即 `postStop()` 冻在当前位置(**保持保持力矩,不卸力**),
  当前点标记为未完成。**响应是立即的** —— 不会出现"按了暂停还要等一分钟这一行走完"。
- **继续**:**重新走向该点并重新采样**,所以不会写进半点数据的半成品。
- **中止**:同样冻住,状态转 `Aborted`,**已完成进度留在 CSV 里**。

> 暂停/中止走的是 hmi 的「停止」语义:**故意不写 `6040h=0x0000`**,那是卸力,
> 滑台会因自重下滑。

### 自动中止(每个 tick 都查)

扫描是**一次一两小时、没人看着**的长动作,所以下面这些在**每个 tick** 都查,
命中就立刻自动中止(而不是继续默默往下扫,把一整轮数据全采在错的地方):

| 条件 | 备注 |
|---|---|
| 掉出 OP / 连接断了 | |
| 任一轴 `6041h` bit3 故障 | `EcatThread` 已经会冻结目标,但扫描必须停下来 |
| 任一轴 `6041h` bit11 撞硬件限位 | `2311h`/`2312h` 实测 = 2/3(**X1 = 正限位 / X2 = 负限位**)。**这一条最可能真触发** |
| WKC 连续 10 帧不足 | 拔网线就是这个表现 |
| 任一轴丢帧(`mirror_ok` 掉)或掉使能 | |
| 有人从**旁路**改了目标 | 见下 |
| 走到位的最后期限 | `max(5000, 距离/速度*3 + 3000)` 封顶 120s —— 卡住/被夹住时的兜底 |
| CSV 写失败 | 宁可停,也不要默默少采几千点 |

中止时弹**红色横幅 + 模态框** —— 正是因为它无人值守,一闪而过的提示等于没提示。

> **`externalWantChanged()` 的两个坑,都是单测逼出来的。**
>
> 1. `setTarget()` → `publish()` 之间差一个 2ms 周期,所以下发之后不能立刻比 ——
>    那样会把自己当成外部干预。于是有一道"等它出现"的确认门(`m_want_ok`)。
>    但这道门**可能永远开不了**:如果在我们自己的值出现**之前**就有别人改了目标,
>    扫描会跟着别人的目标一路走下去,直到 120s 的移动期限才停。
>    所以加了 `WANT_CONFIRM_MS = 200`:下发 200ms 内没看到自己的值,就判定为外部干预。
> 2. **暂停时目标本来就"不是我们下发的那个了"** —— `postStop()` 把它冻在当前位置
>    (`want := tgt`),而那正是我们要的。不在暂停时放行的话,**一按暂停就会被自己
>    判定成"有人从别处改了目标"然后自动中止 —— 暂停按钮变成了中止按钮。**

## 7. 功率计接口(异步)

真机很可能是串口/SCPI,一次往返几百毫秒。**同步接口会把整个界面冻在那儿**,
而扫描一次要采几千个点,那就是几千次卡顿。所以是**请求 + 信号**:

```cpp
class PowerMeter : public QObject {
   Q_OBJECT
public:
   virtual QString kind() const = 0;
   virtual bool    open(QString *err) = 0;
   virtual void    close()            = 0;
   virtual void    requestReading()   = 0;   // 非阻塞; 恰好回一次 ready 或 failed
   bool isOpen() const;                      // Preflight 要问这一句
signals:
   void readingReady (double watts);
   void readingFailed(const QString &err);
};
```

三个模拟实现(**这一版全部做完**):

| 实现 | 用途 |
|---|---|
| `ManualMeter` | 界面上现填一个数,每次采回来都是它。用来手对流程 |
| `RandomMeter` | 基值 + 噪声,可调延迟。用来压热力图的配色与刷新 |
| `ScriptMeter` | 读一个每行一个数的文本文件,**每次请求取下一行**。可以配延迟 |

`ScriptMeter` 是没有功率计时最有用的一个:**它能让整条流水线(状态机 → CSV → 热力图 →
断点续扫)完整跑一遍,而且数据是可预测、可断言的**。

三个实现都用 `QTimer::singleShot(...)` 把 `emit` **挪出调用栈**
(`ManualMeter` 是 `0`,另两个是那个可调的 `delay_ms`,默认 20ms)。
这一点不是装饰:如果 `requestReading()` 直接 emit,状态机的 `readingReady` 槽会在
`requestReading()` 内部**嵌套执行** —— 状态机正在 Reading 里发请求,槽又把它推到下一步,
于是所有"进入某状态后紧接着做的事"都会踩到自己。延时投递之后,模拟源与真机
(串口回来了才 emit)的行为**完全一致**,状态机只需要考虑一种时序。

**不做工厂 / 注册表 / 配置文件**:一个基类 + 三个子类 + 界面上一个下拉框的 `switch`
就是终态。也不支持并发请求 —— 一个时刻只允许一个未决请求,状态机才能有确定的 Reading。

## 8. CSV:它本身就是进度文件

**不另存 sidecar 状态文件** —— 边采边写的 CSV 里已经有全部信息,再维护一份"扫到哪了"
就是两份真相,迟早对不上。

```csv
# scan v1
# area_x_unit=27.000000 area_y_unit=27.000000 res_unit=0.500000 pulses_per_unit=50000.000000
# speed_pul_s=20000 dwell_ms=200 settle_ms=100 samples=1 serp=1 start_pos=1
# range_pul=725000 pos_tol_pul=1250 zero_epoch=1
# started=2026-09-17T10:00:00
index,ix,iy,x_unit,y_unit,x_pul,y_pul,watts,ok,flags,pos_x_pul,pos_y_pul,spread_x_pul,spread_y_pul,unix_ms,elapsed_ms
0,0,0,-13.5,-13.5,-675000,-675000,0.001234,1,,−675000,−675000,60,45,1758096000123,412
```

- **每采一点追加一行 + `flush`** → 中途崩了/断电了,已采的数据一行不丢
- 列名一律 ASCII、数值用 C locale 格式化(`%f`/`%lld` 本来就是)—— 中文列名在中文
  Windows 上会被 Excel 按 GBK 打开成乱码,而某些区域设置会把小数点变成逗号、
  把整列解析搞崩
- `watts` 用 `%.9g`,**采不到时留空而不是写 0** —— 0 是一个合法的读数,
  拿它当"没采到"的哨兵,以后就没法区分"这儿真的没有功率"和"这儿没读上"了
- **`ok` 与 `flags` 是一对**:`ok=0` 时 `flags` 写原因(如 `timeout`),`ok=1` 时留空。
  单点重测写 `flags=retest` —— 重测**不是一个单独的列**,而是与失败原因共用这一列
  (两者可以同时成立,那时用 `|` 连起来,如 `timeout|retest`)。热力图与统计一律取
  **该格最后一行**
- `pos_*_pul` 是**采样那一刻的实测位置**,和网格点的理论值放一起就能看出这一点的
  定位误差;`spread_*_pul` 是稳定窗口内 `pos` 的极差:**振没振,在这儿看得见**

### 断点续扫

打开一个已有 CSV → 读表头**校验几何参数一致**(区域 X/Y、分辨率、每单位脉冲数;
不一致就拒绝并**指出哪个变了**)→ 读所有 `(ix,iy)` → 剩下没采的补扫 →
**继续往同一个文件追加**。

速度/停留/采样次数这些**不影响几何**的随便改,不该拦。

读回数值还有一个必须做的理由:不做的话,续扫打开的局面是**前半场的数据在文件里、
在图上却是空的** —— 而这张图正是这个程序存在的理由。

### 零点世代(`zero_epoch`)

每次「连接」或每次「设为区域中心」,**零点世代 +1**,写进 CSV 表头。

为什么需要它:连接时 `tryInitOrigin()` 会把零点重设为"当时所在的位置"。
所以断线重连之后,**同一个显示坐标指的可能已经是另一个物理位置** ——
那下半场的数据会和上半场拼在一张图上,而图上不会有任何异常的样子。

续扫时世代对不上**不是错误,是"要你确认一下"**:界面弹出一个说清差异的模态框,
确认后才继续。

### 单点重测

在画布上 **Shift + 左键**选中一格 → 点「重测选中点」→ 走回那一点再采一次,
**追加一行**(带 `flags=retest`),不改动别的格子。热力图与统计取**该格最后一行**。

> **`ScanLog::beginAppend()` 会先把没写完的那半行切掉。** 追加写是掉电留下的残行是
> **正常情况**,不是异常情况;而 `QIODevice::Append` 会把下一行**粘在那半行后面**,
> 于是产生一行字段错位的垃圾,并且**它之后的所有行都跟着错位**。
> 切回最后一个 `'\n'` 是唯一不丢东西的做法 —— 那半行按定义就是没写完的。

> **跑完之后日志不关。** "刚跑完看一眼图、随手重测几个可疑点"是最自然的用法,
> 关掉之后重测就没地方追加了。中止也一样不关。

## 9. 二维面板与配色

`MapCanvas` 是 hmi 那两条一维轨道的二维版本,语义照搬:
**实心点 = `6064h` 实测位置,橙色 = `want`(点击给的),绿色虚线 = `tgt`(本周期下发的)**。
多出来的一层是热力图。

- **可视量程**自动算(区域半宽 × 1.12),网格 + 每 5 单位一条淡线 + 零点十字
- **区域框**:超出量程时**标红并写明"边缘会被静默夹掉"**
- **扫描路径预览**:开始前画出将要走的蛇形折线
- **当前点高亮** + 剩余点数 / 预计剩余 / 悬停读数(单位 + 脉冲)
- **左键 = 手动定位**;**Shift + 左键 = 选中该格**;**扫描进行中一律吞掉**,只留一行提示

### 色标:单色相顺序色标,OKLab 插值

蓝色的 13 级(`#0d366b` → `#cde2fb`),取自仓库里既有的强调色 `#4a9eff` 那一族,
于是新程序看起来还是同一个程序。取色是**在 OKLab 里插值**的,**不是 sRGB** ——
sRGB 插值在中段会发灰、发脏,一眼就能看出色带分节。

顺序色标该过的那一关**跑过,过了**:明度严格单调、色相跨度 4°(不分叉成两种颜色)。
(同一份校验里"相邻色阶 ΔL 太小"那条是 FAIL,但那是给**离散色块**用的判据 ——
这里色标是连续插值的,相邻两级的差别本来就不该看得出来,所以不适用。)

暗色底上的方向是 **暗 = 小,亮 = 大**,与"近零应该退回底色"是同一条规则:
亮的地方就是功率大的地方。代价是最小值那一端跟底色对比度低(1.5:1),
于是**必须有数字兜底** —— 右侧色标条上写着锁定的最小/最大值,鼠标移到格子上也出数。
**热力图永远不能只有颜色。**

> **色阶是锁定的,不跟着数据实时变。** 这一点是刻意的:边采边自动缩放的话,
> 每来一个点整张图的颜色都会重排一遍,操作员看到的"渐变"其实只是自己在动 ——
> 那种图不能用来判断任何事。所以是两个数字(默认 0..1)加一个「按数据定标」按钮,
> 要改是**显式**改一次。超出范围的格子夹到两端,数值仍可在悬停里读到。

**三种状态在画面上分得清清楚楚,不靠深浅去猜**:

| 状态 | 画法 |
|---|---|
| 还没扫到 | 只有底色的空位 |
| 扫到了、读数失败 | **红框** —— 那才是要人去处理的一格 |
| 扫到了、有数 | 顺序色标 |

> **实测位置那个点刻意是白的,不是 hmi 的蓝色。** 因为这块画布上蓝色已经是**数据**了
> (热力图就是蓝色色标)。位置标记再用蓝色,就变成"一个中值的格子和滑台现在在哪儿"
> 分不清 —— 而这两个意思完全不同。白色在所有色阶上都最跳,也正是"现场光标"该有的样子。
> hmi 那边画布上没有数据,所以它用蓝色没问题,不必跟着改。

### 刷新与缓存

热力图是一张 `nx×ny` 的 `QImage`(**一格一像素**),放大时用最近邻
(`SmoothPixmapTransform = false`)—— 一格就是一个方块,不该被糊成渐变。
3025 个像素比一次 `QPainter` 填充还便宜,所以每帧重建,不值得为它做脏标记;
只有扫描路径是跟几何走的,才做几何变动的缓存。

## 10. 安全护栏(与 hmi / CLI 逐条对应,一条都不许退化)

| 场景 | 行为 |
|---|---|
| 程序启动 | **一个字节都不写总线**(只会 `postRange` 一个本地成员) |
| 「连接」 | `em_open` → `em_setup(...,1)` → `em_enter_op`。进 OP 开始发帧但**不发使能**;点之前弹模态说清它写什么 |
| 「使能」 | **唯一让电机带电的按钮**。每次点击都弹模态确认(人在设备旁、手放在物理急停上),**没有持久勾选、不自动使能** |
| 「开始扫描」 | 过 Preflight;另外弹一个把**区域 / 网格 / 点数 / 预计时长 / 数据流向**再报一遍的模态 —— 区域填错一个数字就是一头撞上限位 |
| 暂停 / 中止 | 目标冻在当前位置,**保持保持力矩**(故意不写 `6040h=0x0000`) |
| 扫描中 WKC 掉 / bit3 故障 / bit11 撞限位 / 掉出 OP | **自动中止** + 红色横幅 + 模态 |
| 扫描中改参数 / 换取样源 | 控件**全部锁住**。几何改到一半的扫描没有意义 —— 落进 CSV 的 `(ix,iy)` 和实际位置就对不上了 |
| 关窗 / 断开 | **先中止扫描** → 失能 → 还原 PDO 映射 → 降 `PRE_OP` → 关网卡 |
| 收尾未能确认失能 | **模态告警**,要求立即断驱动器动力电源(CLI 退出码 10) |
| 全程不写 | `2102h`(EEPROM)、`607Dh` 软限位、`2400h/2408h/2409h/2201h` |

> **收尾顺序不能反。** `disconnectAndStop()` 是**先中止扫描再断总线** ——
> 反过来的话状态机会看到"掉出 OP",然后作为一个**异常**去自动中止,
> 一条本来正常的收尾路径会变成红色告警。

> **启动时不弹任何对话框。** 每次启动都要点一次的弹窗只会被条件反射地关掉;
> 真正危险的三个动作各有自己的模态确认。常驻的一行须知比启动弹窗看得见。

## 11. 构建

`scan` 与 `hmi` 用**同一个 preset**(`hmi-qt-ucrt64`),所以**不改 preset、不加第二条
configure 命令**:

```cmake
option(EC_BUILD_SCAN "构建扫描采集程序 (需要 Qt6 + C++ 编译器)" ${EC_BUILD_HMI})
if(EC_BUILD_SCAN)
  add_subdirectory(scan)
endif()
```

`${EC_BUILD_HMI}` 作默认值 ⇒ 现有的 `cmake --preset hmi-qt-ucrt64` 一次把两个都编出来;
而只想编 hmi 的人可以 `-DEC_BUILD_SCAN=OFF`。

```bash
cmake --preset hmi-qt-ucrt64
cmake --build out/build/hmi-qt-ucrt64            # 全部
cmake --build out/build/hmi-qt-ucrt64 --target scan
```

产物:`bin/scan.exe`、`bin/scan_selftest.exe`。

`scan_selftest` **不链 SOEM 也不链 Widgets**(只用到 `Qt6::Core`)——
它几秒钟就能跑完,不需要设备、不需要网卡、不需要界面:

```bash
PATH="/c/msys64/ucrt64/bin:$PATH" ./bin/scan_selftest.exe
# ... 143 passed, 0 failed
```

> **`scan_selftest` 被钉在 `-O1`,这是绕开一个工具链 bug,不是偷懒。**
> 本目标在 `-O2`/`-O3` 下链接必然失败 —— `collect2: ld returned 5 exit status`
> (也见过 1/9/116),`ld` 自己的报错一个字都没有,输出文件被建出来但内容是**一片零**。
> `bin/scan.exe` 与 `bin/hmi.exe` 在同样的 `-O3` 下链接正常。
>
> 症状**只跟优化级别有关**,与代码写法无关:`-O0`/`-O1` 成功,`-O2`/`-O3` 失败;
> 单独 `ld -r` 同一组目标文件是成功的,只有完整链接才炸;
> `-ffunction-sections`、`-fno-asynchronous-unwind-tables`、`-fno-ipa-icf` 都试过,没用。
> 所以这是 **GCC 16.1.0 (MSYS2 UCRT64) 这一套 `ld` 自己的问题**,不是本仓库代码的问题。
> 出厂的 `bin/scan.exe` 保持 `-O3` 不变 —— 为一个自检程序的毛病去动 ship 出去的东西
> 是拿芝麻换西瓜。**GCC/binutils 一升级就可以把那行删掉**,然后重跑一遍自检确认。
