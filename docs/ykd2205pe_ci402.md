# YKD2205PE EtherCAT 驱动器速查

研控 (www.yankong.com) EtherCAT 闭环步进/伺服驱动器。CoE + CiA 402。
电源 24~50 VDC、5A；100BASE-TX；DC 同步 250µs~4000µs。
SM2 = RxPDO、SM3 = TxPDO。站号由拨码 SW1~6 设定 (0~63)，存于 0012h-0013h。
**注意**: 拨码站号对 **pysoem** 不可见 —— CoE 0012h 对象实测缺失 (SDO
"object does not exist")，pysoem 封装的旧版 SOEM 也不暴露 ESC 别名寄存器。
因此本框架(python 链) **按 EtherCAT 总线线序 (从站 0/1) 定位轴**。

> 若要真正按手册读取该 0012h-0013h 别名寄存器，须用原生 SOEM：见下文
> 「读取拨码站号」，工具 = [`aliasinfo/`](../aliasinfo/)。

> 下表提取自 `../YKD2205PE.pdf`，供写代码时对照，不用反复翻 PDF。

## 读取拨码站号 (原生 SOEM)

拨码站号存于每台从站 ESC 的 *Configured Station Alias* 寄存器 **0012h-0013h**
(由 SW1~6 在驱动器上电时写入)，普通 EtherCAT 主站启动时就靠读它识别/寻址。
python 链 (pysoem) 读不到这个寄存器，所以仓库里放了一个原生 SOEM 读取器工具
[aliasinfo](../aliasinfo/aliasinfo.c) (自有顶层工程，引用下载的 SOEM)：SOEM 在
`ecx_config_init()` 里已对每台从站 FPRD 0x0012，结果在 `ctx.slavelist[i].aliasadr`，
该工具只把它打印出来 (只读、不进 OP)。

构建并运行 (需要 VS/CMake；在仓库根配置顶层工程，`SOEM` 作为子工程):

```bash
cmake -S . -B build                 # 首次/改 CMakeLists 后重跑一次
cmake --build build --config Release --target aliasinfo
build/aliasinfo/Release/aliasinfo.exe '\Device\NPF_{GUID}'
```

输出形如 (位置 = 0-based 总线线序，与 python 链 `--pos` 一致):

```
2 台从站。位置为 0-based 总线线序 (主站起数)。
  位置    序号   配置地址     别名0012h      厂商ID      产品码  名称
  -----  -----  ------  ------------  ----------  ----------  ----
    0       1   0x0001        5 (0x0005)  0x00000994  0x00003000  YKD2205PE
    1       2   0x0002       17 (0x0011)  0x00000994  0x00003000  YKD2205PE
```

注意:
- 别名 = 0 表示拨码=0 或未启用，同型号多台仍按总线位置区分。
- 拨码站号是驱动器**上电时**读的，改动拨码须断电重启才生效。
- 该工具用 Npcap 独占网卡，运行期间勿同时跑 python 链的 pysoem 脚本。

## 状态字 6041h (位)
| 位 | 名称 |
|---|---|
| 0 | Ready to switch on |
| 1 | Switched on |
| 2 | Operation enabled |
| 3 | Fault |
| 10 | Target reached |
| 12 | Set-point acknowledge (PP) |

> 注意: 该驱动器状态字低 4 位用 **0000/0001/0011/0111** 编码，并非标准
> CiA 402 的 0~7。代码里用位判断 (`& 0x04` = 使能、`& 0x08` = 故障) 而非数值比较。

## PDO 映射 (默认)
| 对象 | 默认内容 |
|---|---|
| 1600h RxPDO0 | 6040h (控制字) |
| 1601h RxPDO1 | 空 |
| 1A00h TxPDO0 | 空 |
| 1A01h TxPDO1 | 空 |
| 1C12h RxPDO 分配 | 1600h |
| 1C13h TxPDO 分配 | 1A00h |

> 默认 TxPDO 为空，故本框架默认用 **SDO 控制 + PreOp/SafeOp** 方式，
> 不依赖 PDO 周期数据，也避免了空 TxPDO 可能导致无法进入 OP 的问题。

## 数字输入与限位 (60FDh / 2004h / 2310h)

输入端子 X0~X3 的功能由 **2310h~2313h** 配置（值：1=原点, 2=正限位, 3=负限位,
4=停止, 5=急停, 6=MF, 7/8=探针1/2, 9~12=用户自定义）。限位/原点开关的**逻辑状态**读
**60FDh**（已含 2300h 电平反转与功能映射后的结果）：

| 位 | 含义 |
|---|---|
| Bit0 | 负限位 |
| Bit1 | 正限位 |
| Bit2 | 原点开关 |
| Bit16 / Bit17 | 探针 1 / 探针 2 |

- **2004h**：原始 X0~X4 输入电平（Bit0~Bit4），反映物理端子状态（常开/常闭由 2300h 决定）。
- **2204h**：超程停车方式（0=停止, 1=急停），软限位越界时驱动器动作。
- **2300h**：输入有效电平逻辑（Bit0~Bit3 = X0~X3，1=电平反转）；**2330h~2333h**：X0~X3 滤波时间。

### 回零方式 (6098h)

| 值 | 动作 |
|---|---|
| 17 | 反方向找**负限位**，减速停止后退一段，再慢速反向找负限位停下 |
| 18 | 正方向找**正限位**，减速停止后退一段，再慢速正向找正限位停下 |
| 24 | 正方向找**原点开关**，碰到正限位反向继续找原点 |
| 29 | 反方向找**原点开关**，碰到负限位反向继续找原点 |

6099h:01 = 找开关(快)速度、6099h:02 = 找零(慢)速度（越小精度越高）；607Ch = 原点偏移。

## 设备导入验证工具 slide_verify (原生 SOEM)

滑台设备接入/上电 EtherCAT 总线时的**导入验证**:扫描总线 → 逐台读取身份与关键
CiA402 对象 → 判定是否为受支持的 YKD2205PE 滑台驱动器,逐项给出 PASS / WARN /
FAIL,最后汇总并返回退出码。**只读工具**:不进 OP、不写 6040h 控制字、不做使能
序列、不动电机。验证深度:PRE_OP 读对象(主),随后可选尝试 SAFE_OP(失败记
WARN 不致命)。

**源码位置与工程结构**(本仓库自有代码,独立于下载的 SOEM):

```text
EC_CPP/
├─ CMakeLists.txt        # 顶层工程: add_subdirectory(SOEM) + add_subdirectory(slide_verify)
├─ slide_verify/         # 本工具 (slide_verify.c + CMakeLists.txt)
└─ SOEM/                 # 下载的第三方库, 未改动
```

构建(在仓库根,顶层工程会引用并编译 SOEM 库,但不构建 SOEM 自带 samples):

```bash
cmake -S . -B build                  # 首次/改 CMakeLists 后重跑一次
cmake --build build --config Release --target slide_verify
build/slide_verify/Release/slide_verify.exe '\Device\NPF_{GUID}'
```

不带 `ifname` 时仅列出可用网卡。

**识别集合**(与代码 `sv_is_ykd_slave()` 一致):厂商 `0x0994`,产品码
{`0x2000`, `0x3000`} 双收。位置 = 0-based 总线线序(与 python 链 `--pos`、aliasinfo
一致)。

**输出流程**:
1. 身份表(位置 / 序号 / 配置地址 / 别名0012h / 厂商ID / 产品码 / 修订 / 序列号 / 状态 / 名称);
2. 逐台身份判定(是否 YKD、是否达 PRE_OP);
3. 每台 YKD 的 PRE_OP **对象级验证**(逐对象 PASS/WARN/FAIL + 读数:状态字低4位/
   Fault位 bit3/到位 bit10、操作模式名 1/3/6/8、实际位置/速度等);
4. 可选 **SAFE_OP 探针**(进不去记 WARN 不致命;默认空 TxPDO 是正常诱因);
5. 汇总表 + 退出码。

**对象校验矩阵**(表驱动 `sv_objs[]`,加对象只改表不动码):

| 对象 | 角色 | 判定 |
|---|---|---|
| 6041h 状态字 / 6060h / 6061h / 6064h / 606Ch | **必需** | 缺失或超时 → FAIL;Fault 位=1 / 未知模式 / PRE_OP 下仍有速度 → WARN |
| 607Ah / 6081h / 6083h / 6084h / 60FDh / 60FEh | **可选** | 缺失 → WARN;读出仅显示 |

**退出码**:

| 码 | 含义 |
|---|---|
| 0 | 通过:至少 1 台 YKD 且全部 PASS |
| 1 | 用法错误 / 初始化失败(网卡打不开、Npcap 被独占、需管理员) |
| 2 | 空总线(config_init 未发现从站) |
| 3 | 存在 YKD FAIL(必需对象缺失/超时、YKD 未达 PRE_OP) |
| 4 | 无 FAIL 但含 WARN(可选对象缺失、未达 SAFE_OP、未知模式、混挂非 YKD) |
| 5 | 有从站但一台 YKD 都没有(环境不匹配) |

> 想干净退出 0,就只在总线上挂 YKD2205PE 且必需对象全部可读。别名=0 不判 FAIL,
> 同型号多台按总线位置区分。

**注意**:与 aliasinfo / python 链 pysoem 一样独占 Npcap 网卡,勿同时运行
(docs 顶部的网卡独占提醒同样适用)。

## 带动作验收验证工具 slide_motion (原生 SOEM)

`slide_verify` 证明的是「驱动器能被识别、能读」。它**刻意**不进 OP、不写 6040h、
不动电机, 所以参数错、电子齿轮错、电机相序反、编码器方向反、限位接反这些故障
在它眼里全是 PASS —— 只有让轴真的动一次才暴露。

`slide_motion` 就补这一段:参数基线与漂移比对 → CiA402 使能状态机 →
相对微动并校验编码器反馈的行程/方向/闭环归位。

**默认不动**:不给 `--allow-motion` 时全程只读, 一个字节都不写; 移动还额外需要
`--allow-jog` 与一次交互确认。它走 **SDO + PRE_OP/SAFE_OP**, 不开 OP、不改 PDO
映射 —— 因为 PP 模式的速度规划器本来就在驱动器内部, 不需要周期数据。

阶段:`S0` 身份门(只读) → `S1` 参数基线(只读) → `S2` OP/DC(**本版未实现**)
→ `S3` 使能状态机 → `S4` 微动与反馈闭环 → `S5` 收尾(无条件执行)。

> 退出码与 `slide_verify` 不同, 且多一个 **10**: 收尾后回读 `6041h` 仍报
> Operation enabled, 即**电机可能仍带电** —— 它覆盖其它所有码。

**完整设计、安全须知、微动判据、退出码与真机实测记录**:
[docs/slide_motion_verify.md](slide_motion_verify.md)。

示例基线:[baseline_ykd2205pe.ini](../baseline_ykd2205pe.ini)。

> **关于 2401h 最大电流**:上表记的默认值是 5000 mA, 但现场两台实测均为
> **2000 mA**。以现场读数为准 —— 这正是需要基线文件的原因, 手册默认值与实际
> 整定值可以不同。

## 状态机切换专项验证小程序 sm_state / sm_pdo (原生 SOEM)

`slide_motion` 的 S3 用的是 **SDO + PRE_OP/SAFE_OP**, 实测在出厂配置下到不了 ——
空 TxPDO 让从站以 AL `0x001E` 拒绝 `PRE_OP → SAFE_OP`, 而 PRE_OP 下 CiA402 状态机
根本不响应 `6040h` (论证与实测见
[slide_motion_verify.md](slide_motion_verify.md) §6)。这两个小程序专门把这件事单独
拎出来验:

| | `sm_state` | `sm_pdo` |
|---|---|---|
| 控制字怎么发 | **SDO** 写 `6040h` | **RxPDO 过程数据**里的 `6040h` |
| 状态字怎么读 | SDO 读 `6041h` | **TxPDO 过程数据**里的 `6041h` (+ 步末 SDO 交叉核对) |
| AL 状态 | PRE_OP / SAFE_OP | SAFE_OP / **OP** |
| 写 PDO 映射 | 不写 | **写** `1A00h`/`1C13h` (仅 RAM, 默认还原) |
| 需要授权 | 无 (只写 `6040h`) | `--allow-pdo` |

两者的切换序列完全同构 —— 上行 `0x0000 → 0x0006 → 0x0007 → 0x000F`,
`--hold` 观察, 下行 `0x0007 → 0x0006 → 0x0000`。断言掩码都是 **`0x000F`**:
手册 `6041h` 位表未定义 bit6, 所以"未使能"不区分标准里的
Not ready / Switch on disabled (拿 bit6 去判会误报)。**两者都不发运动指令**,
不写 `607Ah`/`6060h`/软限位; 但第 3 步之后电机通电有保持力矩。

### sm_pdo 为什么必须写 PDO 映射

出厂 `1A00h` (TxPDO0) 是**空的** → SM3 长度为 0 → 从站拒绝 SAFE_OP。
要验证 PDO 路径, 这个前置条件绕不过去。边界收在:

- 只写 **RAM**, **从不写 `2102h`** (EEPROM) —— 掉电即回出厂空 TxPDO。
- 默认跑完**还原**成运行前快照; `--keep-mapping` 才保留; `--no-map` 整个跳过
  (此时若映射不合期望, 直接以退出码 4 拒绝)。
- 默认只往 TxPDO **追加 `6041h`** 一项, 已有映射项原样保留。
- **偏移证不出就拒绝** (退出码 4): `6040h`/`6041h` 在过程数据镜像里的字节偏移
  必须能从映射表严格推出; 不猜。写错字段可能凭空下位指令。
- `6040h` **不经 SDO 写** —— 它就是被测变量。唯一的 SDO 写入口只用于映射对象与
  `--reset-fault` 的故障复位。

```
sm_pdo [网卡] [选项]
  --allow-pdo           允许写 PDO 映射并进 OP。不加则只读快照 (退出码 0)。
  --axis N              选哪根轴 (总线位置, 0 起)。默认第一台 YKD2205PE。
  --no-map              不写 PDO 映射 (要求映射已合法, 否则退出码 4)。
  --keep-mapping        跑完保留改过的映射 (默认还原)。
  --state op|safe-op    跑到哪一级 AL 状态, 默认 op。
  --dc                  配置分布式时钟 (自由运行进不去 OP 时试它)。
  --cycle US            DC 同步周期, 默认 1000 (范围 250~4000)。
  --reset-fault         允许清故障 (进 OP 后经 PDO 推 0x0080)。
  --allow-other-slaves  总线上还有别的从站时也继续 (它们留在 PRE_OP)。
  --hold MS             停在 Operation enabled 的观察时长, 默认 500。
  --tmo MS              单步等待超时, 默认 1000。
  --ifname=GUID         覆盖写死的网卡。
```

退出码: **0** 全 PASS / **1** 用法或初始化失败 / **2** 无从站或无目标轴 /
**3** 有 FAIL / **4** 安全护栏拒绝 (未写任何东西) / **5** 进不去 SAFE_OP 或 OP /
**6** 过程数据未落地 (WKC 持续偏短) / **10** 收尾后 `6041h` 仍报 Operation enabled
(**电机可能仍带电**, 覆盖其它所有码)。

`--state safe-op` 只验证"补完映射后 AL `0x001E` 是否消失", 不进 OP、不写控制字。

> 无授权直接跑 `sm_pdo` 是**纯只读**的: 它会打印 `1A00h` 计数、`SM3` 长度与
> `6041h` 当前值 —— 预期能看到 `1A00h` = 0 项、`SM3` 长度 = 0。这就在不写任何
> 东西的前提下复现了上面那条根因。
