# YKD2205PE EtherCAT 驱动器速查

研控 (www.yankong.com) EtherCAT 总线型步进驱动器。CoE + CiA 402。
开环步进(适配 42 两相开环电机)；电源 DC 24~50 V；**最大输出电流 2 A**；100BASE-TX。
通信模式: **SM 同步** 与 **DC 同步** (同步周期 250µs~4000µs) 都支持。
SM0/SM1 = 邮箱收发、SM2 = RxPDO、SM3 = TxPDO。站号由拨码 SW1~6 设定 (0~63)，
驱动器上电时写入 ESC 别名寄存器 0012h。

**注意**: 拨码站号对 **pysoem** 不可见 —— CoE 0012h 对象实测缺失 (SDO
"object does not exist")，pysoem 封装的旧版 SOEM 也不暴露 ESC 别名寄存器。
因此本框架(python 链) **按 EtherCAT 总线线序 (从站 0/1) 定位轴**。

> 若要真正按手册读取该 0012h 别名寄存器，须用原生 SOEM —— 它本来就在手边：
> SOEM 在 `ecx_config_init()` 里已对每台从站 FPRD 0x0012，结果就在
> `ctx.slavelist[i].aliasadr`，打印一行就有。本仓库原先有个 114 行的只读小工具
> **`aliasinfo/`** 就是干这个的，**2026-09-21 随清理移除了** —— 那条路本身仍然通，
> 只是现在没有现成程序替人打这一行。
> (手册 V2.4 另有 **2215h 从站节点来源** / **2216h 从站节点号** 可以改这个别名，
> 但那是写操作，本仓库不用。)

## 读取拨码站号 (原生 SOEM)

拨码站号存于每台从站 ESC 的 *Configured Station Alias* 寄存器 **0012h-0013h**
(由 SW1~6 在驱动器上电时写入)，普通 EtherCAT 主站启动时就靠读它识别/寻址。
python 链 (pysoem) 读不到这个寄存器，所以当年仓库里放了个原生 SOEM 读取器
**`aliasinfo`** (自有顶层工程，引用下载的 SOEM)：SOEM 在 `ecx_config_init()` 里已对
每台从站 FPRD 0x0012，结果在 `ctx.slavelist[i].aliasadr`，那个工具只把它打印出来
(只读、不进 OP)。**该工具 2026-09-21 已从仓库移除** —— 下面是它当年打出来的输出，
作为实测记录留着；**要复现它，现在得自己写那几行** (`ecx_config_init()` 之后遍历
`ctx.slavelist[]` 打 `aliasadr`，再用 `ecx_config_map_group` 之外的那套读法拿
`1018h:01/:02`)。

输出形如 (位置 = 0-based 总线线序，与 python 链 `--pos` 一致):

```
2 台从站。位置为 0-based 总线线序 (主站起数)。
  位置    序号   配置地址     别名0012h      厂商ID      产品码  名称
  -----  -----  ------  ------------  ----------  ----------  ----
    0       1   0x0001        5 (0x0005)  0x00000994  0x00003000  YKD2205PE
    1       2   0x0002       17 (0x0011)  0x00000994  0x00003000  YKD2205PE
```

注意:
- 别名 = 0 表示拨码=0 或未启用，同型号多台仍按总线位置区分。
- 拨码站号是驱动器**上电时**读的，改动拨码须断电重启才生效。
- 读它一样要用 Npcap 独占网卡，运行期间勿同时跑 python 链的 pysoem 脚本
  (两个上位机开着时同理)。

### 状态机各状态的含义 (V2.3 p8)

CiA402 协议中定义了运动控制设备的标准状态机，同时还定义了各种运行模式，以及它们在
对象字典中的定义。标准状态机 (State machine) 描述了设备的状态和驱动可能的控制序列。
每一步状态表示了一个特定的内部或者外部行为，设备的状态也决定了哪些命令可以被接收。

| 状态 | 手册说明 |
|---|---|
| Not Ready to Switch on | 设备电源已接通，驱动器已经初始化，并执行内部自检，制动器也被激活 |
| Switch on Disabled | CANopen 通信已开始，可以利用 SDO 通信服务对驱动器进行参数设置 |
| Ready to Switch on | 驱动器继续进行参数设置，电机没有被励磁 |
| Switched on | 驱动器电机准备好状态，输出级电压将在该状态中最后接通，但不能执行驱动功能 |
| Operation Enable | 驱动器电机使能，驱动器正常运行状态，按照控制模式控制电机 |
| Quick Stop Active | 快速停止功能被激活，驱动功能已启动，同时启动了电机 |
| Fault Reaction Active | 驱动器检测到报警发生，按照设定方式停机，电机仍使能 |
| Fault | 错误出现，允许更改驱动器参数 |

> **`[实测]`**：两台上电后第一次读到的 6041h 是
> **0x0210** (bit4 Voltage enabled + bit9 Remote，低 4 位 = 0000 = 手册「步骤 0」态)。
> 随后程序写 6040h = **0x0000**，再读到的是 **0x0231** (bit0+bit4+bit5+bit9，
> 低 4 位 = **0001** = 手册「步骤 1」态，即 **Ready to switch on / 电机释放**)。
> 按手册，**0000 和 0001 都是「电机释放」**(步骤 0 与步骤 1)，都不是故障。
> 要判「未使能且无故障」，判据是 **`(6041h & 0x000C) == 0`**
> (bit2 = 未使能、bit3 = 无故障)。0x0210 / 0x0231 的 **bit9** 都是 1 (Remote 有效)。

## 四种工作模式 (V2.3 §3.2, p9~p10；§3.4~§3.7, p11~p17)

CANopen 通过对象 `6060h`(Mode of operation)对驱动器工作模式进行设置，并通过对象
`6061h`(Mode of operation display)反映驱动器当前的工作模式状态。驱动器目前支持
4 种工作模式：循环同步位置模式 (CSP)、位置模式 (PP)、速度模式 (PV)、回原点模式
(home) (V2.3 p9)。

| `6060h` | 工作模式 |
|---|---|
| 0 | 未定义 |
| 1 | 位置模式 (pp) |
| 3 | 速度模式 (pv) |
| 6 | 回原点模式 (home) |
| 8 | 循环同步位置模式 (csp) |

### 循环同步位置模式 csp (V2.3 §3.4, p11~p12)

循环同步位置模式下，控制器完成位置指令规划并输出规划好的目标位置 `607Ah`，同时
以周期同步的方式将目标位置发送给驱动器，驱动器内部完成位置、速度控制。需将工作
模式对象 `6060h` 值设置为 8，当工作模式状态对象 `6061h` 寄存器读取为 8 时可进行
CSP 工作模式的相关操作。

通信对象：控制字 `6040h`、状态字 `6041h`、工作模式 `6060h`、模式显示 `6061h`、
目标位置 `607Ah`、实际位置 `6064h`。

**控制字在该模式下无功能** (V2.3 p12)。

| `6041h` | 名称 | 值 | 描述 |
|---|---|---|---|
| Bit12 | Drive follow the command value | 0 | 从站未跟随指令 |
| Bit12 | Drive follow the command value | 1 | 从站跟随指令 |
| Bit13 | Following error | 0 | 没有位置偏差过大故障 |
| Bit13 | Following error | 1 | 发生位置偏差过大故障 |

| 对象 | 名称 | 数据类型 | 访问 | 单位 | 范围 |
|---|---|---|---|---|---|
| `607Ah`:00 | 目标位置 | INT32 | RW | p | -2^31~2^31-1 |
| `6064h`:00 | 实际位置 | INT32 | RO | p | -2^31~2^31-1 |

### 位置模式 pp (V2.3 §3.5, p12~p14)

此模式主要用于点位定位运动，该模式下，控制器给定目标位置 `607Ah`，位置曲线速度
`6081h`，加速度 `6083h`，减速度 `6084h` 参数，急停减速 `6085h` 驱动器内部完成轨迹
规划。需将工作模式对象 `6060h` 值设置为 1，当工作模式状态对象 `6061h` 寄存器读取为
1 时可进行 PP 工作模式的相关操作。

通信对象：控制字 `6040h`、工作模式 `6060h`、目标位置 `607Ah`、轮廓速度 `6081h`、
加速度 `6083h`、减速度 `6084h`、急停减速度 `6085h`、状态字 `6041h`、模式显示
`6061h`、实际位置 `6064h`。

| `6040h` | 名称 | 值 | 描述 |
|---|---|---|---|
| Bit4 | New set-point | 0 | 没有目标位置 |
| Bit4 | New set-point | 1 | 目标位置更新，该位从 0 到 1 的上升沿表示预触发新的目标位置 `607A` |
| Bit5 | Change set immediately | 0 | 完成当前目标位置后更新 |
| Bit5 | Change set immediately | 1 | 立即更新 |
| Bit6 | abs/rel | 0 | 目标位置是一个绝对值 |
| Bit6 | abs/rel | 1 | 目标位置是一个相对值 |
| Bit8 | Halt | 0 | 按 Bit4~Bit6 命令运动 |
| Bit8 | Halt | 1 | 停止 |

| `6041h` | 名称 | 值 | 描述 |
|---|---|---|---|
| Bit10 | Target reached | 0 | Halt=0：目标速度没有到达；Halt=1：轴减速 |
| Bit10 | Target reached | 1 | Halt=0：目标速度到达；Halt=1：轴速度为 0 |
| Bit12 | Drive follow the command value | 0 | 可更新目标位置 |
| Bit12 | Drive follow the command value | 1 | 不可更新目标位置 |
| Bit13 | Following error | 0 | 没有位置偏差过大故障 |
| Bit13 | Following error | 1 | 发生位置偏差过大故障 |

在位置模式下，通过向控制字 `6040h` 的 Bit4 位依次写入 0 和 1 产生上升沿以完成运动
触发。一旦驱动器收到触发命令，状态字的 Bit12 被置为 1，运动开始，同时通过控制字的
bit6 控制该运动属于绝对定位运动还是相对定位运动。

一旦到达目标位置，状态字的 Bit10 被置为 1，如果没有到达目标位置，或者出现位置误差
偏差过大故障，则该位保持 0 状态。

当新目标位置更新时会有两种情况出现：当前目标位置到达和当前目标位置未到达。如果在
当前目标位置未运动到达的情况下出现新的目标位置和新的触发命令，应根据控制字 `6040h`
的 Bit5 位给定情况做出相应反应 (V2.3 p13~p14)：

- `6040h` 的 Bit5 位为 0 时，表示必须完成当前运动后再响应新的目标位置和触发命令
  (时序图：**新目标位置出现后不立即更新**)。
- `6040h` 的 Bit5 位为 1 时，表示打断当前运动马上响应给定的新的目标位置和触发命令
  (时序图：**新目标位置出现后立即更新**)。

## PDO 映射

| 来源 | 生效的 RxPDO | 生效的 TxPDO | SM2 / SM3 长度 |
|---|---|---|---|
| 手册 V2.4 附录 3 (p78~79, YKD) | 只映射 **6040h**，其余 11 项未映射 | **全部未映射** | 手册未给 |
| 手册 V1.0 (p38~40) | 同上 | **全部未映射** | 手册未给 |
| ESI V2.5 `<RxPdo>/<TxPdo>` | 5 项: 6040h:16 / 607Ah:32 / 60FFh:32 / 60B8h:16 / 60FEh:01:32 = **16 B** | 12 项: 603Fh:16 / 6041h:16 / 6064h:32 / 60FDh:32 / 606Ch:32 / 60F4h:32 / 60B9h:16 / 60BAh~60BDh:32×4 / 6061h:8 = **39 B** | Outputs 16 / Inputs 39 |
| ESI V2.5 `<Dictionary>` 默认值 | 2 项: `60400010h` + `60600008h` = **3 B** | 2 项: `60410010h` + `60610008h` = **3 B** | (同上) |
| **[实测] 2026-09-15,当时那个只读诊断 CLI** | **1C12h = { 1601h }**，1601h 共 7 项 = **23 B** (见下) | **1C13h = { 1A00h }**，1A00h 共 3 项 = **10 B** | IOmap **输出 23 + 输入 10** |

三份资料说的是「1C12h = { 1600h }」，而 **[实测] 这台设备的 1C12h 指的是 `1601h`**，
`1600h` 是同一台驱动器里另一张**没有生效**的表。所以**写死的必须是分配对象里读出来的
那个索引**：照着 `1600h` 去读偏移、去补缺项不会报任何错，而那张表里的字段齐不齐都与
过程数据无关。

1C13h = { 1A00h }（与三份资料一致）；1C00h:01~04 = SM0~SM3 通讯类型 1/2/3/4。

**[实测] 2026-09-15 的完整实读值** (只读运行，一个字节都没写)：

```text
1C12h (分配): 1 项  0x1601
1601h (映射): 7 项
  [1] 6040h:00  16 bit  @ +0    控制字
  [2] 6060h:00   8 bit  @ +2    运行模式
  [3] 607Ah:00  32 bit  @ +3    目标位置 (CSP)
  [4] 60FFh:00  32 bit  @ +7    目标速度 (PV)
  [5] 6081h:00  32 bit  @ +11   轮廓速度 (PP)
  [6] 6083h:00  32 bit  @ +15   轮廓加速度
  [7] 6084h:00  32 bit  @ +19   轮廓减速度
  合计 184 bit = 23 字节      <-- 那 23 字节就是它, 已解释
1C13h (分配): 1 项  0x1A00
1A00h (映射): 3 项
  [1] 6041h:00  16 bit  @ +0    状态字
  [2] 6064h:00  32 bit  @ +2    实际位置
  [3] 606Ch:00  32 bit  @ +6    实际速度
  合计 80 bit = 10 字节
```

**读法**:
- **不要相信任何一份「出厂映射」**。同一个厂家在手册、ESI 声明、ESI 字典默认值里
  给了三种答案，真机上量到的又是第四种 —— 驱动器当前的映射很可能被厂家上位机
  改过。**每次运行前读一遍 `1C12h` / `1C13h`，按它们指到的索引再读那张映射表，
  再定偏移。**
- 三份资料唯一的共识是: **6040h 在 RxPDO 的第 0 项**，所以控制字在输出镜像的 `+0`
  字节 —— 这一条 [实测] 也成立。但 6041h 在 ESI 声明里位于 **输入镜像 +2**，
  [实测] 1A00h 里却在 **+0**：偏移必须从实读的映射表推，不能照抄任何文档。
- 实测输出 23 字节**不是** `1600h`，而是 `1601h`：6040h(2) + 6060h(1) + 607Ah(4) +
  60FFh(4) + 6081h(4) + 6083h(4) + 6084h(4) = 23。
- 副作用：**当前生效的映射里 `6040h` / `607Ah` / `60FFh` 已经齐全**，所以做
  CSP / PV / HM **不需要改写任何 PDO 映射**。
- **生效 RxPDO 里的每一项都是"主站拥有"的 —— 不驱动它，就是在每周期下发 0。**

  主站每周期把整块输出镜像原样发出去，驱动器控制环连续采样自己的 SM2 缓冲。
  所以表里每一项的主站侧都是**由我们决定**的：写了就是那个值，没写就是 **0**，
  而且不会有任何报错。`1601h` 有 7 项，`motor_api` 曾经只驱动其中 4 项。

  > **通用规则（与具体驱动器无关）：一个对象只要在生效的 RxPDO 里，就必须经过程
  > 数据驱动它；SDO 写会被下一帧覆盖。** 反过来，不在 RxPDO 里的对象才轮到 SDO。
  > 判断"在不在"只能实读映射表 —— 所以 `motor_api` 在 setup 时逐项实读偏移。
  >
  > 另一个容易踩的变体：**驱动器可能只接受在"未使能"状态下改运行模式**（CiA402 的
  > 要求）。经过程数据改也一样 —— 要先失能，再改 `6060h`，再使能。

  两个实测到的例子，都是"没写的那一项"：

  **① `6060h`（运行模式）在 `+2`。** [实测] 2026-09-15 的 S6：SDO 写 `6060h = 8`
  （CSP），回读 `6060h` 对象**确实是 8**，但 `6061h`（实际模式）一直读回 **0** ——
  因为主站每周期都在下发 `6060h = 0`，驱动器认的是过程数据那一侧。

  **② `6083h` / `6084h`（轮廓加减速度）在 `+15` / `+19`。** [实测] 2026-09-15 的
  PV 运行**全阶段 PASS、退出码 0，而电机一步没走**：

  ```text
  S4/S5/S6 → 停后:  6064h = 15270510   (全程一个计数都没变)
                    606Ch = 0          (全程)
  使能时 6041h = 0x1637,  跑的时候 = 0x0237   (bit12 "Speed=0" 被清零)
  ```

  `6041h` bit12 在 PV 下是 `Speed`（1 = 速度为 0），它**跟着我们下发的 `60FFh`
  变了** —— 说明驱动器确实收到了速度指令、也承认目标速度非零。但 `6083h = 0`
  意味着**斜坡永远起不来**：驱动器认为该转，实际减速器上不来，`606Ch` 停在 0，
  一步不走。驱动器自己的 `6083h/6084h` 是 **500000**（当年那份参数基线里记的就是它；
  基线文件 2026-09-21 已删，数值留在这儿），
  被主站每周期下的 0 盖掉了。判据只能是 `6064h`（实际位置）有没有变、
  `606Ch` 有没有非零。

- **`6081h` 是这条规则下唯一"有意不驱动"的一项**：它只在 PP 下当轮廓速度用，
  而本仓库的运动层(`motor_api`)**不做 PP** —— PP 是驱动器自己内部规划的模式。
  驱动器里它是 `0`(表示"从未设过")，与主站下发 0 一致。判据是 `em_dump_pdo()` 里
  那张「本接口对生效 RxPDO 每一项的处置」表：7 项逐项写清偏移与"驱动 / 不驱动"。
  加字段时先看这张表还差谁。
- 顺带一个容易忽略的后果：**只要进了 OP, 就在覆盖这些项。**
  当年那个 CLI 带 `--allow-pdo` 会进 OP 并开始发帧，于是连"只读观测"那次也把
  `6081h`/`6083h`/`6084h` 推成了 0(现在界面点「连接」是同一件事)。所以
  `motor_api` 的 pin 动作放在 `em_setup()` 里、**进 OP 之前**。
- 这正是 `motor_api` 里「**偏移证不出就拒绝**」那条护栏:偏移一律从**实读的**映射表
  推,**不猜**(`em_setup()` 里那张「本接口对生效 RxPDO 每一项的处置」表会整张证一遍,
  证不出就报错、连接直接失败;当年 CLI 把它翻译成退出码 4)。
  `6040h`/`6041h` 在过程数据镜像里的字节偏移算错, 后果是**把控制字写进别的字段**
  —— 万一那是 `607Ah`, 就是凭空下了一个位置指令。

> **对「空 TxPDO 挡 SAFE_OP」这条根因**：
> 手册确实说 1A00h 出厂未映射，`[实测] 2026-09-11` 也确实拿到
> **AL 状态码 0x001E (Invalid input configuration)**、从站拒绝 PRE_OP→SAFE_OP；
> 但 `[实测] 2026-09-15` 那次现场运行里 **1A00h 已含 6041h、SM3 = 10 字节，
> SAFE_OP 与 OP 都到达了**。所以「出厂空 TxPDO」是**手册口径**，
> 报 0x001E 时要先去读 1A00h/1C13h 确认，不要默认它就是空的。

## 数字输入 / 输出与限位

本机硬件 (V1.1 §1.2/§4.2.4): **4 路光电隔离输入 X0~X3** (5~24 V，共 XCOM，
**电平脉冲宽度需 > 10 ms**)、**2 路光耦隔离输出 Y0/Y1**。

- **2004h** (U16 RO): 输入端子电平 **Bit0~Bit3 = X0~X3** (物理状态，常开/常闭由 2300h 决定)。
- **2005h** (U16 RO): 输出端子状态 **Bit0~Bit1 = Y0~Y1**。
- **2300h / 2301h** (U16 RW, 默认 0): 输入/输出端子**有效电平逻辑**，对应位 0 = 常开、1 = 常闭。
  > **本机实测 (2026-09-18) 是 `0`（常开 = 有效电平为高），而现场 X0~X3 接的是 NPN
  > 传感器（**高电平 = 未触发**）—— 两者正好反着**，于是"没触发"被读成"触发"，
  > `60FDh` 的 bit1/bit2 常年同时置起、`6041h` bit11 恒为 1，扫描一步都开不了。
  > 现场症状是拒绝启扫的话里说"正限位与负限位**同时**压着"—— 那个组合物理上不成立
  > （见 `scan_sweep.md` §13）。
  > 修法两条，层次不同：改这里的 bit0~bit2 置 1（`0x0007`）是**修根**（驱动器的限位
  > 保护、`60FDh`、bit11 一次全对），也是程序现在的默认动作（`em_di_set_logic`，
  > 连接时写、收尾还原，从不写 2102h）；上位机的「上位机侧取反」**只治软件那一侧**，
  > 驱动器自己的 bit11 与限位保护不受它影响。两条一起上 = 双反相 → 扫描永远开不了。
  > 手册没写 `2300h` 会不会被驱动器自己落 EEPROM。
- **2310h~2313h / 2320h~2321h / 2330h~2333h**: 端子功能与滤波，见下表。
- **60FDh** (U32 RO) 是**经过 2300h 电平反转与 2310h 功能映射之后**的结果：

| 位 | 含义 |
|---|---|
| Bit0 | 负限位 |
| Bit1 | 正限位 |
| Bit2 | 原点开关 |
| Bit3~Bit15 | 保留 |
| Bit16 / Bit17 | 探针 1 / 探针 2 |
| Bit18~Bit22 | 用户自定义 0~4 |
| (Bit31) | Z 信号 —— 该位只在 V2.4 的 **MS-Mini3E/S3E 附录**里写明；YKD 表未列 |

**这三位是 `2300h` 反转与 `2310h`~`2312h` 功能映射之后的结果**，调用方**不再取反**。
反过来说：**`2300h` 配反了三个灯一起反相**（当年那份参数基线把 `2300h` 记为 WARN 级
正是这个原因；基线 2026-09-21 已删, 这条结论留下）。

### 本仓库怎么用它 (`motor_api` / `scan`，2026-09-17)

- 位定义在 [ec_motor.h](../motor_api/ec_motor.h) 的 `EM_DI_NEG_LIMIT` /
  `EM_DI_POS_LIMIT` / `EM_DI_HOME`（`EM_DI_X3` 也定义了，本机未接线）。
- `em_setup` **只在 `60FDh` 已经在生效 TxPDO 里时**绑它（`em__find_field`，**只绑不补**）。
  绑上/绑不上都会打一行 `printf` 如实报告。
- 访问器 `em_dig_in_known()` / `em_di_home()` / `em_di_poslim()` / `em_di_neglim()` /
  `em_dig_in_raw()` / `em_dig_in_offset()`。**一律先问 `em_dig_in_known()`**：
  它 = `off_dig_in >= 0 && mirror_ok`，因为「读不到」和 `0x00000000`
  在数值上长得一模一样，而 0 在"开关压着没有"这个问题上是个**看起来完全正常**的答案。
- 要让 `60FDh` 进 TxPDO 有两条路：**用厂家上位机改一次 `1A00h`（推荐，零代码、断电也在）**，
  或者 `em_require_dig_in()` 在连接时补一次（仅写 RAM，收尾还原；崩在收尾前会留在驱动器里）。
  `scan` 界面「高级选项」里的「让 60FDh 进 TxPDO」就是后者，**默认开**。

  上面只摘了本仓库在用的四个；**注意第二段的方向**：17 的第二段是**正向**、
  18 的第二段是**反向**。
- 只有 17/18 这两个「以限位为原点」的方式，手册才分 a)/b) 两条分支 —— 分岔的判据是
  **回零启动那一刻减速点（= 那一侧的限位开关）信号有效还是无效**。两条分支的终点都是
  **开关的释放点**（刚退开一点的那个位置）。(V2.4 p46~p48)
- 因此 17 与 18 的**首段方向是相反的**，而同一个方式的 **a) 与 b) 之间又各反一次**：

- `22 14h 回零辅助设置` (0~11, 默认 0) 决定**回零完成后 6064h 显示什么**
  (是否叠加/取反 607Ch、显示 0 还是实际值)。
- `221Eh 回零超时报警` (ms，默认 0 = 不开启)。

#### 本仓库的上位机用哪几个方式

**`scan` 用 24 / 29 / 18 / 17 这四个**，分两排按钮：

| 按钮 | 方式号 | 基准 | 算方式号的函数 |
|---|---|---|---|
| 「X/Y 正向回零」「X/Y 反向回零」 | 24 / 29 | **原点开关 X0** | `ecatcmd::home_method_for` |
| 「X/Y 找正限位」「X/Y 找负限位」 | 18 / 17 | **正 / 负限位开关** | `ecatcmd::home_lim_method_for` |

- 两排的差别只有**基准**：24/29 找原点开关，18/17 把那一侧的限位开关当机械基准
  （手册把后者叫「找限位」）。四个方式都走同一条 `em_home()`，它里面没有任何按方式
  分支的逻辑 —— 朝哪走、什么时候停全由驱动器按 6098h 自己决定。
- 24/29 是**唯一一对"朝一个方向高速去找，找不到就换另一边继续找"**的通用方式
  （见表里那两句："若先撞正/负限位则反向继续找"）。
- **35**：以当前位置为机械原点，**它不去找** —— 按一下就把当前位置定义成原点。
- **1~14、33、34 不可用**：需配带 Z 信号的闭环电机，本机是开环机型。
- 18/17 的 a)/b) 分支由**驱动器**按启动那一刻开关的信号自己选，上位机只负责在发起前
  把它读出来（60FDh 的 bit1/bit0）并预告这一趟走哪条；读不到就没法预告，所以那是一种
  拒绝发起的条件（见 `docs/scan_sweep.md` 的「找限位」一节）。

**「正向 / 反向」说的是电机轴的正反向**，与画布上的哪一边、与用户面对的哪一边都没有
必然关系。

**速度 × 超时 = 能找多远。** `6099h:01` 是找原点速度，而 `em_home()` 等 `6041h` bit12
有个上限（`scan` 用 30 秒），所以**它能找的距离是有限的**：按驱动器自己那个
`6099h:01 = 50000` 算是 1500000 脉冲 = 30 圈，而缺省扫描区域是 27 圈；速度调低时能找
的范围跟着缩小（2000 pul/s 只有 1.2 圈）。

**`609Ah` 与 `6099h:01` 的关系**：`609Ah = 6099h:01 × 10` 就是**斜坡时间 0.1 秒**，
驱动器自己那对实测值（`6099h:01 = 50000` / `609Ah = 500000`）相除正好也是 0.1 秒。
`scan` 不写死加速度，而是按斜坡时间反推（`ecatcmd::home_accel_for`），并在 `500000`
（器件自己那个数，`6083h`/`6084h` 也是它）封顶。

**回零之后 `6064h` 读作什么由 `2214h` 决定。** `em_home()` 对这个值不做任何断言，
`scan` 的做法是**从 `6064h` 重新锚定显示零点**（`m_origin[axis] = em_pos(ax)`），
而不是假设它等于 0 —— 见 [scan_sweep.md](scan_sweep.md) §18.3 与 §18.5。

> **回零用的是驱动器自己读到的开关电平**（`2310h~2312h` 映射到哪一路、`2300h`
> 的极性怎么算，都是驱动器的事）。所以上位机的「上位机侧取反」那个勾选框
> **对回零一点用都没有** —— 它只改上位机这一侧的中止判据。极性配反时
> （2026-09-18 实测 `2300h = 0` + NPN 传感器）**必须先改驱动器的 `2300h`**
> （「高级选项」里的「写驱动器 2300h」默认开着，做的就是这件事）。

### `603Fh` 进 TxPDO —— 让报警码与 bit3 同一帧到达 (2026-09-22)

`6041h` bit3 只说"有故障", 说不了是哪一个; 而**读 `603Fh` 得靠一条 SDO, 见下面那条硬事实**
—— 那正是"上位机自己在驱动器最脆弱的一刻把总线静默掉"的来源。所以本仓库把这个对象
**追加进 `1A00h` (TxPDO0)**: 照 `60FDh` 那一套, 只写 RAM、写前快照、收尾还原,
连接时打印它到底补上没补上。补上之后 `603Fh` 与 `bit3` 落在**同一帧**里, 一个字节的
SDO 都不发。SM3 装不下或驱动器拒绝重映射时退回 SDO 读 (那条路会晚一拍, 且有下面的代价)。

### 判定"同步方式"的三个只读对象

驱动器是否在等 SYNC0, 决定的是**另一种**报警 (与上位机发不发帧无关), 而本程序
**不上 DC**。要判定这件事只需要读三个只读对象, **一个字节都不写**:

| 对象 | 含义 | 本仓库程序 |
|---|---|---|
| `1C32h:01` | 同步方式: 0 自由运行 / 1 SM 同步 / 2 DC 同步 | **作数的那个数**。报 2 = 驱动器在等 SYNC0 |
| `1C32h:02` | 同步周期 (ns) | 与 `HMI_CYCLE_US` 对照 |
| `2217h` | 同步帧阈值 (同步帧报警阈值), 出厂 20 | 手册里的默认值, **实测栏一直是空的** |

>上位机 (`hmi/ecatworker.cpp` 的 `doConnectInner`) 会在进 OP 之后把这三个数打到控制台
>(只读、只报轴 0 —— 同一台机器上驱动器型号与配置相同)。`2217h` 那个默认值从来没在真机上
>核过, **读到之前不要拿它当结论**。

### 硬事实: 一条 SDO 事务期间, 过程数据**一帧都不发**

**SOEM 的 SDO 走邮箱, 不捎带过程数据**: `ecx_SDOread` → `ecx_mbxreceive`
(`SOEM/src/ec_coe.c:117` → `SOEM/src/ec_main.c:1600`), 那里只有邮箱状态轮询
(`ecx_readmbxstatus`, 一次 FPRD) 与 `osal_usleep`, **没有任何 `processdata` 调用**。
所以超时不是"这一圈长一点", 而是**连着好几圈一帧都不发**, 超时多长就停多久
(`EC_TIMEOUTRXM` = 700 ms —— `SOEM/include/soem/ec_options.h:102`)。

驱动器那边看到的就是主站掉线: SM 看门狗踢它出 OP (AL `0x001B`)、ALM 灯闪 6 次 (通讯)、
`603Fh` = `FF06`。**上位机在 OP 里做一条 SDO, 就是自己按一次这个报警**, 而驱动器报警时
恰恰最不可能应答 SDO —— 于是静默最长。2026-09-22 实机量到过一次 **1638 ms** 的静默
(两根轴各 700 ms), 就是这么来的。

因此本仓库的口径: **OP 里的诊断读一律用 `em_set_sdo_timeout()` 把超时压短**
(`hmi/ecatworker.cpp` 进 OP 时统一装 60 ms), 能不读就不读 (所以有了上面
`603Fh` 进 TxPDO 那一条), 而且帧已经不健康时**一条 SDO 都不发**。

## 进 SAFE_OP / OP 的前置条件 —— AL `0x001E` 那条根因

这条是本仓库早期**踩过的坑**,也是每次"进不去 OP"时第一个要查的东西:

**手册口径的出厂 `1A00h` (TxPDO0) 是未映射的 → SM3 长度为 0 → 从站以 AL `0x001E`
拒绝 `PRE_OP → SAFE_OP`。** TxPDO 空着时**连 SAFE_OP 都进不去**, 更别说 OP。

两条推论:

- **PRE_OP 下 CiA402 状态机根本不响应 `6040h`。** 所以"用 SDO 在 PRE_OP 里跑使能
  阶梯"这条路走不通 —— 必须先有可用的 TxPDO, 才能进 SAFE_OP/OP, 状态机才动。
  这也是本仓库的运动接口**全部走过程数据**的原因(见下文 `motor_api`)。
- **补 TxPDO 只写 RAM, 从不写 `2102h` (EEPROM)** —— 掉电即回出厂映射。
  主站在连接时补写 `1A00h`/`1C13h` 是**通信配置**, 收尾必须还原成运行前的快照;
  崩在收尾之前的那一次改写会留在驱动器里直到断电。
  零代码的替代路是用厂家上位机改一次, 那样断电也在。

> **掩码别只取低 4 位就完事(据手册更正)**:手册**定义了** bit5/bit6, 低 4 位就是
> `0000/0001/0011/0111` 四态, 取低 4 位本身没问题 —— 但**「上电后第 0 步期望
> `0x0000`」是错的**:上电自检完成后驱动器处于 `0001` (Ready to switch on,
> **电机释放**), 手册的「步骤 0 = 0000」只在刚上电那一瞬成立。
> 要判「未使能且无故障」请用 **`(sw & 0x000C) == 0`** (bit2 未使能 / bit3 无故障)。

> **期望值取决于这台设备的当前配置。** 若读到的 `1A00h` = 0 项 / `SM3` 长度 = 0
> (手册口径的出厂态), 就复现了上面那条根因;若像 2026-09-15 实测那样 `1A00h` 已含
> `6041h`、`SM3` = 10 字节, 说明**配置已被改过**。别把任何一次的读数当常量。

### 那两条"被移除的程序"留下的驱动器事实

原先那两个只读验证程序 (`slide_verify` / `slide_motion`) **2026-09-21 随清理移除了**,
但它们量出来的两条与驱动器本身有关的事实仍然有效:

- **`2401h` 最大电流 = 2000 mA 就是 YKD2205PE 的正常出厂值**(机型上限 2 A;
  手册默认列写的是型号相关的 2000/4000/5500)。所以看到 2000 **不是**被改过。
- **`2201h` 决定行程当量来自 `2400h` (细分) 还是 `2408h`/`2409h` (电子齿轮)**,
  不固定住它, 「1 脉冲 = 多少位移」就没有任何东西兜底。当年那份参数基线里
  `2201h` 是**按手册默认填的 `0`、注明那是假设、不是本机实测** ——
  **这份基线与读它的程序一起删了,现在没有任何东西会替人挡住一个错的当量**。
  出路只有:用厂家上位机看,或临时加一行 `em_rd_u16(bus, slave, EM_OID_GEAR_ENABLE, 0, &v)`。

## 多轴运动接口 motor_api (原生 SOEM)

**仓库里现存的唯一运动层**就是它(`ec_motor.c` + `ec_motor_motion.c`, 由 `scan` 与
`hmi` 各自直接编进去)。它用**过程数据**做需要每周期下发目标值的三种模式:

| 模式 | 6060h | 目标值走哪 | 用它的接口 |
|---|---|---|---|
| 位置同步 CSP | **8** | RxPDO `607Ah`, **每周期刷新** | `em_csp_move_abs/rel`, `em_csp_move_multi` |
| 速度 PV | **3** | RxPDO `60FFh`, 到位后写 0 | `em_pv_run_for` |
| 回零 HM | **6** | `6098h` 方式 + `6040h` bit4 上升沿 | `em_home` |

**本驱动器没有 CSV(6060h=9)** —— `6502h` 实测 `0xA5` = PP + PV + HM + CSP。
所以"速度模式"只能是 PV。

**为什么不能在 SDO 上做**: SOEM 的 `EC_TIMEOUTRXM` 是 **700 ms**, 而同步周期是 **ms 级**;
CSP/PV 的目标值必须每周期刷新, SDO 的往返时间根本追不上。

### CSP 的加减速形状由主站决定 —— 手册口径

手册对 CSP 的原话:

> 循环同步位置模式下，**控制器完成位置指令规划**并输出规划好的目标位置 `607Ah`，
> 同时以周期同步的方式将目标位置发送给驱动器，**驱动器内部完成位置、速度控制**。

- **形状 = 主站下发的 `607Ah` 流。** 驱动器只跟踪, 不生成斜坡。所以仓库里两个 CSP
  发送方的形状**就是**电机的形状, 而**两者都不是 S 型**:

  | 发送方 | 加速段 | 减速段 |
  |---|---|---|
  | `em_csp_move_multi()` | **速度阶跃** | **速度阶跃**(全程匀速) |
  | `hmi` 的 `interpolate()` | **速度阶跃** | 恒定减速度(线性) |

- **`6081h`/`6083h`/`6084h` 不构成 CSP 的形状来源。** 它们是 PP / PV / HM 的轮廓参数。
  (它们在生效 RxPDO `1601h` 里、每周期被下发, 那是映射的既成事实, 不是"CSP 要用它们"。)

分层(**这个目录现在是纯源码目录, 没有 CMakeLists, 也不产出目标**;
两个 `.c` 由 `scan` 与 `hmi` 各自直接编进去):

```text
motor_api/
├─ ec_motor.h           对外接口 (em_bus_t / em_axis_t 不透明)
├─ ec_motor_internal.h  两层之间的私有定义与写原语声明
├─ ec_motor.c           底座 —— **本目录唯一出现 ecx_SDOwrite 的文件**
└─ ec_motor_motion.c    运动层 —— 使能阶梯 / CSP 插值 / PV / 回零
```

它在真机上走的路(当年那个验收程序 `motor_test` 的 S0~S8, **程序已删, 这条路还在**):
S0 开总线 / S1 选轴 / S2 实读映射与只读参数 / S3 补映射 + 建过程数据 + 证明偏移 /
S4 进 OP / S5 使能 / **S6 CSP 或 PV** / S7 回零 / S8 收尾(无条件执行)。
**两个上位机的「连接」按钮就是 S0~S4 + S8**; S5~S7 落在「使能」「扫描/手动定位」
「原点模式」那些按钮上。

不变量: `grep -rn ecx_SDOwrite motor_api/` **只应有 `ec_motor.c` 一处**。

### 多轴怎么"同时"

`em_csp_move_multi()` 在一个循环里**一帧喂所有轴**: 逐轴按实测 `dt` 推进插值目标、
逐轴写各自的输出镜像 `6040h`/`607Ah`, 然后**才**调一次 `em_service()`。
各轴**各自独立**判到位（`|6064h - 终点| <= 容差` 且插值目标已到终点), 没有耦合、
没有插补、没有龙门同起同停。

### CSP 的目标位置以什么为基准

`em_csp_move_multi()` 收的是**绝对**目标位置, 接口不替调用方决定基准。
`em_csp_move_rel_multi()` 收的是**相对位移**, 基准由**接口内部**取:

> 每根轴的 `607Ah = 调用这一刻该轴的实际位置（6064h）+ delta[i]`。

函数先把**所有**轴的起点读完, 再算目标, 再一次性下发。任何一根轴取不到实际位置就
**整体拒绝**, 一个字节都不下发。日志里会把每根轴的 `起点 -> 终点 (位移)` 打出来。
`em_csp_move_rel()` 就是它的 n=1 薄封装。

### 偏移从哪来

**必须先读 `1C12h` / `1C13h` 问"哪个 PDO 生效", 再按它指到的索引读映射表。**
这台设备的 `1C12h` 指的是 **`1601h`** —— 见上文「PDO 映射」。写死 `1600h` 的后果不是
报错, 而是**悄悄改错表**。

实测结论: 生效的 `1601h` 里 **`6040h` / `607Ah` / `60FFh` 已经齐全**
（在 +0 / +3 / +7 字节）, `1A00h` 里 `6041h` / `6064h` / `606Ch` 也齐全
（在 +0 / +2 / +6）。所以在本机上做 CSP / PV / HM **不需要改写任何 PDO 映射**。
不改映射 ≠ 不写输出镜像: 输出镜像的每一个字节都是主站每周期**必须**给出的,
镜像里属于本次运动的那些项（`6040h`/`6060h`/`607Ah`/`60FFh`/`6083h`/`6084h`）
**一项都不能漏**, 漏掉的那项就是每周期下发 0。判据是 `em_dump_pdo()` 里那张 7 项的
处置表。

> **下面这几条是驱动器那一侧的量值与语义, 与调用方式无关, 所以留在这儿:**
>
> - **`6083h` = 0 会让 PV 的斜坡永远起不来** —— 现象是报"速度指令已被接受"却一步
>   不走。它在生效 RxPDO `1601h` 里, 所以主站每周期都在下发它: **不驱动就是下发 0**。
>   驱动器的轮廓加减速度由 `em__pick_ramp()` 在连接期实读进来 (读不到才退回常数),
>   经 `em_set_ramp()` 每周期下发。**能下发 0, 但 0 就是"斜坡起不来"**。
> - **回零的返回速度 (`6099h:02`) 取找原点速度 (`6099h:01`) 的 1/4**
>   (`ecatcmd::home_vel_slow()`), 加减速 (`609Ah`) 按**斜坡时间 0.1 秒**从同一个
>   速度算出来。四个方式号在界面上都有按钮: 找原点 **24** (正向) / **29** (反向),
>   找限位 **18** (以正限位为原点) / **17** (以负限位为原点)。
> - **「退出码 10」的语义**: 收尾写完 `6040h = 0` 后回读 `6041h` 仍报 Operation
>   enabled —— 即**电机可能仍带电**, 它覆盖其它所有码。**两个上位机把这一条变成了
>   一个没有「取消」可点的模态框**, 见到请立即断掉驱动器动力电源, 不要只依赖软件。

### PV 怎么判"到底转没转"

`em_pv_run_multi()` 会逐轴打印 `6064h 起点 -> 终点 (走了 N pul)` 与运行期间
`606Ch` 的峰值, **位置一个计数都没变即判 FAIL**（退出码 3）。

2026-09-15 那次 PV 全阶段 PASS、退出码 0, 而电机一步没走
—— 因为所有检查都在问「驱动器收下指令了吗」（`6041h` bit12 该清的清、该置的置、
无故障无限位, 全对), **没有一条在问「电机动了吗」**。判据落在这两项上:

| 观测 | 含义 |
|---|---|
| `6064h` 变没变 | **唯一的硬判据** —— 走没走, 位置说了算 |
| `606Ch` 峰值 | 辅助证据。有些驱动器会直接回报指令值, 所以它非零**不能**反推真的在转 |

CSP 一侧本来就有到位断言（`|6064h - 终点| <= 容差`)。

### 安全边界 (这套口径出自那个已删的 CLI, 两个上位机照搬)

- **默认一个字节都不写。** 写 PDO 映射要显式授权(CLI 是 `--allow-pdo`, 界面是
  「连接」那道确认框);使能/运动要 `--allow-motion` —— **界面里就是「使能」按钮上
  那道每次点击都弹的模态确认**;回零要 `--home`(它会撞限位、会找原点开关)。
  找限位与回零是**同一道授权**(CLI 里缺了 `--home` 直接拒绝, 退出码 4);
  界面里它们本来就在同一个「原点模式」框里。
- **那句确认的形态两种, 共同点是"不会被记住"**: CLI 版 `--allow-motion` **本身**
  就是确认、运行时不问 y/N;界面版是**每次点击都弹模态、没有持久勾选、不自动使能**。
- **上限只能收紧。** 按 `2400h = 50000 pul/圈` 算, CLI 默认那 5000 脉冲 ≈ **0.1 圈**;
  界面侧的速度是 1000~100000 pul/s(默认 20000), 回零速度 100~100000(默认 50000,
  那是驱动器 `6099h:01` 的实读值)。
- `6040h` 推送值只有 **`0x0000` / `0x0006` / `0x0007` / `0x000F`**, 回零另加 `0x001F`,
  故障复位另加 `0x0080`。**不试探厂商私有控制字。**
- **从不写 `2102h`** (EEPROM), 不改软限位 `607Dh`, 不改 `2400h`/`2408h`/`2409h`/`2201h`
  任何当量参数。改过的 PDO 映射**收尾还原**, 且只写 RAM。
  (唯一的写参数例外是「高级选项」里那个**默认开着**的 `2300h` 写入 —— 它走单独的
  `em_allow_param_write()` 那道门, 收尾同样还原。)
- 收尾路径**无条件执行**; 收尾后 `6041h` 仍报 Operation enabled 就是那个
  **「退出码 10」** 的语义(界面里是一个没有「取消」可点的模态告警)。
- 首次回零**必须**把速度收到很低、人在物理急停旁 —— 方式 24 的物理正确性取决于现场
  接线 (`2310h`~`2312h` 实测 = 1/2/3, 即 X0 = 原点、X1 = 正限位、X2 = 负限位),
  不对就换 29 或 35。
- **找限位的前置条件更硬**: 它的 a)/b) 两条分支靠读 `60FDh` 才分得出来,
  而 `60FDh` 那两位是 `2300h` (输入有效电平逻辑) 与接线是否一致的结果。本机实测
  `2300h = 0x0000` 而 X1/X2 空载物理为高 → 正/负限位**同时**报有效, 那种读数下
  界面**拒绝发起**(一个字节都不写)。出路是把「高级选项」里那个默认开着的
  「让 `60FDh` 进 TxPDO」重新勾上再「连接」。
- 网卡是**单进程独占** (Npcap): 与仓库的 python 链**不能同时跑**;两个上位机之间
  也不能 —— `hmi` 和 `scan` 各有一份 `ecatworker`, 谁先连上谁占住网卡。
